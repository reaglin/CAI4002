Introduction

Bidirectional search runs two searches at once: one forward from the initial state and one backward from the goal state. Each search builds its own frontier, and the algorithm stops when the two frontiers touch — that is, when some state has been reached from both directions. The solution is then assembled by joining the forward path to the reversed backward path.

The reason this matters is complexity. A single breadth-first search to depth d expands on the order of b^d nodes, but two searches that each only need to reach depth d/2 expand roughly 2b^(d/2) nodes, which is dramatically smaller for large d. That saving is why bidirectional search appears alongside depth-limited and iterative deepening search as one of the classic uninformed strategies in this module.

The saving is not free. You must be able to generate predecessors of a state (not just successors), you need an explicit and small set of goal states to search backward from, and you need an efficient membership test — usually a hash table — to check whether a newly generated node already sits on the other frontier. You also must decide which strategy each half uses; breadth-first on both halves is the standard choice because it preserves the shallow-meeting property that makes the solution optimal. The two videos below do not teach bidirectional search directly, so use them to solidify the machinery it is built from: the frontier, the explored set, and breadth-first expansion. While watching, ask yourself what would change if a second frontier were growing toward the first.

How These Videos Support the Learning Outcomes

Neither video names bidirectional search, so treat them as foundation rather than coverage. The breadth-first video makes the frontier and visited-set machinery explicit, which is what you extend to implement efficient frontier intersection testing and to justify why two breadth-first halves meet near depth d/2 (MO4). The broader uninformed-algorithms tutorial places depth-limited, depth-first and breadth-first search in one comparison, supporting the tracing and complexity reasoning in MO1–MO3 and giving you the completeness, optimality, time and space criteria needed to recommend a strategy in MO5. For the bidirectional-specific requirements — predecessor generation and explicit, few goal states — rely on the module readings and lecture notes rather than these videos.
