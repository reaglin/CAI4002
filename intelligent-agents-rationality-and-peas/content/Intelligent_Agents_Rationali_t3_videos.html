Introduction

Before you can design an intelligent agent, you have to say clearly what job it is supposed to do. PEAS—Performance measure, Environment, Actuators, Sensors—is the standard checklist for doing exactly that. It forces you to state how success will be judged, what world the agent operates in, what it can do to that world, and what it can perceive of it, all before a single line of agent code is written.

The four elements are deceptively simple, and most of the difficulty lives in the performance measure. A vacuum agent rewarded only for dirt collected may learn to dump dirt and re-clean it; a taxi agent rewarded only for speed will drive dangerously. Good performance measures describe desired states of the environment rather than how the agent should behave, and they usually combine several competing criteria such as safety, speed, comfort, and cost. The worked examples in this topic—vacuum cleaner, automated taxi driver, and medical diagnosis system—show how the same four-column template scales from a toy problem to a messy real-world one.

As you watch the videos below, keep a blank four-column PEAS table beside you and try to fill it in for each example the presenters discuss. Pay particular attention to how the task specification constrains the agent design that follows: a partially observable, dynamic environment with a rich performance measure demands a very different architecture than a fully observable, static one. That link between specification and architecture is the thread connecting this topic to the rest of the module.
