Introduction

A PEAS specification tells you what an agent is for: its Performance measure, Environment, Actuators, and Sensors. Classifying that environment — observable or partially observable, deterministic or stochastic, episodic or sequential, static or dynamic, discrete or continuous, single- or multi-agent — tells you what the agent is up against. This topic connects those two descriptions to a design decision: which internal architecture should the agent actually have?

The five classic architectures form a ladder of increasing capability and cost. Simple reflex agents map the current percept straight to an action through condition-action rules, which works only when the right action is fully determined by what is sensed right now. Model-based agents keep internal state to cope with partial observability. Goal-based agents reason about which future states are desirable, utility-based agents compare outcomes when goals conflict or are uncertain, and learning agents improve their own behavior when the environment is unknown in advance. More capability is not automatically better: the rational choice is the simplest architecture that the task environment allows.

The videos below come from industry practice with modern LLM-based agents rather than from a textbook treatment, so expect different vocabulary for overlapping ideas. As you watch, keep translating: when a speaker describes an agent that reacts to input, ask whether that is a reflex agent; when they discuss memory, ask what partial observability problem that memory is solving; when they describe several agents cooperating, ask which environment dimension that corresponds to. Try to write a PEAS specification for every example that appears.

About this video

Martin Keen explains the different kinds of memory an AI agent maintains and why one form of memory is not enough. In classical terms, this is a discussion of internal state: what an agent stores because its sensors cannot reveal everything at once, and how stored information shapes later decisions. Expect concrete distinctions among memory types used in current agent systems.

Why this video

It gives a modern, concrete grounding for the model-based agent subtopic, where internal state exists precisely to handle partial observability of the environment.

How These Videos Support the Learning Outcomes

Together these videos reinforce the architecture-selection outcome (MO5) most directly: the five-types overview maps onto the same reflex, model-based, goal-based, utility-based, and learning distinctions you must be able to justify for a given task. The memory video supports MO1 and MO4 by making concrete why an agent needs internal state when percepts alone underdetermine the world, which is the observability dimension in action, while the multi-agent video addresses the agent-count dimension of MO4. None of the videos builds a formal PEAS table, so you should practice MO2 and MO3 by writing out performance measures, environments, actuators, and sensors for the examples the videos present, and by asking in each case whether the agent shown is rational given its limited information rather than omniscient.
