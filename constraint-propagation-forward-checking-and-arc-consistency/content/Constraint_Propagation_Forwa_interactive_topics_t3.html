Arc Consistency and the AC-3 Algorithm

▶

Backtracking search alone explores a combinatorial space blindly: it assigns a value, discovers a conflict many levels deeper, and then undoes a great deal of work. Constraint propagation changes the economics of that search by reasoning about the constraints before committing to assignments. Rather than asking "which value shall I try next?", propagation asks "which values could never participate in any solution, given what I already know?" and deletes them. Arc consistency is the workhorse of this idea for binary constraint satisfaction problems (CSPs), and AC-3 is the algorithm that made it practical. Everything that follows — the REVISE subroutine, the queue of arcs, the termination analysis, the complexity bounds, and the comparison with forward checking and higher levels of consistency — is an elaboration of one simple principle: a value that has no support is a value that can be thrown away.

Defining arc consistency

A CSP is a triple of variables, domains and constraints. For a binary CSP, each constraint relates exactly two variables, say X and Y, and can be viewed as a set of permitted pairs C(X,Y) ⊆ D(X) × D(Y). Each binary constraint gives rise to two directed arcs: (X, Y) and (Y, X). The direction matters, because arc consistency is a statement about one variable's domain being supported by the other's.

Formally: the arc (X, Y) is arc consistent if and only if, for every value x ∈ D(X), there exists at least one value y ∈ D(Y) such that the pair (x, y) satisfies the constraint between X and Y. Such a y is called a support for x on that arc. A value with no support anywhere in D(Y) is unsupported.

Note the asymmetry carefully. Arc (X, Y) being consistent says nothing about arc (Y, X). Consider D(X) = {1, 2, 3}, D(Y) = {1, 2, 3, 4, 5} and the constraint X < Y. Arc (X, Y) is already consistent: 1 is supported by 2, 2 by 3, 3 by 4. But arc (Y, X) is not: y = 1 needs some x ∈ D(X) with x < 1, and none exists, so 1 must be deleted from D(Y). A CSP as a whole is arc consistent only when every arc, in both directions, is arc consistent.

Why is deleting an unsupported value safe? Suppose x ∈ D(X) has no support in D(Y). Any complete solution must assign some value to Y drawn from D(Y), and that value must be compatible with X's value. If X = x, no legal choice for Y exists, so no solution contains X = x. Deleting x therefore removes zero solutions: the pruned CSP is equivalent to the original in the sense that it has exactly the same solution set. This is the crucial property that lets us interleave propagation with search without compromising completeness.

Arc consistency is best understood as inference, not search. It never guesses a value, never branches, and never creates a choice point. It deduces consequences of the constraints and records those consequences by shrinking domains. Because it is sound (it deletes only values that cannot appear in a solution) but incomplete (an arc-consistent network may still have no solution), it is used as an accelerator inside search rather than as a replacement for it.

A small worked illustration of pure inference: let D(X) = D(Y) = {0,1,2,...,9} with the constraint Y = X².

  • REVISE on arc (X, Y): the value x survives only if x² ∈ D(Y). Thus 0, 1, 2, 3 survive (squares 0, 1, 4, 9), while 4..9 are deleted (16, 25, ... exceed 9). New D(X) = {0,1,2,3}.
  • REVISE on arc (Y, X): the value y survives only if some x ∈ D(X) has x² = y. So D(Y) = {0,1,4,9}.

Both arcs are now consistent and the network has been reduced from 100 candidate pairs to 4, with no assignment made and no solution lost.

Many real constraints are not binary: Alldiff(A,B,C,D), A + B + C = 10, or a table constraint over five variables. Generalized arc consistency (GAC), also called hyper-arc consistency or domain consistency, extends the definition to any arity: a constraint C(X₁,...,X_k) is GAC with respect to variable X_i if, for every value v ∈ D(X_i), there exists a tuple in C containing v whose other components are all drawn from the current domains of the other variables. Such a tuple is the support. Enforcing GAC on an arbitrary k-ary constraint by brute-force search over tuples costs O(d^k), which is why practical solvers attach a specialised propagator to each global constraint — an algorithm that achieves GAC for that constraint far faster than enumeration. Binary arc consistency is simply the case k = 2.

The REVISE step

REVISE is the atomic operation of arc consistency: it makes a single arc consistent by deleting unsupported values from the tail variable's domain. It never touches the head variable's domain.

function REVISE(csp, X, Y) returns true if D(X) was changed
    revised ← false
    for each x in D(X) do
        if no value y in D(Y) satisfies the constraint C(X, Y) with x then
            delete x from D(X)
            revised ← true
    return revised

Three details deserve emphasis:

  • Only D(X) is modified. To make the relationship symmetric you must also call REVISE(csp, Y, X), which is exactly why the queue is initialised with arcs in both directions.
  • The boolean return value is the propagation trigger. Returning true means at least one value disappeared from D(X). Any other variable Z constrained with X may have had values whose only support was one of the just-deleted values, so arcs (Z, X) must be re-examined. Returning false means the arc was already consistent; nothing changed, so nothing downstream can have become inconsistent because of this call, and no new work is scheduled. This simple flag is what turns a collection of local checks into a cascading global propagation.
  • Implementation hygiene. Deleting from a collection while iterating over it is a classic bug; implementations typically iterate over a snapshot of D(X) or collect deletions in a buffer and apply them afterwards. Solvers that support backtracking must also record deletions on a trail so they can be undone when search retreats.

The cost of the naive version is O(d²) where d = max|D|: the outer loop runs up to d times, and for each x the inner search for a support may scan all d values of D(Y) before giving up. The inner loop can of course exit early the moment a support is found, which is why REVISE is usually much cheaper than d² in practice — but the worst case is realised whenever many values are genuinely unsupported.

A concrete trace: D(X) = {1,2,3,4}, D(Y) = {2,3}, constraint X > Y, arc (X, Y).

Value xCandidate supports y ∈ D(Y)Support found?Action
12 (1>2 false), 3 (1>3 false)NoDelete 1 from D(X)
22 (2>2 false), 3 (2>3 false)NoDelete 2 from D(X)

REVISE returns true with D(X) = {3,4}. Observe that the asymmetry persists: arc (Y, X) would next delete nothing, since 2 is supported by 3 and 3 is supported by 4.

The AC-3 algorithm and its queue of arcs

AC-3 (Mackworth, 1977) drives REVISE to a fixed point using a worklist of arcs that still need checking.

function AC-3(csp) returns false if an inconsistency is found, true otherwise
    queue ← all arcs (Xi, Xj) of csp, both directions for every binary constraint
    while queue is not empty do
        (X, Y) ← REMOVE-FIRST(queue)
        if REVISE(csp, X, Y) then
            if size of D(X) = 0 then return false        // wipe-out: failure
            for each Z in NEIGHBOURS(X) \ {Y} do
                add arc (Z, X) to queue
    return true

The logic of each line:

  • Initialisation. Every arc, in both directions, must be examined at least once, because at the start we know nothing about which arcs are already consistent. For a CSP with c binary constraints the queue starts with 2c directed arcs. (When AC-3 is used for maintaining arc consistency inside search, the initial queue is smaller — typically only the arcs pointing into the variable just assigned — because the rest of the network was already arc consistent before the assignment.)
  • Pop and revise. The queue is really a set-like worklist: order affects speed but not the final result. A FIFO queue gives breadth-first-like propagation; a LIFO stack often reaches a wipe-out faster; many solvers use a priority scheme that revises arcs with small domains first. Whichever discipline is used, the fixed point reached is unique — arc consistency defines the largest sub-domains closed under the support condition, independently of processing order.
  • Re-enqueuing neighbours. If D(X) shrank, then for any neighbour Z of X there may be a value z ∈ D(Z) whose only support in D(X) was one of the deleted values. That is precisely the arc (Z, X), pointing into the shrunken variable, so (Z, X) goes back on the queue. The arc (Y, X) is excluded because Y's domain was untouched by this REVISE and every value of Y that had support in the old D(X) still has it: the values just deleted from D(X) were by definition unsupported by D(Y), so they were supporting nothing in D(Y). Arcs of the form (X, Z) are also not re-added, since shrinking the tail domain cannot make the tail arc inconsistent.
  • Loop to emptiness. When the queue drains, no arc can be revised further, which is the definition of a globally arc-consistent network.

A full worked example on map colouring. Take the Australian states WA, NT, SA, Q, NSW, V, T with colours {R, G, B} and "adjacent regions differ" constraints: WA–NT, WA–SA, NT–SA, NT–Q, SA–Q, SA–NSW, SA–V, Q–NSW, NSW–V (T is isolated). Suppose search has assigned WA = R and Q = G, so D(WA) = {R} and D(Q) = {G}, with every other domain still {R,G,B}. Running AC-3 produces:

2(SA, WA)R unsupportedD(SA) = {G,B}(NT,SA), (Q,SA), (NSW,SA), (V,SA)
3(NT, Q)G unsupported (D(Q)={G})D(NT) = {B}(WA,NT), (SA,NT)
4(SA, Q)G unsupportedD(SA) = {B}(WA,SA), (NT,SA), (NSW,SA), (V,SA)

The decisive moment is step 6. The deletions in steps 3 and 4 reduced NT and SA to the same single colour, and since they are adjacent this is impossible. AC-3 discovers it by inference, with no further assignments: the partial assignment {WA=R, Q=G} cannot be extended, and search backtracks immediately.

Termination conditions and outcomes

An AC-3 run ends in exactly one of two ways, and the "success" case subdivides into three situations of practical interest.

  • Failure (domain wipe-out). Some D(X) becomes empty. Since every variable must receive a value, the current partial assignment has no extension to a solution. AC-3 returns false and the search backtracks at once — crucially, before wasting effort on the subtree below. Detecting failure early is the main source of AC-3's speed-up.
  • Success (queue empties, all domains non-empty). The network is now arc consistent, and the pruned CSP is equivalent to the original. Three sub-cases:
    • All domains are singletons. Then the unique remaining combination is forced and, because the network is arc consistent, every pair of neighbouring assignments is mutually supporting — so a solution has been read off directly by inference, with no search at all. (This is the dream case; it occurs, for example, in easy Sudoku puzzles solvable by simple elimination rules.)
    • Some domain is empty — impossible here by assumption, so the remaining case is that at least one domain has two or more values. The reduced domains are handed back to the search algorithm, which chooses a variable and value as usual but now over strictly smaller domains. Smaller domains also sharpen value-ordering and variable-ordering heuristics: minimum-remaining-values (MRV) and degree heuristics become far more informative after propagation.
    • No pruning at all occurred. The network was already arc consistent; AC-3 has cost time without reducing anything. This is the overhead that must be weighed against the pruning benefit.

It is essential to remember that an arc-consistent network is not necessarily solvable. The canonical counterexample is 2-colouring a triangle: variables A, B, C, domains {R, B}, with A≠B, B≠C, A≠C. Every value has support on every arc (for A=R, B=B works; for A=B, B=R works, and so on), so the network is perfectly arc consistent — yet no solution exists, because a triangle needs three colours. Arc consistency reasons only about pairs; it cannot see the three-way interaction. That limitation motivates stronger consistency levels, discussed below.

Why termination is guaranteed. Consider the quantity Φ = (total number of values remaining in all domains, size of queue) ordered lexicographically. Each iteration pops one arc. Either REVISE deletes at least one value — which strictly decreases the first component, and the first component is a non-negative integer bounded by nd — or REVISE deletes nothing, in which case no arcs are added and the queue strictly shrinks. Since Φ cannot decrease forever in a well-founded order, the loop must terminate. In other words, arcs can only be re-enqueued as a consequence of a deletion, and there are finitely many values to delete.

Complexity analysis of AC-3

Let n be the number of variables, d the maximum domain size, and c the number of binary constraints (so 2c directed arcs).

  • How often can an arc enter the queue? An arc (Z, X) is inserted initially (once) and thereafter only when D(X) loses a value. D(X) can lose at most d values in total over the entire run, because deletions are never undone within a run. Hence each directed arc is processed O(d) times.
  • Cost per processing. Each REVISE is O(d²).
  • Total time. O(2c · d · d²) = O(c d³). Since a binary CSP on n variables has at most n(n−1)/2 = O(n²) constraints, the bound can equivalently be written O(n² d³).
  • Space. The queue holds directed arcs and never needs duplicates (a well-implemented worklist checks membership before inserting), so it is O(c), i.e. O(n²). Added to that is the storage for the domains themselves, O(nd), plus — in a backtracking solver — a trail of deletions so that propagation can be undone on backtrack.

Comparing the three figures for a sense of scale:

QuantityBoundReason
Insertions per directed arcO(d)One initial insertion plus one per value deleted from the head variable's domain
Cost of one REVISEO(d²)Up to d values of X, each scanning up to d values of Y
Total time (AC-3)O(c d³) = O(n² d³)2c arcs × O(d) insertions × O(d²) per revision
SpaceO(c) + O(nd)Queue of arcs plus the domains (plus a trail inside search)
Optimal algorithms (AC-4, AC-6, AC-2001)O(c d²)Support counters or "last support" pointers avoid rescanning D(Y) from scratch

The O(cd³) figure is a genuine worst case and is rarely approached. Three reasons explain the gap between theory and practice. First, most arcs are revised only once or twice: a revision re-enqueues neighbours only when it actually deletes something, and in a typical network the great majority of REVISE calls delete nothing. Second, the inner support search exits at the first support found, so for loose constraints (where almost every pair is permitted) the first candidate y usually works and REVISE behaves like O(d). Third, domains shrink as propagation proceeds, so later revisions operate on smaller d than the bound assumes. The practical consequence is that AC-3 is simple, cache-friendly and fast enough that it remains the default generic propagator in many teaching solvers, even though AC-4, AC-6 and AC-2001 have asymptotically better O(cd²) bounds (which is worst-case optimal). AC-4 achieves this by precomputing support counters for every value pair, but the up-front cost of building those structures often makes it slower than AC-3 on real instances; AC-2001 reaches the optimal bound with much lighter bookkeeping by remembering, for each value x and arc, the last support found, and resuming the scan from there.

AC-3 versus forward checking

Forward checking (FC) and arc consistency sit on the same spectrum; they differ only in how far the inference is pushed.

When search assigns Y = v, forward checking revises exactly the arcs (X, Y) for each unassigned neighbour X of Y, deleting from D(X) every value incompatible with v. It then stops. Nothing is re-enqueued; if D(X) shrinks, the consequences of that shrinkage for X's own neighbours are never explored. In the AC-3 pseudocode, forward checking is what you get if you delete the inner for each Z in NEIGHBOURS(X) loop and initialise the queue with only the arcs into the newly assigned variable. In other words, forward checking is one round of revision with no propagation; AC-3 is revision driven to a fixed point.

Maintaining arc consistency (MAC) is the standard name for running AC-3 (or a stronger AC algorithm) after every assignment during backtracking search, starting the queue with the arcs (X, Y) for unassigned neighbours X of the just-assigned Y, and letting the cascade run.

The Australian map-colouring trace above shows the difference sharply. After WA = R and Q = G, forward checking would set D(NT) = {B} (removing R because of WA and G because of Q), D(SA) = {B} (same reasoning), and D(NSW) = {R,B}. No domain is empty, so forward checking reports no problem and search continues, only to discover the NT/SA clash one or two levels deeper. AC-3, by contrast, re-examines arc (NT, SA) because D(SA) changed, finds that NT's only value B has no support in SA's only value B, wipes out D(NT), and backtracks immediately. This is the characteristic pattern: forward checking cannot detect inconsistency between two unassigned variables; arc consistency can.

AspectForward checkingAC-3 / MAC
Arcs revised per nodeOnly (X, Y) for unassigned neighbours X of the assigned YAll arcs reachable by cascading from the change, to a fixed point

The trade-off is therefore between nodes expanded and work per node, and neither metric alone decides the winner — only their product, total runtime, does. On tightly constrained problems (many constraints, small domains, few solutions) propagation pays for itself many times over, because most branches are dead and AC-3 kills them near the root; MAC is the standard choice for hard instances such as large Sudoku variants, graph colouring near the chromatic threshold, or scheduling with tight resources. On loosely constrained problems (large domains, few constraints, many solutions) almost every branch leads to a solution anyway, AC-3 deletes little, and its overhead at every node is pure waste; forward checking — or even plain backtracking with good heuristics — can be the faster overall choice. Hybrid strategies exist: run full arc consistency once as a preprocessing step before search begins (cheap, done only once, and often a big win), then use forward checking during the search itself.

Stronger consistency: path and k-consistency

The triangle-colouring example showed the ceiling of arc consistency: it reasons about one constraint at a time and cannot see interactions among three or more variables. Higher levels of consistency raise that ceiling.

Path consistency (equivalently 3-consistency) considers pairs of variables and a third witness. A pair {X, Y} is path consistent with respect to Z if, for every assignment {X = a, Y = b} consistent with the constraint on X,Y, there exists some c ∈ D(Z) such that {X = a, Z = c} and {Y = b, Z = c} are both consistent. A CSP is path consistent when this holds for every pair and every third variable. Unlike arc consistency, enforcing path consistency may delete pairs, not just values — it tightens the binary constraints themselves, possibly adding explicit constraints between variables that previously had none.

Path consistency cracks the triangle example immediately. With D(A)=D(B)=D(C)={R,B} and all-different constraints, take the consistent pair {A=R, B=B} and the witness C: C=R clashes with A, and C=B clashes with B. No witness exists, so the pair (R, B) is deleted from the constraint on {A, B}. By symmetry the pair (B, R) also goes, leaving the constraint on {A,B} empty — an immediate, inference-only proof that the problem is unsolvable, which arc consistency could never produce.

k-consistency generalises the pattern. A CSP is k-consistent if, for any consistent assignment to any k−1 variables, and any k-th variable, there is a value for that k-th variable extending the assignment consistently. The hierarchy lines up as follows:

LevelNameWhat it guaranteesWhat it prunesTypical enforcement cost
k = 1Node consistencyEvery value satisfies all unary constraints on its own variableSingle valuesO(nd)
k = 2Arc consistencyEvery value of every variable has support in each neighbourSingle valuesO(cd³) with AC-3; O(cd²) optimal
k = 3Path consistencyEvery consistent pair extends to any third variablePairs of valuesO(n³d⁵) for the classic PC algorithms

A CSP is strongly k-consistent if it is j-consistent for every j ≤ k. Strong n-consistency on an n-variable problem means a solution can be constructed greedily without ever backtracking — but establishing it is NP-hard in general (it essentially amounts to solving the problem), and in the worst case requires space exponential in n. This is the central practical lesson of the hierarchy: consistency levels above arc consistency buy pruning at a price that rises exponentially in k, and beyond k = 2 — occasionally k = 3 on small, very tight subproblems — the price usually exceeds the benefit. Arc consistency sits at the sweet spot of the cost/pruning curve, which is why MAC, not "maintaining path consistency", is the industry default. There is one notable structural exception: if the constraint graph is a tree, enforcing arc consistency (directionally, along a topological ordering of the tree) is sufficient to guarantee a backtrack-free solution in O(nd²) time.

Modern solvers get stronger-than-arc pruning by a different route: specialised propagators for global constraints. The classic example is Alldiff(X₁,...,X_k). Decomposed into k(k−1)/2 pairwise ≠ constraints and handled by generic arc consistency, it prunes very little — with D(X₁)=D(X₂)=D(X₃)={R,B} and pairwise ≠, arc consistency detects nothing, exactly as in the triangle example. Treated as a single global constraint, however, GAC can be enforced using Régin's algorithm, which models the value–variable relation as a bipartite graph and uses maximum matching plus a strongly-connected-components analysis (Hopcroft–Karp and Tarjan) to delete, in roughly O(k^1.5 d) time, every value that belongs to no maximum matching. That immediately detects the three-variables/two-values wipe-out. A cheaper but still very effective rule is the pigeonhole or Hall-interval check: if any set of m variables in an Alldiff collectively has fewer than m values available, fail; if their union is exactly m values, those values can be removed from all other variables in the constraint. Similar dedicated propagators exist for Sum, Cumulative, Element, Regular and many others. The general principle is that semantic knowledge of a constraint buys more pruning per unit of time than any syntactic increase in the generic consistency level — a far better trade than climbing the k-consistency ladder.
