Introduction

This topic shifts from theory to practice: you will build a working CSP solver and then measure how its components behave. The plan is to start with a clean architecture — a representation for variables, domains, and constraints, plus a backtracking search loop with pluggable inference — and then add forward checking, AC-3 with maintained arc consistency (MAC), and a min-conflicts local search alternative. Keeping these as interchangeable strategies behind one interface is what makes a fair comparison possible later.

The second half of the topic is experimental. You choose benchmark instances (map colouring, scheduling, n-queens, random binary CSPs near the phase transition), instrument the solver to count nodes expanded, constraint checks, revisions, and wall-clock time, and then run controlled experiments with repeated trials. Good instrumentation is cheap to add up front and nearly impossible to retrofit mid-analysis, so decide early what you will record. Debugging and validation matter just as much: a solver that is subtly wrong can look impressively fast, so verify solutions against the constraint set and cross-check that different strategies find consistent answers.

The videos below are short, project-style walkthroughs of CSP implementations in Python, built around familiar benchmark problems such as map colouring and scheduling. Watch them for the engineering decisions rather than for formal algorithm proofs: how the problem is encoded, how variables and constraints are represented in code, and how a solution is checked. As you watch, ask yourself where you would insert a forward-checking hook, where an AC-3 queue would live, and what counters you would add to turn each demo into a measurable experiment.

How These Videos Support the Learning Outcomes

These short project videos complement the module's algorithmic content by showing CSP models in running code. The map colouring examples give you the exact problem structure used for tracing forward checking and its domain reductions (MO1, MO2), and a working backtracking implementation is the scaffold into which you insert an AC-3 arc queue and REVISE routine (MO3). Having two distinct problem domains — colouring and scheduling — supplies the varied benchmark instances needed to compare pruning power and per-node cost across forward checking, MAC, and min-conflicts (MO4), and to interpret results using nodes expanded alongside runtime rather than either metric alone (MO5). Note that the videos demonstrate solving CSPs rather than formally deriving the propagation algorithms, so pair them with the module readings and your own instrumentation work.
