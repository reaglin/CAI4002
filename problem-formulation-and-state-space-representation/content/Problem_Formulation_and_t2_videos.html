Introduction

Before an AI system can search for a solution, the problem itself has to be written down in a form a search algorithm can consume. The standard formulation has five components: the state space (the set of all configurations reachable from the start), the initial state, the set of actions together with a rule saying which actions are applicable in which states, the transition model or successor function that says what each action does, the goal test that recognizes a solution, and the path cost built up from individual step costs. Specify those pieces and the problem is defined completely and unambiguously; leave one vague and the algorithm either fails or silently solves a different problem.

This matters throughout the course because every search method you will study later — uninformed, informed, local, adversarial — assumes this interface. Good formulation is also where abstraction lives: deciding what belongs in a state and what is irrelevant detail determines whether the state space is tractable. A state that is too rich explodes the search; a goal test that is too loose accepts non-solutions; inconsistent step costs break optimality guarantees.

The two videos below come from Stanford's CS221 treatment of constraint satisfaction problems. CSPs are a related but different way of specifying a problem — in terms of variables, domains and constraints rather than states, actions and transitions — so watch them comparatively. As you view, ask yourself: what plays the role of a state here? What corresponds to an action or a successor function? What is the goal test, and is there any notion of path cost at all? Contrasting the two formalisms will sharpen your sense of what the five components actually buy you.

How These Videos Support the Learning Outcomes

Together these videos reinforce MO1 and MO3 by presenting a rigorous, worked-through problem formalism that you can map term by term onto state space, initial state, actions, transition model, goal test and path cost, and by supplying classic example problems to formulate. The overview lecture supports MO2, since choosing variables and domains is an exercise in abstraction — deciding what detail a representation must retain to remain solvable. The dynamic ordering lecture supports MO4 and MO5 by making visible how the search process expands over a representation, and how representational and ordering choices change the amount of work required, which is exactly the lens you need when critiquing a proposed formulation. Note that neither video is a direct lecture on the five components, so use them as comparative material alongside the module readings rather than as a substitute for them.
