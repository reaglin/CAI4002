Introduction

A learning agent is any agent architecture — simple reflex, model-based, goal-based, or utility-based — wrapped inside a loop that lets it improve with experience. Russell and Norvig describe this loop in four parts: the performance element (the agent you already know, which chooses actions), the critic (which judges incoming percepts against a fixed performance standard), the learning element (which uses the critic's feedback to modify the performance element), and the problem generator (which deliberately suggests exploratory actions that may be suboptimal now but informative later). The key insight is that the performance standard must sit outside the performance element; otherwise the agent could simply learn to lower its own bar.

This topic matters in CAI4002 because the earlier architectures all assume a designer who already knows enough about the environment to hand-code the right rules, model, goals, or utility function. In unknown, partially observable, or changing environments, that assumption fails. Learning agents are the engineering answer: start with an incomplete agent, give it feedback signals, and let experience fill the gaps. This is also where the exploration versus exploitation tension appears — an agent that only exploits its current best guess never discovers anything better.

The videos below come from IBM Technology and are framed around modern LLM-based AI agents rather than the classical textbook diagram. Watch them as case studies: when a speaker discusses agent types, memory, or retrieval, ask yourself which classical component is being described. Where does the feedback come from? What plays the role of the critic? What is being learned, and what is merely being stored or retrieved? Mapping industry vocabulary back onto the four-component framework is the real exercise here, and it is also the skill you will need for the design-and-justify subtopic.

About this video

This video surveys five categories of AI agent — the lineup typically runs from simple reflex agents through model-based, goal-based, and utility-based agents to learning agents — using a package-delivery drone as the running example. Expect each type to be introduced by what it can and cannot handle, with the learning agent presented as the most capable because it improves from experience rather than relying solely on its initial programming.

Why this video

It directly covers the taxonomy this module is built around and places learning agents at the end of that progression, which is exactly the framing needed for "why learning agents are needed" and for comparing architectures against environment properties.

Video 2: The Four Types of Memory Every AI Agent Needs

IBM Technology · 10:41 · 149,524 views · 4mo ago · captions — Watch on YouTube

About this video

Martin Keen breaks down several distinct kinds of memory an agent can maintain — commonly short-term or working memory, long-term memory, and episodic and semantic varieties — and explains what each is used for during a task. The discussion should make clear how storing past percepts and outcomes differs from simply reacting to the current input.

Why this video

Retaining experience is the raw material the learning element works with, so this video gives concrete grounding for how feedback and past episodes persist inside an agent, supporting the subtopics on what can be learned and on operating in unknown environments.

Video 3: Skills vs MCP vs RAG vs Memory: What AI Agents Need to Know

IBM Technology · 9:11 · 217,453 views · 1mo ago · captions — Watch on YouTube

About this video

This video contrasts four mechanisms modern agents use to extend their capability beyond their training: skills, the Model Context Protocol, retrieval-augmented generation, and memory. The emphasis is on when each mechanism is the right choice and how they differ in where knowledge lives and how it gets updated.

Why this video

It sharpens an important distinction for this topic — genuinely modifying an agent's behavior through learning versus supplying it with external knowledge at run time — which is central to justifying a learning agent design rather than a simpler alternative.
