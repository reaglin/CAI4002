Model-Based Reflex Agents

1

Model-Based Reflex Agents

▶

A simple reflex agent is the most economical design in the agent taxonomy: it reads the current percept, matches it against a set of condition–action rules, and fires the first rule that applies. Its entire decision procedure can be summarised as action ← RULE-MATCH(INTERPRET-INPUT(percept), rules). This works beautifully — but only under a demanding assumption: that the current percept contains everything the agent needs to know in order to act correctly. In formal terms, the environment must be fully observable with respect to the agent's task, so that the percept uniquely identifies the relevant world state. The moment that assumption breaks, the reflex design degrades from "elegant" to "broken". The model-based reflex agent is the minimal repair: keep the condition–action machinery, but give the agent an internal state that summarises the percept history, and the models it needs to keep that state honest as the world and the agent itself change.

Why reflex agents fail in partially observable worlds. A percept is a snapshot — a thin slice of the world, taken through whatever sensors the agent happens to possess, at one instant. It is not the world state. Consider the classic two-square vacuum world, where the agent perceives [location, status], e.g. [A, Dirty]. Here the percept actually does reveal the agent's location, so a simple reflex agent can succeed. Now remove the location sensor, so the agent only perceives [Dirty] or [Clean]. The agent in square A with a clean square A and the agent in square B with a clean square B produce the identical percept [Clean], yet they demand different actions (move Right versus move Left). This is the defining pathology of partial observability: perceptual aliasing — distinct world states that collapse to the same sensory signature.

Perceptual aliasing has two consequences worth separating. The first is simply choosing the wrong action: with no way to tell A from B, any fixed rule if Clean then Right is correct half the time and wrong the other half. The second is more insidious: infinite loops. Because a deterministic simple reflex agent maps percept to action with a fixed function, the same percept always yields the same action. If [Clean] → Right and the agent is already in the rightmost square, it bumps the wall, perceives [Clean] again, and moves Right again — forever. The agent cannot escape because the information needed to break the symmetry (which square am I in? have I already cleaned the other one?) is simply not being sensed. Randomisation ([Clean] → Right or Left with probability ½) can rescue the agent from the loop and is a genuinely useful trick, but it is a blunt instrument: it trades a guaranteed failure for an expected-time-to-success that may be exponentially bad, and it still never lets the agent know anything.

Other everyday examples of the same failure mode:

  • Blind-spot lane change. A car's side camera sees empty road because the overtaking vehicle is momentarily occluded. The percept "lane clear" is identical whether the lane is truly clear or whether a car is hidden alongside. A pure reflex agent merges into a collision.
  • Brake-light ambiguity. A single camera frame showing a car's rear lights illuminated cannot distinguish "the car just started braking" from "the car has been braking for two seconds and is nearly stopped". The appropriate deceleration differs sharply between the two.
  • Corridor navigation. Every junction in an office building looks alike to a laser scanner. Without memory the robot cannot tell junction 3 from junction 7 and will wander.
  • Thermostat without memory. A naive thermostat sees 20 °C and does nothing — unaware that the temperature has been falling at 2 °C per hour and that the room will be uncomfortably cold in fifteen minutes.

The remedy in every case is the same and is almost obvious once stated: the agent should remember something about what it has seen and done before. The information that disambiguates the present is often available in the past.

Internal state: remembering what sensors cannot see. The internal state is a data structure held inside the agent program that carries information forward across decision cycles. Three properties make it practical rather than merely conceptual.

  • It is updated incrementally, not recomputed. On each cycle the agent takes the previous state and revises it in light of the last action and the new percept. It does not replay the entire percept history from the beginning. This keeps the per-cycle cost constant rather than growing without bound, which matters enormously for an agent that runs for hours or years.
  • It compresses the percept history. In principle the ideal agent function maps the whole percept sequence to an action; storing that sequence verbatim is infeasible. The internal state is a sufficient summary: a compact representation that preserves whatever the decision rules actually need. A robot does not store ten million laser scans; it stores an (x, y, θ) pose estimate. A vacuum does not store its whole movement log; it stores a bit-vector of which rooms are clean.
  • It restores distinguishability. Two world states that look alike to the sensors become distinguishable in the agent's extended description (percept, internal state). Returning to the sensorless-location vacuum: if the agent remembers "I started in A and have executed one Right", then percept [Clean] now means "B is clean", which is different from the same percept with state "I am in A". The rule set can key on the pair, and the loop dissolves.

Note that internal state is not the same thing as a goal. The vacuum's coverage map says "B is already clean"; it does not say "I want the whole house clean". The distinction matters and we return to it below.

The transition model: how the world evolves. Memory alone is not enough, because the world does not politely freeze while the agent is not looking. A remembered fact decays in value: "there was a cyclist on my left" is actionable one second later and almost meaningless thirty seconds later. To keep stored state useful the agent needs knowledge of how the world changes. This knowledge is traditionally split into two parts, and the split is conceptually important.

  • "How the world evolves independently of the agent." These are exogenous dynamics — things that happen whether or not the agent acts. Other cars continue along their trajectories; a braking vehicle decelerates at roughly the rate observed; dirt reappears in rooms over time; the outdoor temperature drops after sunset; a stock price drifts. For example, a car-tracking module can propagate a tracked vehicle forward with a constant-velocity assumption: x' = x + v·Δt. The tracked object persists in the internal state through an occlusion precisely because the model says where it should have gone.
  • "What my actions do." These are endogenous effects — the consequences of the agent's own behaviour. Executing Right in the vacuum world changes the current square from A to B (unless the agent is already at the right edge, in which case nothing changes — a detail the model must capture or the state estimate drifts). Turning the steering wheel 10° changes heading. Commanding Suck makes the current square clean. Placing a buy order reduces available cash and increases held inventory.

Together these two bodies of knowledge constitute the transition model of the environment. Its representation can be chosen to suit the domain:

  • Symbolic rules: IF action = Suck THEN status(current_square) ← Clean. Readable, easy to author, brittle under noise.
  • Equations / difference equations: dead-reckoning for a wheeled robot, θ' = θ + (v_right − v_left)·Δt / L. Compact and precise, but accumulates drift.
  • Probabilistic transitions: P(s′ | s, a), the conditional distribution over next states. This is the formulation used in Markov decision processes and in Bayesian filters such as the Kalman filter and particle filter. It is the honest choice when actions sometimes fail — wheels slip, grippers drop objects, a Right command succeeds 90% of the time.
  • Learned models: a neural network or regression model trained on logged (state, action, next state) triples, used when the dynamics are too complex to write down.

Why insist on a transition model at all? Because without it the stored state goes stale and becomes worse than no state. An agent that remembers "the road ahead was clear" and never ages that belief will drive confidently into a queue of traffic. Stale memory is actively dangerous because it carries the same authority as fresh observation. The transition model is what converts memory from a snapshot archive into a continuously maintained estimate of the present.

The sensor model: interpreting percepts. The third ingredient answers a different question: given that I received this percept, what does it tell me about the world? The sensor model encodes the relationship between underlying world states and the raw observations the hardware delivers — in probabilistic form, P(percept | state).

  • It says what a percept reveals. A bank of pixels is not a fact about the world until something interprets it. "The region of the image corresponding to the vehicle ahead has become significantly redder and brighter, therefore its brake lights are on, therefore it is decelerating" is a chain of sensor-model reasoning. Likewise "the ultrasonic sensor returned 0.4 m, therefore there is an obstacle roughly 0.4 m in front" — the word "roughly" is doing real work.
  • It says what a percept leaves ambiguous. This is just as important. A forward-facing camera says nothing about the blind spot; a motion sensor that is silent is consistent with both "room empty" and "occupant sitting still"; a bump sensor fires identically for a wall and a chair leg. A good sensor model makes these limitations explicit so that the agent does not over-interpret silence as evidence of absence.
  • It is the mechanism for reconciling prediction with observation. The transition model produces a prediction of the current state; the sensor model converts the new percept into evidence; the update step fuses the two. In Bayesian terms this is predict-then-correct: belief⁻ = Σ P(s′|s,a)·belief(s) followed by belief(s′) ∝ P(percept|s′)·belief⁻(s′). A Kalman filter is exactly this loop with Gaussian assumptions; a particle filter is the same loop with sampled hypotheses. Even a non-probabilistic implementation performs an informal version: "I predicted I'd be at the third doorway; I see a doorway; good, confidence up."
  • It forces honesty about uncertainty. Because sensors are noisy, partial, biased, and occasionally broken, the resulting internal state is a best estimate, not ground truth. Robust designs represent this explicitly — a covariance matrix, a confidence score, a set of candidate hypotheses — and let the decision rules degrade gracefully when confidence is low (e.g. slow down when the obstacle estimate is uncertain rather than steering aggressively on a guess).

The agent program: update state, then match rule. The model-based reflex agent program is the simple reflex program with a state-maintenance stage bolted on the front. Its canonical form:

function MODEL-BASED-REFLEX-AGENT(percept) returns an action
    persistent: state,          the agent's current conception of the world
                transition_model, how the world evolves and what my actions do
                sensor_model,     how the world is reflected in percepts
                rules,            a set of condition-action rules
                action,           the most recent action, initially none

    state  <- UPDATE-STATE(state, action, percept, transition_model, sensor_model)
    rule   <- RULE-MATCH(state, rules)
    action <- rule.ACTION
    return action

function UPDATE-STATE(state, action, percept, transition_model, sensor_model)
    predicted <- PREDICT(state, action, transition_model)   // step 1
    state     <- CORRECT(predicted, percept, sensor_model)  // step 2
    return state

The four steps of each cycle, spelled out:

  • Step 1 — Predict. Using the previous action and the transition model, project the stored state forward to the current instant. "I commanded Right, so I am probably now in square B." "0.1 s has elapsed, so the tracked car ahead has advanced about 2 m." This step applies both halves of the transition model: the agent's own effects and the world's independent evolution.
  • Step 2 — Correct. Fold in the new percept through the sensor model, refining or overriding the prediction. "I predicted B, and I see a wall on my right — consistent, confidence up." Or: "I predicted B, but the floor pattern matches A — my Right action must have failed; revise." Disagreement between prediction and percept is information, not an error to be suppressed.
  • Step 3 — Match. Run the updated internal state (typically together with the current percept) against the condition–action rules and select an action. Note the crucial difference from a simple reflex agent: the rules are conditioned on state, not on percept. That single substitution is what buys the extra power.
  • Step 4 — Record. Store the chosen action in the persistent variable so that the next cycle's prediction step can account for its effects. Omitting this step is a classic bug: the agent then predicts as though it had been standing still, and its state estimate drifts away from reality in exactly the way the model was meant to prevent.

A worked micro-example — the vacuum with no location sensor, in a two-square world, starting in A with the rule set below:

A second example — adaptive cruise control through an occlusion. At t=0 the camera sees a vehicle 40 m ahead at 25 m/s. At t=1 a truck momentarily occludes it and the percept contains no vehicle. The prediction step propagates the tracked vehicle to ≈ 40 m using constant velocity; the correction step, guided by a sensor model that says "occlusion produces absence of detection, which is not evidence of absence", leaves the track alive with reduced confidence. The rule if gap < safe_gap then decelerate continues to fire sensibly. A simple reflex agent, seeing "no vehicle detected", would have accelerated.

Strengths, limits, and when to choose this architecture. The model-based reflex agent occupies a well-defined sweet spot in the design space.

Choose it when: the environment is partially observable or the sensors are noisy, and yet the correct action is still a direct function of current conditions rather than of some desired future outcome. If you can write down "in situation X, do Y" rules — and you only need memory to work out reliably which situation X you are actually in — this is the right architecture. It is substantially cheaper than planning: there is no search, no lookahead, no goal expansion, just one state update and one rule match per cycle, which makes it realisable in hard real-time loops running at tens or hundreds of hertz.

Its principal limit is the absence of goals. The agent has a model of how the world works but no explicit representation of how the world ought to be. It cannot reason "if I take this action, I will be closer to a state I desire", and it therefore cannot plan, cannot handle novel objectives without rewriting rules, and cannot trade off competing considerations. A model-based reflex taxi at a junction knows exactly where it is, what the other cars are doing, and what turning left would do — but nothing in its architecture tells it where the passenger wants to go. That requires a goal-based agent; ranking partial successes requires a utility-based one.

Scalability of the rule set is the second limit. Giving the agent more internal state increases the number of distinguishable situations, and the rule table must cover them. Rule sets grow combinatorially, develop overlaps and gaps, and become difficult to test and maintain; conflicting rules require arbitration schemes; and a change to the state representation can ripple through hundreds of conditions. This is a real engineering cost, and it is often the practical trigger for migrating to a goal- or utility-based design where behaviour is derived rather than enumerated.

Third, everything rests on model quality. The internal state is only as good as the transition and sensor models that maintain it. A wrong model does not produce visible confusion — it produces confidently wrong actions, which is the most dangerous failure mode of all. Dead reckoning with a slightly mis-measured wheel radius yields a robot that is certain it is in the corridor while it is actually in a wall. Mitigations include periodic re-grounding against unambiguous landmarks, explicit confidence tracking with fallback to cautious behaviour, divergence detection (flagging persistent prediction/percept disagreement), and model learning from logged data.

Typical deployments span exactly this profile of "partial observability, reactive decisions":

  • Automatic emergency braking and adaptive cruise control — maintain tracks of surrounding vehicles through occlusion and sensor dropout; brake according to current estimated gap and closing speed.
  • Occupancy-aware thermostats — remember the last motion event and model how a house cools, rather than reacting only to the instantaneous sensor reading.
  • Vacuum and lawn-mowing robots — maintain a coverage map so that already-cleaned regions are not revisited endlessly, and odometry-based pose so that the map stays aligned.
  • Industrial process controllers —estimate unmeasured internal variables (tank levels, reactor temperature profiles) from a handful of sensors plus a process model, and actuate valves on the resulting estimate.
  • Object-tracking modules in surveillance and sports analytics — persist identities across frames in which a subject is hidden behind another.
  • Stateful network firewalls and intrusion detectors — classify a packet using remembered connection state rather than the packet alone.

In short, the model-based reflex agent is the smallest architectural step that makes reactive behaviour viable in the real world. It keeps the speed and simplicity of condition–action rules, but replaces the naive assumption "what I see is what there is" with a maintained, model-driven best estimate of what there actually is. Everything above it in the hierarchy — goal-based, utility-based, and learning agents — builds on this same state-estimation core, and merely changes how the action is chosen once the state is known.

A simple reflex agent chooses an action by matching its current percept against a set of condition-action rules. That works well only when the percept tells the agent everything it needs to know. In most realistic environments it does not: a sensor sees one room but not the next, a camera sees the car ahead but not whether the brake lights were on a second ago, a robot loses track of where it has already cleaned. These are partially observable environments, and a purely reactive agent either thrashes, loops, or acts on dangerously incomplete information.

The model-based reflex agent fixes this by adding internal state: a stored summary of the percept history that stands in for the parts of the world the sensors cannot currently see. Keeping that state useful requires two pieces of knowledge. The transition model answers "how does the world evolve on its own, and what do my actions do to it?" The sensor model answers "given the state of the world, what percepts should I expect to see?" The agent program then runs a two-step loop: update the internal state using the previous state, the last action, and the new percept, then match a rule against that updated state and act.

As you watch, keep the architecture ladder in view. Notice exactly where each video draws the line between simple reflex and model-based reflex, listen for the phrase "internal state" or "model of the world," and ask yourself what extra cost the model imposes — more memory, more engineering, more ways to be wrong when the model drifts from reality. That cost is the heart of the final subtopic: knowing when this architecture is the right choice and when a goal-based or utility-based agent is warranted instead.
