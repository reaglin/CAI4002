Introduction

Goal-based agents ask a single yes-or-no question: does this action sequence reach the goal? That is often not enough. There are usually many ways to reach a goal, and they differ in cost, time, risk, comfort, and side effects. A utility-based agent replaces the binary goal test with a utility function — a mapping from states (or outcomes) to a number that expresses how desirable each one is. This lets the agent rank competing outcomes rather than merely accept or reject them, and it is how we build agents that not only achieve a goal but achieve it well.

Two ideas do most of the work in this topic. First, the utility function acts as an internalized version of the external performance measure: the designer's standard of success is written into the agent so the agent can evaluate its own options. Second, when the environment is stochastic or partially observable, the agent cannot know which outcome an action will produce, so it chooses the action with the highest expected utility — probability-weighted desirability averaged over possible outcomes. This is what makes utility-based agents the natural architecture for uncertain, multi-objective settings, and the direct ancestor of decision-theoretic and reinforcement-learning methods later in the course.

While watching, keep a running comparison in mind. Watch for where a score or weight replaces a goal test, how conflicting objectives are combined into one comparable number, how probabilities enter the calculation, and what the decision cycle looks like: perceive, predict outcomes, score them, pick the best. Also notice the cost side — designing and tuning utility functions is real engineering work, which matters when you later justify choosing (or rejecting) this architecture for a given scenario.
