Introduction

A simple reflex agent is the most basic agent architecture in AI: it looks at the current percept, matches it against a set of condition-action rules, and acts. There is no memory of past percepts, no model of how the world works, and no explicit goal — just "if this condition holds, do that." The classic implementation pattern is a rule table or a chain of if-then statements wrapped around an interpretation of the current sensor reading.

This architecture matters in the course because it sets the baseline against which every richer design is judged. It is fast, cheap, and easy to verify, and it works well when the environment is fully observable and the right action really is determined by what the agent can sense right now. When observability is partial, the same percept can require different actions, and the agent either stalls or cycles forever in an infinite loop — the standard motivation for adding internal state in a model-based reflex agent. Rule sets also scale badly: every new situation adds rules, and interactions between rules get hard to maintain.

The videos below are short industry overviews of the agent type taxonomy. While watching, listen for how the simple reflex agent is defined, what examples are used, and especially what limitation the presenter cites as the reason to move to the next architecture in the list — that transition point is the heart of this topic. Treat the videos as orientation; the formal definitions of agent function, percept sequence, and full observability come from your textbook readings.
