scikit-learn for Machine Learning Tasks

▶

scikit-learn is the workhorse library for classical machine learning in Python. Its enduring popularity comes less from any single algorithm than from a design decision made early in the project's life: every learning component in the library — a classifier, a regressor, a scaler, a dimensionality reducer, a clustering routine, even a whole composite workflow — obeys the same small, predictable interface. Once you have learned that interface for one object, you have effectively learned it for the two hundred others. This topic walks through that interface in detail, then builds outwards through data loading, training, preprocessing, pipelines, cross-validation and evaluation, so that by the end you can assemble a complete, leak-free, reproducible machine learning experiment from a handful of composable parts.

The scikit-learn Estimator API

In scikit-learn vocabulary, an estimator is any object that can learn something from data. The contract has three parts: construction, fitting, and use. Construction takes only hyperparameters — the configuration choices you make before seeing any data. Fitting takes the data and produces learned parameters. Use means calling predict, transform, or score.

from sklearn.neighbors import KNeighborsClassifier

clf = KNeighborsClassifier(n_neighbors=5, weights="distance")
# Nothing has been learned yet. No data has been touched.
print(clf)
# KNeighborsClassifier(n_neighbors=5, weights='distance')

A crucial rule the library enforces on itself is that __init__ performs no validation and no computation. It simply stores each keyword argument on an attribute of the same name. This is why you can always write clf.n_neighbors and get back exactly the 5 you passed in. It is also why constructing an estimator is instantaneous even for models that are expensive to train.

After fitting, everything the model learned appears on attributes whose names end with a single trailing underscore. The underscore is a deliberate, library-wide convention that lets you tell configuration apart from learned state at a glance:

from sklearn.linear_model import LogisticRegression
from sklearn.datasets import load_iris

X, y = load_iris(return_X_y=True)
lr = LogisticRegression(max_iter=1000)   # hyperparameter: max_iter
lr.fit(X, y)

print(lr.coef_.shape)      # (3, 4)  -> learned weights, one row per class
print(lr.intercept_)       # learned biases
print(lr.classes_)         # array([0, 1, 2]) -> label vocabulary discovered in y
print(lr.n_features_in_)   # 4  -> number of columns seen during fit

A practical consequence: hasattr(est, "coef_") is a reliable way of asking "has this thing been fitted?", and scikit-learn's own check_is_fitted helper uses exactly that heuristic. Calling predict before fit raises NotFittedError rather than silently returning garbage.

Estimators are further specialised by which methods they expose. The table below summarises the main families you will meet in assignments.

Because hyperparameters are stored transparently, every estimator can report and reconfigure them programmatically through get_params() and set_params():

from sklearn.svm import SVC

svc = SVC()
print(svc.get_params())
# {'C': 1.0, 'kernel': 'rbf', 'gamma': 'scale', 'probability': False, ...}

svc.set_params(C=10.0, kernel="linear")
print(svc.C, svc.kernel)   # 10.0 linear

This pair of methods is not a convenience — it is the mechanism that makes automated tuning possible. GridSearchCV does not know anything about SVMs; it simply calls clone() on your estimator, calls set_params(**candidate) with each point in the grid, and fits. Any object that implements the same protocol, including a custom estimator you write yourself, becomes tunable for free.

Finally, every estimator makes strong assumptions about the shape and dtype of its inputs. The feature matrix X must be two-dimensional with shape (n_samples, n_features) and numeric (floating point internally; integers are upcast). The target y must be one-dimensional with n_samples entries for ordinary single-output problems. A very common beginner error is passing a single sample as a flat 1D array:

import numpy as np

sample = np.array([5.1, 3.5, 1.4, 0.2])
# lr.predict(sample)               -> ValueError: Expected 2D array, got 1D array instead
lr.predict(sample.reshape(1, -1))  # correct: one row, four columns

Likewise, if your target comes out of pandas as a column DataFrame of shape (n, 1), you will get a DataConversionWarning; use df["target"] (a Series, 1D) rather than df[["target"]].

Loading and Preparing Datasets

The sklearn.datasets module gives you three kinds of data source: small bundled "toy" datasets for instant experiments, downloadable real-world datasets, and synthetic generators you control precisely.

from sklearn.datasets import load_iris, load_digits, load_wine

iris = load_iris()                # Bunch object: dict-like with attribute access
print(iris.data.shape)            # (150, 4)
print(iris.target.shape)          # (150,)
print(iris.feature_names)         # ['sepal length (cm)', ...]
print(iris.target_names)          # ['setosa' 'versicolor' 'virginica']
print(iris.DESCR[:200])           # human-readable description

X, y = load_iris(return_X_y=True)        # just the arrays
df = load_iris(as_frame=True).frame      # a pandas DataFrame with a 'target' column

When you want to test an algorithm you wrote — say your own k-nearest-neighbours or your own decision-tree splitter — synthetic generators are better than real data because you know the ground truth. make_classification builds clusters on the vertices of a hypercube and lets you dial in difficulty; make_blobs produces isotropic Gaussian blobs that are perfect for clustering and distance-based methods.

from sklearn.datasets import make_classification, make_blobs, make_regression

X, y = make_classification(
    n_samples=1000,
    n_features=20,
    n_informative=5,      # only 5 columns actually carry signal
    n_redundant=5,        # 5 more are linear combinations of the informative ones
    n_classes=3,
    weights=[0.6, 0.3, 0.1],   # deliberately imbalanced
    flip_y=0.02,               # 2% label noise
    class_sep=1.0,
    random_state=42,
)

Xb, yb = make_blobs(n_samples=300, centers=4, cluster_std=1.2,
                    n_features=2, random_state=0)   # 2D so you can plot it

Xr, yr, coef = make_regression(n_samples=500, n_features=10, noise=10.0,
                               coef=True, random_state=7)  # true coefficients returned

Because make_regression can hand back the true coefficient vector, you can check whether your implementation recovers it — a far stronger test than "the accuracy looked reasonable".

Any numeric NumPy array works as X, and so does a pandas DataFrame whose columns are all numeric. Passing a DataFrame has a real benefit from scikit-learn 1.0 onwards: the estimator records feature_names_in_ and will warn you if the columns at predict time differ from those at fit time, catching a whole class of silent bugs.

import pandas as pd

df = pd.read_csv("housing.csv")
y = df["median_house_value"]                     # 1D Series
X = df.drop(columns=["median_house_value"])      # 2D DataFrame

model.fit(X, y)
print(model.feature_names_in_)   # recorded from the DataFrame columns

The single most important preparation step is holding out data you will not look at until the very end. train_test_split shuffles and splits any number of equal-length arrays consistently:

from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X, y,
    test_size=0.25,        # 25% held out; 20–30% is the usual range
    random_state=42,       # reproducible shuffle
    stratify=y,            # preserve class proportions in both halves
)
print(X_train.shape, X_test.shape)

Two arguments deserve emphasis. stratify=y matters enormously on small or imbalanced datasets: without it, a random split of a 95/5 problem can easily put almost no minority examples in the test set, making your test metric meaningless. And random_state fixes the pseudo-random shuffle so that the split — and therefore every number you report — is reproducible. Set it on the splitter, on the estimator (for anything stochastic such as random forests, SGD or k-means initialisation), and on the search objects. A grader who runs your notebook must see the figures you claimed; an unseeded run that reports 0.94 one day and 0.89 the next is not evidence of anything.

For a genuinely honest workflow on larger projects, split three ways: train (fit the model), validation (choose hyperparameters), and test (touched exactly once, at the end). Cross-validation, covered below, folds the first two together, but the test set stays sacred either way.

Training and Predicting with fit / predict

fit(X, y) is where learning happens. It validates the inputs, runs the algorithm, writes the trailing-underscore attributes, and returns self. Returning the estimator enables the fluent one-liner you will see all over the documentation:

from sklearn.tree import DecisionTreeClassifier

preds = DecisionTreeClassifier(max_depth=3, random_state=0).fit(X_train, y_train).predict(X_test)

A second important property is that fit is stateless across calls: calling it again completely discards whatever was learned before and starts over. It is not incremental. If you genuinely need online or mini-batch learning, you must use estimators that provide partial_fit (such as SGDClassifier or MultinomialNB), or set warm_start=True on the ensembles that support it.

predict(X) returns a 1D array of length n_samples. For a classifier these are hard labels drawn from classes_ and have the same dtype as the y you trained on (so if you trained on strings, you get strings back). For a regressor they are continuous values.

y_pred = clf.predict(X_test)
print(y_pred[:10])          # e.g. array([0, 2, 1, 1, 0, ...])

When you need confidence rather than a verdict, use predict_proba, which returns an array of shape (n_samples, n_classes) whose rows sum to 1 and whose column order matches clf.classes_:

proba = clf.predict_proba(X_test)
print(clf.classes_)         # [0 1 2]
print(proba[0])             # [0.02 0.91 0.07]  -> class 1 with 91% confidence

# Custom threshold on a binary problem: favour recall over precision
import numpy as np
positive_col = list(clf.classes_).index(1)
y_flag = (proba[:, positive_col] >= 0.30).astype(int)

Not every estimator supports it. SVC requires probability=True at construction (which triggers an expensive internal cross-validated Platt calibration), and some models only offer decision_function(X), an uncalibrated score where larger means "more positive". ROC-based metrics accept either. If you need well-calibrated probabilities from a model that lacks them, wrap it in CalibratedClassifierCV.

score(X, y) is a convenience that fits the model's default metric: mean accuracy for classifiers, R² (coefficient of determination) for regressors, and typically negative inertia or a model-specific quantity for others.

print(clf.score(X_train, y_train))   # 1.00 -> memorised the training data
print(clf.score(X_test,  y_test))    # 0.87 -> the number that actually matters

A large gap between those two numbers is the classic signature of overfitting, and comparing them is the cheapest diagnostic available. But be careful about treating score as the whole story: accuracy is a poor summary for imbalanced problems (a model that always predicts the majority class on a 99/1 dataset scores 0.99 while being useless), and R² can be negative when a regressor performs worse than predicting the mean.

The cardinal sin of this workflow is fitting on test data. Every one of these is a leak:

  • scaler.fit(X) on the full dataset before splitting — the test set's means and standard deviations influenced the training transformation.
  • scaler.fit_transform(X_test) instead of scaler.transform(X_test) — the test set is now scaled by its own statistics, which the deployed system could never know.
  • Imputing missing values, selecting features, or running PCA on the combined data.
  • Tuning hyperparameters by repeatedly checking the test score until it looks good — slower leakage, but leakage nonetheless.

The correct pattern is always fit on train, transform both:

from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_train_s = scaler.fit_transform(X_train)   # learns mean_ and scale_ from train only
X_test_s  = scaler.transform(X_test)        # reuses those learned statistics

Transformers and Preprocessing

A transformer rewrites the feature matrix. It learns the rewriting rule in fit and applies it in transform; fit_transform does both in one call and is sometimes faster than doing them separately. Many transformers also offer inverse_transform to map back to the original space.

StandardScaler standardises each column to zero mean and unit variance, storing mean_ and scale_:

scaler = StandardScaler()
scaler.fit(X_train)
print(scaler.mean_)    # one value per feature
print(scaler.scale_)   # standard deviations
Z = scaler.transform(X_train)   # (X - mean_) / scale_

Scaling is not cosmetic. Any algorithm that measures distances (k-NN, k-means, SVM with an RBF kernel, PCA) or that follows gradients (logistic regression with SGD, neural networks) is dominated by whichever feature happens to have the largest numeric range. On the wine dataset, proline runs into the hundreds while hue sits around 1 — unscaled, k-NN is effectively a one-feature model. Conversely, tree-based models (decision trees, random forests, gradient boosting) split on thresholds one feature at a time and are completely invariant to monotone rescaling, so scaling them is harmless but pointless. Alternatives include MinMaxScaler (squashes to [0, 1], useful when you need bounded inputs) and RobustScaler (uses median and interquartile range, far less sensitive to outliers).

Categorical data must become numeric. OneHotEncoder expands a column of k categories into k binary indicator columns, which is the right choice for nominal categories with no inherent order:

from sklearn.preprocessing import OneHotEncoder
import numpy as np

enc = OneHotEncoder(sparse_output=False, handle_unknown="ignore")
colours = np.array([["red"], ["green"], ["blue"], ["red"]])
print(enc.fit_transform(colours))
# [[0. 0. 1.]
#  [0. 1. 0.]
#  [1. 0. 0.]
#  [0. 0. 1.]]
print(enc.categories_)            # [array(['blue', 'green', 'red'], dtype=object)]
print(enc.get_feature_names_out())  # ['x0_blue' 'x0_green' 'x0_red']

handle_unknown="ignore" is important in production and in cross-validation: if a category appears in the test fold but not the training fold, the encoder emits all-zeros instead of raising. For linear models you may also want drop="first" to avoid perfect collinearity among the dummy columns.

LabelEncoder maps labels to integers 0…k−1, but note the asymmetry in its intended use: it is for the target y, not for features. Encoding a nominal feature as 0/1/2 tells a linear or distance-based model that "blue" is halfway between "red" and "green", which is nonsense. If you must integer-encode features (for example, for a tree model or an ordinal variable with a real order), use OrdinalEncoder, which is designed for 2D input.

from sklearn.preprocessing import LabelEncoder

le = LabelEncoder()
y_enc = le.fit_transform(["cat", "dog", "cat", "bird"])   # [1 2 1 0]
print(le.classes_)                 # ['bird' 'cat' 'dog']
print(le.inverse_transform(y_enc)) # back to the original strings

Missing values are handled by SimpleImputer, which learns a fill value per column:

from sklearn.impute import SimpleImputer
import numpy as np

X = np.array([[1.0, 2.0], [np.nan, 3.0], [7.0, 6.0]])
imp = SimpleImputer(strategy="median")     # 'mean', 'median', 'most_frequent', 'constant'
print(imp.fit_transform(X))
# [[1.  2. ]
#  [4.  3. ]
#  [7.  6. ]]
print(imp.statistics_)   # [4. 3.]  -> the learned medians

The strategy matters: mean is pulled around by outliers, median is robust and is usually the safer default for skewed numeric columns, most_frequent is the only sensible option for categorical columns, and constant (with fill_value=) is right when "missing" is itself meaningful. A common refinement is to add add_indicator=True, which appends a binary column recording where the gaps were, so the model can learn from the fact of missingness. For stronger imputation, KNNImputer fills a cell using the values of its nearest neighbours.

PCA is a transformer too, even though we usually think of it as an analysis technique. It finds the orthogonal directions of greatest variance and projects the data onto the first few of them:

from sklearn.decomposition import PCA
from sklearn.datasets import load_digits

X, y = load_digits(return_X_y=True)

pca = PCA(n_components=0.95, random_state=0)   # keep enough components for 95% variance
X_small = pca.fit_transform(StandardScaler().fit_transform(X))

print(X.shape, "->", X_small.shape)                 # (1797, 64) -> (1797, 40)
print(pca.explained_variance_ratio_[:5])            # variance captured per component
print(pca.explained_variance_ratio_.sum())          # ~0.95
X_back = pca.inverse_transform(X_small)             # approximate reconstruction

Note that n_components may be an integer (exactly that many components), a float in (0, 1) (as many as needed to reach that cumulative variance), or 'mle'. PCA is unsupervised — it never looks at y — so the directions it picks maximise variance, not class separation; a low-variance feature can still be the one that discriminates your classes. Always standardise before PCA when features have different units, because variance is scale-dependent. Typical uses are speeding up distance-based models, decorrelating inputs, denoising, and projecting to two dimensions for visualisation.

The non-negotiable rule for all transformers is the one stated earlier: fit on training data only. The means, medians, category lists and principal axes are themselves parameters learned from data; computing them over the test set lets information from the held-out examples bleed into training, and your reported score becomes optimistic by an amount you cannot measure. Doing this by hand across many steps is error-prone, which brings us to pipelines.

Pipelines for Reproducible Workflows

A Pipeline chains transformers followed by a final estimator and presents the whole chain as a single estimator. Calling fit on the pipeline calls fit_transform on each intermediate step in order and fit on the last one; calling predict calls transform on each intermediate step and predict on the last.

from sklearn.pipeline import Pipeline, make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA
from sklearn.svm import SVC

pipe = Pipeline([
    ("scaler", StandardScaler()),
    ("pca",    PCA(n_components=20)),
    ("clf",    SVC(C=1.0, kernel="rbf")),
])

pipe.fit(X_train, y_train)      # scaler and PCA fitted on train only
print(pipe.score(X_test, y_test))

# Identical object, names generated from the lower-cased class names:
pipe2 = make_pipeline(StandardScaler(), PCA(n_components=20), SVC())
print(pipe2.named_steps.keys())   # dict_keys(['standardscaler', 'pca', 'svc'])

The leakage-prevention benefit is the headline feature. When you pass a bare estimator to cross_val_score after manually scaling the whole dataset, every validation fold has already been contaminated by its own statistics. When you pass a pipeline, scikit-learn clones it for each fold and refits the scaler, imputer and PCA on that fold's training portion alone — exactly as a deployed system would behave on genuinely unseen data. The same applies inside GridSearchCV. This correctness guarantee, repeated across dozens of folds and candidates, is practically impossible to maintain by hand.

Real datasets mix numeric and categorical columns that need different treatment. ColumnTransformer routes subsets of columns to different transformers and horizontally concatenates the results:

from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression

numeric_features     = ["age", "income", "hours_per_week"]
categorical_features = ["occupation", "country"]

numeric_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale",  StandardScaler()),
])

categorical_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="most_frequent")),
    ("onehot", OneHotEncoder(handle_unknown="ignore")),
])

preprocess = ColumnTransformer([
    ("num", numeric_pipe,     numeric_features),
    ("cat", categorical_pipe, categorical_features),
], remainder="drop")           # or remainder="passthrough"

model = Pipeline([
    ("prep", preprocess),
    ("clf",  LogisticRegression(max_iter=1000)),
])

model.fit(X_train, y_train)    # X_train is a DataFrame with named columns

You can select columns by name, by position, by boolean mask, or dynamically with make_column_selector(dtype_include="number"). After fitting, preprocess.get_feature_names_out() tells you what each output column represents, which you need in order to interpret coef_.

To tune hyperparameters that live inside a composite estimator, address them with the double-underscore path syntax: step name, __, parameter name, nesting as deeply as necessary.

from sklearn.model_selection import GridSearchCV

param_grid = {
    "pca__n_components": [10, 20, 40],
    "clf__C":            [0.1, 1, 10],
    "clf__kernel":       ["rbf", "linear"],
}
search = GridSearchCV(pipe, param_grid, cv=5, scoring="accuracy", n_jobs=-1)
search.fit(X_train, y_train)

# Deeper nesting works the same way:
# "prep__num__impute__strategy": ["mean", "median"]
# You can even swap whole steps:
# {"clf": [SVC(), RandomForestClassifier()]}

Note that the keys of param_grid must be valid set_params paths — pipe.get_params().keys() lists every legal option if you are unsure.

Finally, because a fitted pipeline bundles the preprocessing statistics and the model together, it is the correct unit to persist. Serialise it with joblib, which handles large NumPy arrays more efficiently than plain pickle:

import joblib

joblib.dump(search.best_estimator_, "model.joblib")

# Later, in a grading script or a web service:
loaded = joblib.load("model.joblib")
y_pred = loaded.predict(new_raw_dataframe)   # scaling/encoding applied automatically

Saving only the classifier and forgetting the scaler is a classic bug: at inference time the raw features are fed to a model that expects standardised ones, and predictions degrade silently. Two caveats on persistence — the pickle format is tied to library versions (record them in your requirements.txt), and you should never unpickle a model from an untrusted source, because loading executes arbitrary code.

Cross-Validation and Model Selection

A single train/test split gives you one noisy estimate of performance. On 150 iris samples, changing random_state can move the test accuracy by several percentage points. Cross-validation reduces that variance by rotating the role of the validation set: the data is divided into k folds, the model is trained k times on k−1 folds and evaluated on the one left out, and every sample gets to be in the validation set exactly once.

from sklearn.model_selection import cross_val_score
import numpy as np

scores = cross_val_score(pipe, X_train, y_train, cv=5, scoring="accuracy")
print(scores)                                  # [0.94 0.91 0.96 0.93 0.95]
print(f"{scores.mean():.3f} +/- {scores.std():.3f}")

Always report the mean and the standard deviation. A mean of 0.93 ± 0.01 is a very different claim from 0.93 ± 0.09; the latter tells you the estimate is unstable and that any apparent improvement over a rival model of 0.92 is probably noise.

The default splitter depends on the estimator: plain KFold for regressors, StratifiedKFold for classifiers. Stratification keeps each fold's class proportions equal to the full dataset's, which is essential for imbalanced problems — with 5% positives and 10 folds, unstratified splitting can produce folds containing no positive examples at all, making recall undefined and the fold score meaningless. You can pass a splitter object explicitly for full control:

from sklearn.model_selection import StratifiedKFold, KFold, GroupKFold

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
scores = cross_val_score(pipe, X, y, cv=cv, scoring="f1_macro")

When one number is not enough, cross_validate returns a dictionary with several metrics plus timing information, and can optionally include the training scores and the fitted estimators:

from sklearn.model_selection import cross_validate

results = cross_validate(
    pipe, X_train, y_train, cv=5,
    scoring=["accuracy", "precision_macro", "recall_macro", "f1_macro"],
    return_train_score=True,
    return_estimator=False,
    n_jobs=-1,
)
for key, value in results.items():
    print(f"{key:>22}: {np.mean(value):.3f}")
# fit_time, score_time, test_accuracy, train_accuracy, test_f1_macro, ...

Comparing train_* with test_* across folds is the quickest overfitting diagnostic you have: train 0.99 / test 0.72 means high variance (simplify the model, regularise, get more data), while train 0.70 / test 0.69 means high bias (the model is too simple or the features are too weak). The fit_time column is also genuinely useful when you are weighing accuracy against compute budget.

GridSearchCV wraps all of this into a search: give it an estimator and a grid, and it cross-validates every combination, then refits the best configuration on the whole training set.

from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import GridSearchCV

grid = {
    "n_estimators":      [100, 300],
    "max_depth":         [None, 5, 10],
    "min_samples_leaf":  [1, 3, 5],
}
gs = GridSearchCV(
    RandomForestClassifier(random_state=0),
    grid, cv=StratifiedKFold(5, shuffle=True, random_state=0),
    scoring="f1_macro", n_jobs=-1, refit=True, return_train_score=False,
)
gs.fit(X_train, y_train)

print(gs.best_params_)      # {'max_depth': 10, 'min_samples_leaf': 3, 'n_estimators': 300}
print(gs.best_score_)       # best mean CV score
best = gs.best_estimator_   # already refitted on all of X_train
print(best.score(X_test, y_test))   # final, honest estimate on untouched data

import pandas as pd
pd.DataFrame(gs.cv_results_).sort_values("rank_test_score").head()

The cost of a grid is the product of its dimensions times the number of folds: the grid above is 2 × 3 × 3 × 5 = 90 model fits. Add a fourth hyperparameter with five values and you are at 450. RandomizedSearchCV breaks that exponential growth by sampling a fixed number of candidates from distributions you specify, so you control the budget directly:

from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import loguniform, randint

dists = {
    "clf__C":     loguniform(1e-3, 1e3),   # continuous, log-spaced
    "clf__gamma": loguniform(1e-4, 1e1),
    "pca__n_components": randint(5, 50),
}
rs = RandomizedSearchCV(pipe, dists, n_iter=60, cv=5,
                        scoring="accuracy", random_state=42, n_jobs=-1)
rs.fit(X_train, y_train)
print(rs.best_params_, rs.best_score_)

Random search is usually the better default for more than two or three hyperparameters. The intuition, from Bergstra and Bengio's well-known result, is that performance typically depends strongly on only a few parameters; a grid wastes most of its budget re-testing the same values of the important parameter, whereas random sampling tries n_iter distinct values of every parameter. A practical strategy is a broad random search first, then a small grid around the region it identifies.

Both searches expose the same result attributes — best_params_, best_score_, best_estimator_, best_index_ and the full cv_results_ table — and because refit=True by default, the search object itself is a fitted estimator: gs.predict(X_test) works directly. Remember that best_score_ is a cross-validation score computed during the search and is therefore mildly optimistic, since the configuration was chosen to maximise it; the held-out test set remains the number you report.

Evaluation Metrics for Assignments

Choosing the metric is a modelling decision, not an afterthought. The sklearn.metrics module follows a consistent signature, metric(y_true, y_pred, ...) — note the argument order, since swapping them silently changes asymmetric metrics such as precision and recall.

For classification, start from the confusion matrix, which counts every (true, predicted) pair and is the source from which the other metrics are derived:

from sklearn.metrics import confusion_matrix, ConfusionMatrixDisplay

cm = confusion_matrix(y_test, y_pred, labels=clf.classes_)
print(cm)
# [[50  0  0]
#  [ 0 45  5]
#  [ 0  8 42]]
# Rows = true class, columns = predicted class.
# Row 1 vs row 2: versicolor and virginica are being confused with each other.

For a binary problem the four cells are TN, FP, FN, TP, and the headline metrics are:

MetricFormulaAnswers the questionUse when
accuracy_score(TP+TN) / allWhat fraction of predictions were right?Classes are roughly balanced and all errors cost the same
precision_scoreTP / (TP+FP)Of those I flagged positive, how many really were?False positives are expensive (spam filters, costly interventions)
recall_scoreTP / (TP+FN)Of the real positives, how many did I catch?False negatives are expensive (disease screening, fraud)
f1_score2PR / (P+R)Harmonic mean of precision and recallYou need one number and the classes are imbalanced
roc_auc_scoreArea under TPR-vs-FPR curveHow well are positives ranked above negatives?Comparing rankers independently of any threshold

Precision and recall trade off against each other: lowering the decision threshold catches more positives (recall up) at the cost of more false alarms (precision down). The F1 score's harmonic mean punishes imbalance between them — 0.9 precision with 0.1 recall gives F1 ≈ 0.18, whereas the arithmetic mean would flatter it at 0.5.

For multiclass problems you must choose an averaging scheme, via the average= argument:

  • 'macro' — compute the metric per class and take the unweighted mean. Every class counts equally, so rare classes matter as much as common ones. Usually the right choice for imbalanced data.
  • 'weighted' — per-class metric weighted by support. Closer to accuracy; large classes dominate.
  • 'micro' — pool all TP/FP/FN globally. For single-label multiclass this equals accuracy.
  • None — return the array of per-class scores without averaging.
from sklearn.metrics import (accuracy_score, precision_score, recall_score,
                             f1_score, classification_report)

print(accuracy_score(y_test, y_pred))
print(precision_score(y_test, y_pred, average="macro", zero_division=0))
print(recall_score(y_test, y_pred, average="macro"))
print(f1_score(y_test, y_pred, average="macro"))

print(classification_report(y_test, y_pred, target_names=iris.target_names, digits=3))
#               precision    recall  f1-score   support
#       setosa      1.000     1.000     1.000        50
#   versicolor      0.849     0.900     0.874        50
#    virginica      0.894     0.840     0.866        50
#     accuracy                          0.913       150
#    macro avg      0.914     0.913     0.913       150
# weighted avg      0.914     0.913     0.913       150

classification_report is the single most useful one-call summary for a classification assignment: it shows where the model is strong and weak per class, and the support column immediately reveals imbalance. Use output_dict=True if you want to build a DataFrame from it.

Threshold-free evaluation uses scores rather than labels. roc_curve traces the true-positive rate against the false-positive rate as the threshold sweeps from high to low, and roc_auc_score summarises it; an AUC of 0.5 is random guessing and 1.0 is perfect ranking. Crucially, these take probabilities or decision scores, not hard predictions:

from sklearn.metrics import roc_curve, roc_auc_score, precision_recall_curve, average_precision_score

y_score = clf.predict_proba(X_test)[:, 1]     # or clf.decision_function(X_test)

fpr, tpr, thresholds = roc_curve(y_test, y_score)
print(roc_auc_score(y_test, y_score))

# For heavy imbalance, the precision-recall curve is more informative than ROC:
prec, rec, thr = precision_recall_curve(y_test, y_score)
print(average_precision_score(y_test, y_score))

# Multiclass ROC AUC:
# roc_auc_score(y_test, clf.predict_proba(X_test), multi_class="ovr", average="macro")

For regression the standard trio is:

MetricUnitsBehaviourBest value

from sklearn.metrics import mean_squared_error, mean_absolute_error, r2_score
import numpy as np

y_pred = reg.predict(X_test)
mse  = mean_squared_error(y_test, y_pred)
rmse = mean_squared_error(y_test, y_pred, squared=False)   # or np.sqrt(mse)
mae  = mean_absolute_error(y_test, y_pred)
r2   = r2_score(y_test, y_pred)
print(f"MSE={mse:.2f}  RMSE={rmse:.2f}  MAE={mae:.2f}  R2={r2:.3f}")

RMSE and MAE are both in the units of the target, which makes them easy to explain ("the model is off by about £18,000 on average"). Choose between them by asking how you feel about large errors: RMSE penalises a single 10-unit miss as heavily as a hundred 1-unit misses, while MAE treats them equally. R² is convenient for comparing across datasets because it is unitless, but it cannot be compared meaningfully across targets with different variances, and a negative value simply means your model is worse than the constant mean predictor — a useful sanity alarm.

Finally, tie the metric back into model selection. Every cross-validation and search object accepts a scoring argument that takes a string name, a callable, or a list/dict of them. The important convention is that scorers are always maximised, so error metrics appear with a neg_ prefix and return negative numbers:

from sklearn.model_selection import cross_val_score
from sklearn.metrics import make_scorer, fbeta_score

# Optimise the metric you actually care about, not the default:
cross_val_score(pipe, X, y, cv=5, scoring="f1_macro")
cross_val_score(pipe, X, y, cv=5, scoring="roc_auc")
cross_val_score(pipe, X, y, cv=5, scoring="balanced_accuracy")

rmse_scores = -cross_val_score(reg_pipe, X, y, cv=5,
                               scoring="neg_root_mean_squared_error")
print(rmse_scores.mean())

# A custom scorer, e.g. F2 weighting recall twice as heavily as precision:
f2 = make_scorer(fbeta_score, beta=2, average="macro")
cross_val_score(pipe, X, y, cv=5, scoring=f2)

Putting the whole topic together, a complete and defensible assignment workflow looks like this:

import joblib, numpy as np, pandas as pd
from sklearn.datasets import load_wine
from sklearn.model_selection import train_test_split, StratifiedKFold, GridSearchCV
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC
from sklearn.metrics import classification_report, confusion_matrix

RANDOM_STATE = 42

# 1. Load
X, y = load_wine(return_X_y=True, as_frame=True)

# 2. Hold out a test set, stratified and seeded
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=RANDOM_STATE)

# 3. Build a pipeline so preprocessing is refitted inside every fold
pipe = Pipeline([("scale", StandardScaler()),
                 ("clf",   SVC(random_state=RANDOM_STATE))])

# 4. Search hyperparameters with stratified cross-validation
grid = {"clf__C": [0.1, 1, 10, 100], "clf__gamma": ["scale", 0.01, 0.1]}
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=RANDOM_STATE)
search = GridSearchCV(pipe, grid, cv=cv, scoring="f1_macro", n_jobs=-1)
search.fit(X_train, y_train)

print("Best params:", search.best_params_)
print(f"CV f1_macro: {search.best_score_:.3f}")

# 5. Evaluate ONCE on the untouched test set
y_pred = search.best_estimator_.predict(X_test)
print(confusion_matrix(y_test, y_pred))
print(classification_report(y_test, y_pred, digits=3))

# 6. Persist the entire fitted pipeline for the grader
joblib.dump(search.best_estimator_, "wine_svc.joblib")

Every element of good practice is present: a fixed seed for reproducibility, a stratified hold-out set, preprocessing encapsulated in a pipeline so no statistic leaks across folds, a metric chosen deliberately rather than by default, cross-validated tuning, a single final evaluation on data the model has never seen, and a serialised artefact that reproduces the result end to end.

scikit-learn is the standard Python library for classical machine learning, and almost every modelling assignment in this course will use it. Its main strength is consistency: nearly every algorithm is wrapped in an object called an estimator, and every estimator exposes the same small set of methods. You call fit() to learn from data, predict() to produce outputs on new data, and transform() when the object's job is to reshape or rescale features rather than make predictions. Once you internalise this pattern, swapping a logistic regression for a random forest becomes a one-line change.

The library also supplies the surrounding machinery you need for honest results: dataset loaders and train/test splitting, preprocessing transformers such as scalers and encoders, Pipeline objects that chain preprocessing and modelling into a single reproducible unit, cross-validation utilities that give a more stable estimate of performance than a single split, and search tools such as GridSearchCV for tuning hyperparameters. Metrics modules then let you report accuracy, precision, recall, F1, confusion matrices, or regression errors depending on the task.

While watching the videos below, pay attention to three things: the exact sequence of calls (load data, split, fit, predict, score), where preprocessing belongs so that information from the test set never leaks into training, and how model selection and tuning are treated as separate steps from final evaluation. Try to replay each demonstrated workflow in your own notebook rather than only reading the code on screen.
