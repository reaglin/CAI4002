Problem Encoding and Representation

▶

Every genetic algorithm (GA) operates on two distinct levels. On one level there is the problem itself — a timetable, a circuit layout, a set of aerofoil parameters, a routing plan. On the other level there is the chromosome, the artificial data structure that the algorithm actually manipulates. The bridge between these two levels is the encoding (also called the representation). Nothing in a GA is more consequential than this choice: selection, crossover and mutation are all blind to the meaning of the problem and see only the chromosome, so the encoding determines what the algorithm can express, what it can combine, and what it can never reach at all. Two teams can implement identical selection schemes and identical population sizes and obtain wildly different results purely because one chose a representation whose structure matched the problem and the other did not.

The role of encoding in genetic algorithms. Borrowing the vocabulary of biology, a GA distinguishes the genotype — the encoded chromosome — from the phenotype — the actual candidate solution that the chromosome stands for. A chromosome is a structured string of genes; each gene occupies a fixed position, called its locus, and holds an allele, a value drawn from a defined alphabet. In a binary encoding the alphabet is simply {0, 1}; in an integer encoding for a graph-colouring problem it might be {red, green, blue, yellow}; in a real-valued encoding it is a bounded interval of the reals. The alphabet, the number of genes, and the rules governing their arrangement together constitute the representation.

Decoding is the procedure that turns a genotype back into a phenotype so that the fitness function can judge it. Decoding may be trivial — a vector of three real numbers interpreted directly as three physical dimensions — or it may be an elaborate computation, as when a chromosome of priority values is fed into a scheduling heuristic that constructs an actual timetable. The important point is that fitness is a property of the phenotype, while variation operators act on the genotype. Everything interesting about representation design lives in the quality of the mapping between the two.

Consider a concrete miniature example: the 0/1 knapsack problem with five items. A natural genotype is a five-bit string, and decoding means reading each bit as "take this item" or "leave it".

Items:      A      B      C      D      E
Value:      10     7      12     3      8
Weight:     5      3      6      2      4     Capacity: 10

Genotype:   1 0 1 0 0
Decoding:   take A, take C
Phenotype:  {A, C}  ->  value 22, weight 11  -> OVER CAPACITY, infeasible

Three structural consequences of encoding deserve emphasis.

  • The encoding defines the search space. The set of all strings the representation permits is exactly the set of solutions the GA can ever visit. If you encode a travelling salesman tour as a permutation of ten cities, the search space contains 10! = 3,628,800 points and nothing else — no partial tours, no tours that revisit a city. That is usually a virtue, because infeasible regions are excluded by construction. But it is also a hard boundary: a representation that cannot express the optimum guarantees that the optimum will never be found, no matter how long the run or how clever the operators. A classic failure is fixing the number of components (say, "exactly four layers in the neural network") when the best solution needs five.
  • A good encoding keeps related information close together. The building-block intuition behind crossover is that short, low-order, high-fitness patterns of genes — schemata — are inherited intact and recombined across parents. One-point and two-point crossover cut the chromosome at a small number of loci, so genes that sit adjacent to one another survive together with high probability, while genes at opposite ends are easily separated. If the x- and y-coordinates of the same physical component are adjacent in the chromosome, crossover tends to inherit that component as a unit; if they are scattered at loci 2 and 47, crossover will routinely shred a good component into two useless halves. Designing for locality of meaning along the chromosome is therefore a deliberate act, not an accident of implementation order.
  • Poor encodings create redundancy. Redundancy occurs when many distinct genotypes decode to the same phenotype. A moderate amount can be benign or even helpful (it adds neutral paths through the search space), but gratuitous redundancy wastes evaluations and dilutes selective pressure. The canonical example is encoding a set of k items as an ordered list: the same set of three items can be written in 3! = 6 ways, so the GA spends effort rediscovering permutations that are semantically identical. Similar waste arises when unused "junk" genes are carried along, or when a chromosome contains more parameters than the decoder actually reads.

Binary representation. The classical GA of Holland and Goldberg used fixed-length binary strings, and the binary alphabet remains the reference point against which other representations are compared. Its appeal is that the operators are maximally simple: one-point, two-point or uniform crossover on the bit string, and bit-flip mutation applied independently at each locus with some small probability (a common default is 1/L, where L is chromosome length, so that on average one bit flips per offspring).

Binary encoding is an exact fit for Boolean decision problems: subset selection, feature selection for a classifier, knapsack packing, sensor placement, switch settings in a logic circuit. Each bit answers one yes/no question and no decoding arithmetic is required. For feature selection over 40 candidate features, a 40-bit chromosome has one bit per feature; crossover swaps whole blocks of feature decisions between two promising subsets.

Continuous parameters can also be squeezed into binary by discretisation: allocate a block of n bits per variable, read the block as an unsigned integer g in [0, 2n−1], and scale it linearly into the variable's range [lo, hi]:

x = lo + g * (hi - lo) / (2^n - 1)

Example: 8 bits for a variable in [-5, 5]
  bits 10110010  ->  g = 178
  x = -5 + 178 * 10 / 255 = -5 + 6.980 = 1.980
Resolution = 10 / 255 = 0.0392 per step

This immediately exposes a precision/length trade-off. Ten bits per variable over the same range gives a resolution of 10/1023 ≈ 0.0098, four times finer, but a problem with 30 variables then needs a 300-bit chromosome. Longer chromosomes enlarge the search space exponentially (2300 points), slow convergence, and demand larger populations. If the required precision is 10−6 over a range of width 100, you need n such that 100/(2n−1) ≤ 10−6, i.e. n ≥ 27 bits per variable — at which point a real-valued encoding is almost always the better engineering decision.

Standard binary coding also introduces an artefact with no counterpart in the problem: the Hamming cliff. Numerically adjacent values can be very distant in bit space, so a single mutation cannot move between them. The transition from 7 to 8 in four bits requires all four bits to flip simultaneously:

If the optimum sits at 8 and the population has converged around 7, bit-flip mutation must perform four coordinated flips — an event of probability roughly p4 — to cross the cliff. The search stalls for reasons that are entirely an artefact of the code, not of the fitness landscape.

Gray coding repairs this. A Gray code is a binary numbering in which consecutive integers differ in exactly one bit, so single mutations always produce numerically adjacent values and the genotype distance better reflects phenotype distance. Conversion is cheap:

Binary -> Gray:   g[0] = b[0]
                  g[i] = b[i-1] XOR b[i]        (i > 0)

Gray -> Binary:   b[0] = g[0]
                  b[i] = b[i-1] XOR g[i]        (i > 0)

Example: binary 0111 (=7) -> Gray 0100
         binary 1000 (=8) -> Gray 1100    (differ in one bit)

Gray coding smooths local search behaviour and is a standard default whenever numeric quantities are encoded in bits. It does not eliminate all pathologies — large jumps still require multiple flips — but it removes the worst discontinuities around powers of two.

Integer and real-valued representations. When the decision variables are naturally discrete but not binary, an integer encoding is more honest than packing values into bits. Each gene holds a value from a finite set: the machine assigned to a job, the colour assigned to a vertex, the discrete gear ratio chosen for a stage, the resource level (0–5) allocated to a task. A graph-colouring chromosome for seven vertices with four available colours is simply [2, 0, 3, 1, 0, 2, 3]. Crossover can be the usual point or uniform variety (it never breaks validity, because any value from the alphabet is legal at any locus), and mutation resets a gene to a randomly chosen alternative value. Where the integers are cardinal rather than merely nominal — a quantity such as "number of vehicles", where 4 is closer to 5 than to 12 — a creep mutation that adds ±1 or ±2 is usually better than a uniform random reset, because it respects the ordering of the alphabet.

Real-valued (floating-point) encoding stores each design parameter directly as a double, so a chromosome is a vector such as [1.982, -0.447, 12.6031]. There is no bit-level discretisation, no Hamming cliff, and no precision ceiling imposed by chromosome length; the genotype is the phenotype. This makes real coding the standard choice for continuous parameter optimisation — aerodynamic shape design, controller tuning, curve fitting, calibration of simulation models.

The price is that bit-string operators no longer apply, so real-coded GAs need specialised operators:

  • Arithmetic (whole or single) crossover: the child is a convex combination of the parents, c = α·p1 + (1−α)·p2 with α ∈ [0,1]. With α drawn fresh each time, offspring lie on the line segment between the parents.
  • Blend crossover (BLX-α): for each gene, let d = |p1i − p2i| and sample uniformly from [min − α·d, max + α·d], typically with α = 0.5. Unlike pure arithmetic crossover this can produce values outside the parental interval, which counteracts the inexorable shrinkage of population spread.
  • Simulated binary crossover (SBX): uses a polynomial distribution to mimic the spread statistics of one-point binary crossover; widely used in modern multi-objective algorithms.
  • Gaussian mutation: add a normally distributed perturbation, x' = x + N(0, σ). Variants include uniform mutation within the bounds and non-uniform mutation whose spread shrinks with generation number.

The mutation step size σ becomes a first-class tuning parameter and effectively controls the exploration/exploitation balance. A large σ relative to the variable's range (say 20% of the range) scatters offspring widely and behaves like global search; a small σ (0.1% of range) performs fine local refinement but will not escape a basin of attraction. Common practice is to set σ as a fraction of the range per variable, to anneal it downwards over the run, or — as in evolution strategies — to self-adapt it by storing σ inside the chromosome alongside the object variables and letting selection tune it implicitly.

Self-adaptive real chromosome:
   [ x1, x2, x3 | sigma1, sigma2, sigma3 ]
   mutate sigma first:  sigma_i' = sigma_i * exp(tau * N(0,1))
   then mutate x:       x_i'     = x_i + sigma_i' * N(0,1)

Box constraints — the lower and upper bound on each variable — are not automatically respected by arithmetic or Gaussian operators, so every offspring must be made legal before evaluation. Three standard remedies exist, and the choice matters:

TechniqueRule for a value x outside [lo, hi]Behaviour and caution
Clipping (clamping)x ← lo if x < lo; x ← hi if x > hiSimplest; causes a build-up of individuals exactly on the bound, which is fine if optima are on the bound but biasing otherwise.
Reflection (bouncing)x ← lo + (lo − x), repeated until insideKeeps the distribution inside the box without clumping at the edge; needs iteration for extreme overshoots.
Wrapping (toroidal)x ← lo + ((x − lo) mod (hi − lo))Only sensible for genuinely cyclic variables such as angles; otherwise it teleports solutions across the space.
Resample / repairRedraw the perturbation until the child is feasible, or project onto the feasible setUnbiased but can be expensive near corners of the box.

Permutation representation. A large family of combinatorial problems asks not which items to use but in what order or in what one-to-one assignment: the travelling salesman problem (TSP), job-shop sequencing on a single machine, the quadratic assignment problem, flowshop scheduling, and ordering of operations in a production line. Here the chromosome is a permutation of 1..n and the defining constraint is that each element appears exactly once — no duplicates, no omissions.

This constraint is fragile. Standard one-point crossover destroys it immediately:

Parent 1:  1 2 3 | 4 5 6 7
Parent 2:  5 3 7 | 1 6 2 4

One-point child:  1 2 3 1 6 2 4     <- 1 and 2 duplicated, 5 and 7 missing: INVALID

Hence permutation GAs use order-preserving crossovers that are closed under the representation:

  • Order crossover (OX). Copy a contiguous segment from parent 1 into the child at the same positions. Then walk through parent 2 starting after the segment end, wrapping around, and fill the remaining child positions (also starting after the segment, wrapping) with the elements not yet present, in the order they appear in parent 2. OX preserves the relative order of the non-copied genes and is the workhorse for cyclic tour problems.
  • Partially mapped crossover (PMX). Copy a segment from parent 1, then use the positional correspondence between the two parents' segments as a mapping to place parent 2's remaining elements without conflict. PMX preserves absolute positions more strongly than OX, which suits assignment problems where "element 7 sits in slot 3" is itself meaningful.
  • Cycle crossover (CX). Identifies cycles of positions under the permutation that maps parent 1 to parent 2, then takes whole cycles alternately from each parent. Every gene in the child therefore occupies a position it held in one of the parents — maximal positional inheritance, minimal novelty.
  • Edge recombination (ERX). Builds an adjacency table of the edges present in both parents and constructs the child by always moving to the neighbour with fewest remaining connections. Designed specifically for the symmetric TSP, where the meaningful unit of inheritance is the edge, not the position.
OX example  (segment = positions 3..5)

Parent 1:  1 2 [3 4 5] 6 7
Parent 2:  4 6 [2 7 1] 3 5

Child starts:  _ _ 3 4 5 _ _
Read P2 from position 6 onward, wrapping: 3, 5, 4, 6, 2, 7, 1
Drop those already in child (3,4,5):       6, 2, 7, 1
Fill child from position 6 onward, wrapping:
Child:         2 7 3 4 5 6 1       <- a valid permutation

Mutation is likewise redesigned. Flipping or resetting a single gene would create a duplicate, so permutation mutation rearranges existing genes:

OperatorAction on 1 2 3 4 5 6 7Typical effect
Swap (exchange)swap positions 2 and 6 → 1 6 3 4 5 2 7Small positional change; for a TSP it alters four edges, so it is quite disruptive to tours.
Insertion (displacement)move 6 after 1 → 1 6 2 3 4 5 7Shifts one element while preserving the relative order of the rest; gentle on order-based problems.
Inversion (2-opt)reverse 3..6 → 1 2 6 5 4 3 7Changes only two edges in a symmetric tour; the natural local move for TSP.
Scrambleshuffle 3..6 → 1 2 5 3 6 4 7Larger, more exploratory perturbation of a contiguous block.

The final — and frequently overlooked — point is that different permutation problems care about different semantics, and the operator should match. In a symmetric TSP, the solution is defined by its set of edges; rotating or reversing a tour yields the identical phenotype, so operators that preserve adjacency (inversion, ERX, OX) are appropriate and positional operators waste effort chasing redundant encodings. In a machine-scheduling problem with release dates, the absolute position of a job in the sequence determines its start time, so PMX or CX — which transmit positions — align better with the fitness structure. Asking "does my fitness depend on who is next to whom or on who is in slot k?" is the diagnostic question that selects the operator set.

Tree and variable-length representations. Not every problem has a fixed, known number of decision variables. When the object being evolved is an expression, a program, a controller, or a rule, the natural representation is a tree of variable size and shape — the domain of genetic programming (GP). In a GP tree, internal nodes hold functions or operators drawn from a function set (arithmetic operators, IF-THEN-ELSE, trigonometric functions, logical connectives, robot commands), while leaf nodes hold terminals from a terminal set (input variables, random constants, zero-argument actions such as move-forward).

Expression:  (x * x) + (3 / y)

Tree:                +
                   /   \
                  *     /
                 / \   / \
                x   x 3   y

Prefix (Lisp-style) encoding:  (+ (* x x) (/ 3 y))

Variation operators work on subtrees rather than on string positions:

  • Subtree crossover: pick a random node in each parent (commonly biased 90% toward internal nodes, so that whole functional blocks rather than single leaves are exchanged) and swap the subtrees rooted there. Because the swapped fragments can be of very different sizes, offspring size varies freely from generation to generation.
  • Subtree mutation: pick a random node and replace the subtree rooted there with a freshly generated random subtree. Related operators include point mutation (replace a single node with another of the same arity), hoist mutation (promote a subtree to become the whole individual, which shrinks programs), and permutation mutation (reorder the arguments of a function node).

Tree encodings evolve things that a fixed-length vector simply cannot express: symbolic regression models whose functional form is unknown in advance, decision rules for a classifier, agent control programs, electronic circuit topologies, and even the architectures of other learning systems. The representation chooses both the structure and the parameters at once, which is its great strength — and the source of its characteristic pathologies.

The most notorious of these is bloat: the tendency of average program size to grow rapidly over generations without a corresponding improvement in fitness. Trees accumulate introns — semantically inert fragments such as (* x 1), (+ y 0), or (IF false ... ) — because larger individuals are statistically more likely to survive crossover with their behaviour unchanged, and because the space of large programs with a given behaviour is far bigger than the space of small ones. Bloat inflates evaluation cost, consumes memory, and produces unreadable solutions. The standard countermeasures are:

ControlMechanismTrade-off
Depth or node limitReject (or re-attempt) any offspring exceeding a maximum depth, e.g. 17 levels, or a maximum node countSimple and effective, but a hard ceiling can block the discovery of genuinely large solutions and causes individuals to pile up at the limit.
Parsimony pressureSubtract a size term from fitness: f' = f − c·(nodes)Gives a graded preference for compact programs; the coefficient c must be tuned, since too large a value suppresses useful complexity.
Multi-objective treatmentOptimise accuracy and size as two objectives and keep a Pareto frontAvoids choosing a coefficient, at the cost of a more elaborate algorithm.
Operator biasUse size-fair crossover or hoist mutation to balance growth and shrinkageKeeps size distributions stable without an explicit fitness penalty.
Editing / simplificationAlgebraically simplify trees periodicallyImproves readability but removes neutral material that may aid exploration.

Two design requirements make tree GP work at all. Closure demands that every function in the function set accept, without error, any value that any subtree might return. Division is the classic offender: (/ 3 0) crashes or returns infinity, so GP systems substitute protected division that returns 1 (or 0) when the denominator is zero; similarly sqrt is protected to take the absolute value and log to guard against non-positive arguments. If closure cannot be arranged — for example when a program mixes booleans, floats and vectors — the alternative is strongly typed GP, in which every node declares argument and return types and crossover may only swap subtrees of compatible type. Sufficiency demands that the primitive set be rich enough to express a satisfactory solution at all: attempting symbolic regression of a periodic signal with a function set of only {+, −, ×, ÷} and terminal {x} can only ever produce polynomial approximations. Sufficiency is the tree-encoding version of the general truth that the representation delimits the reachable search space; adding primitives enlarges that space but also enlarges the search burden, so the primitive set should be as small as domain knowledge allows.

Other variable-length schemes follow the same logic. Linear genetic programming evolves variable-length sequences of register machine instructions; grammatical evolution evolves an integer string that is interpreted through a BNF grammar to generate syntactically valid programs; messy GAs use variable-length lists of (locus, allele) pairs with under- and over-specification rules. All of them trade the convenience of fixed-length operators for the power to evolve structure.

Representation, constraints, and operator choice. Representation and operators are not independent choices made in sequence; they are a single design decision. The governing principle is closure under the representation: every operator must map valid chromosomes to valid chromosomes. One-point crossover is closed over binary strings, over integer strings whose alphabet is position-independent, and over real vectors (ignoring bounds), but it is not closed over permutations — which is precisely why OX, PMX and CX exist. If you change the representation, you must re-audit every operator.

When closure cannot be guaranteed — typically because the problem carries constraints beyond the shape of the chromosome — there are three broad strategies, and most real systems blend them:

  • Penalty functions. Allow infeasible offspring into the population but degrade their fitness in proportion to the degree of violation, e.g. for the knapsack f = total_value − λ·max(0, weight − capacity). Graded penalties are far better than a flat "fitness = 0", because they give the GA a gradient to follow back towards feasibility. A static λ risks being too soft (the population drifts into infeasible space) or too hard (the search cannot cross a thin infeasible barrier to reach a better feasible region), so adaptive or annealed penalties are common. Penalties shine when optima lie on the constraint boundary, since the search can approach it from both sides.
  • Repair procedures. Take an infeasible child and transform it into a feasible one, usually with a greedy heuristic: for the overweight knapsack, remove items in ascending order of value-to-weight ratio until the capacity is met; for a duplicated permutation, overwrite duplicates with the missing elements. Repair is often highly effective but embeds a heuristic bias into the search, and one must decide whether the repair is written back into the chromosome (Lamarckian) or used only for evaluation (Baldwinian), the two choices having markedly different effects on diversity.
  • Feasibility-by-construction encodings. Design the representation so that no invalid chromosome exists. A permutation encoding for the TSP makes "visit a city twice" unrepresentable. A random-key encoding — store a real number per item and decode by sorting — makes every real vector decode to a valid permutation, so ordinary real-coded operators can be used unchanged. This is the most elegant option when it is available, but it is not always possible, and it can introduce redundancy (many key vectors sort to the same order).

Locality is the quality metric that ties all of this together: a representation has high locality when a small change in the genotype produces a small change in the phenotype, and hence usually a small change in fitness. High locality makes mutation a tool for incremental refinement and makes the fitness landscape navigable; low locality turns mutation into random restart, and the GA degenerates towards random search. Gray coding improves locality over standard binary; real-valued encoding with small Gaussian steps has excellent locality; a hash-based or heavily indirect encoding may have almost none. Locality should be tested empirically during design: sample random individuals, apply single mutations, and plot the distribution of resulting fitness changes. A representation in which one mutation routinely sends fitness anywhere is a representation to redesign.

A further axis is direct versus indirect encoding. A direct encoding maps genes straight onto solution components — gene i is the colour of vertex i, or the x-coordinate of node i. It is transparent, easy to debug, and its locality is easy to reason about, but it scales linearly (or worse) with problem size and cannot exploit regularity. An indirect encoding stores parameters or instructions that a decoder interprets to build the solution. Examples include:

  • Random keys: a vector of reals decoded by sorting into a sequence or schedule.
  • Priority-rule encodings: the chromosome holds a list of dispatching-rule choices, and a scheduling heuristic constructs an always-feasible schedule from them — standard practice in resource-constrained project scheduling.
  • Generative/developmental encodings: a compact grammar or network (as in HyperNEAT or L-systems) that "grows" a large structure, allowing a short genome to specify a huge, regular phenotype.

Indirect encodings guarantee feasibility, compress the search space and can capture symmetry, but they weaken locality (one gene may influence the entire phenotype), can be expensive to decode, and make it harder to understand why a solution is good. The choice is a genuine trade-off, not a matter of fashion.

Finally, real engineering problems rarely fit into a single pure representation, so hybrid or mixed chromosomes are common. A chromosome may be partitioned into typed segments, each with its own alphabet and its own operators applied segment-wise:

Mixed chromosome for a wind-farm controller design:

[ 1 0 1 1 0 | 3 1 0 | 12.44  0.83  -2.07 | 4 2 7 1 5 6 3 ]
  binary      integer   real-valued         permutation
  (which      (control  (gains, set-        (maintenance
   sensors     mode per  points)             visit order)
   active)     turbine)

Operator plan:
  binary segment      -> uniform crossover, bit-flip mutation (p = 1/5)
  integer segment     -> uniform crossover, random-reset mutation
  real segment        -> BLX-0.5 crossover, Gaussian mutation (sigma = 5% of range)
  permutation segment -> order crossover (OX), inversion mutation

The rule for mixed chromosomes is that crossover and mutation are applied within segments, never across segment boundaries, so that closure is maintained for each part. Mutation rates are usually specified per segment as well, because what counts as a "gentle" perturbation differs enormously between a bit flip and a Gaussian step. Mixed encodings are the norm in design optimisation, where a product is defined simultaneously by topology choices, discrete component selections, continuous dimensions and an assembly order.

Pulling the threads together, representation design can be approached as a checklist: Can the representation express the optimum (sufficiency)? Does it exclude invalid solutions, or do I need penalties or repair? Are the operators closed under it? Does it keep interacting genes near one another so crossover inherits building blocks? Is its locality good enough that mutation refines rather than randomises? Is redundancy kept to a defensible level? And is decoding cheap enough to run thousands of times per generation? Answering these questions before writing the main loop saves far more time than tuning population size and crossover rate afterwards.
