Introduction

A constraint satisfaction problem gives you variables, a domain of possible values for each variable, and constraints that say which combinations are allowed. The most obvious way to solve one is generate-and-test: enumerate every complete assignment and check it. That is hopelessly wasteful, because a single violated constraint can often be detected after assigning just two variables, yet generate-and-test keeps filling in the rest before noticing. Backtracking search fixes this by building assignments incrementally and testing consistency of the partial assignment at every step, abandoning a branch as soon as it is doomed.

The algorithm itself is short: pick an unassigned variable, try each value in its domain, check consistency with the assignment so far, recurse, and undo the choice if the recursion fails. Two ideas make it efficient. First, consistency checking of partial assignments prunes whole subtrees early. Second, commutativity — the order in which you assign variables does not change the resulting assignment — means the search tree only needs one variable per level instead of branching over all remaining variables, cutting the tree from n!d^n leaves to d^n. Even so, d^n is exponential, and the worst case remains intractable; CSP solving is NP-hard in general.

That exponential ceiling is exactly why the rest of the module matters: improvements come from choosing which variable to assign next, which value to try first, and how much inference to do after each assignment. While watching the videos below, keep three questions in mind: what exactly is being checked at each node, when does the algorithm back up, and which decisions in the pseudocode are left deliberately unspecified so that heuristics can fill them in later.

The follow-up lecture that pins down the formal definitions: variables, domains, factors or constraints, and what it means for an assignment to satisfy them. Why this video

Precise definitions of assignment and consistency are the prerequisite for understanding why backtracking can reject a partial assignment at all, and this lecture supplies them at the level of rigor expected in this course.

About this video

A compact, code-first walkthrough that builds a Sudoku solver using backtracking in about five minutes, with source code linked in the description. It shows the concrete pattern of the algorithm: find the next empty cell, try each candidate value, check whether it conflicts with the current partial board, recurse, and reset the cell to empty when the recursion fails.

Why this video

It makes the recursive structure and the undo step of backtracking tangible on a problem every student knows, which is the fastest way to see how consistency checking of a partial assignment prunes the search tree in practice.

How These Videos Support the Learning Outcomes

The two Stanford lectures supply the vocabulary behind MO1 and MO2 — variables, domains, constraints, and the distinction between partial and complete assignments — and show how constraint structure is represented, which is what a constraint graph encodes. The Sudoku video directly supports MO3 and MO4: it formulates a familiar puzzle as a CSP and then implements the depth-first, one-variable-at-a-time solver with consistency testing that you are asked to write. None of the three videos covers the MRV, degree, or least-constraining-value heuristics of MO5 in depth, so treat them as establishing the baseline solver whose node counts the heuristics will later be measured against.
