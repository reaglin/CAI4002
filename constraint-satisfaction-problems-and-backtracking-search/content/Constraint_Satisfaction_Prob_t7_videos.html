Introduction

So far in this module you have defined CSPs formally and studied the machinery of backtracking search: variable and value ordering heuristics, consistency checks, and propagation. This topic is about putting that machinery to work. The goal is a single solver whose pieces are pluggable — swap in minimum-remaining-values instead of a fixed variable order, turn forward checking or arc consistency on and off — so that you can run controlled experiments rather than guessing which technique helps.

Two case studies anchor the work. Sudoku is a compact, well-understood benchmark: 81 variables, domains of 1 through 9, and all-different constraints over rows, columns, and boxes, which makes it ideal for watching propagation prune domains. Scheduling instances are messier and closer to practice, with precedence and resource constraints and often no obvious solution at all. Across both, you will measure performance the way researchers do — nodes expanded, consistency checks, wall-clock time — and learn to debug a constraint model when the solver returns nothing, returns garbage, or runs forever.

The videos below approach this from complementary angles. Two are from Stanford's CS221 lecture series and cover arc consistency and local search, which are the inference and the alternative-search ingredients you will plug into or compare against your backtracking solver. The third is a short, hands-on Python walkthrough of map coloring. While watching, pay attention to the distinction between search and inference, and to the moments where a speaker explains why a technique helps on some instances and not on others — that judgment is exactly what the subtopic "knowing when CSP methods fit" asks of you.

About this video

Another CS221 segment, this one covering local search for constraint satisfaction — methods that start from a complete but possibly inconsistent assignment and repair it by changing variable values, rather than building an assignment one variable at a time. Expect discussion of how such methods move through the search space, what guides the moves, and the tradeoffs against systematic search. Likely topics include why local search can scale to large instances but cannot prove that no solution exists.

Why this video

This video directly supports the "knowing when CSP methods fit" subtopic by showing the main alternative to backtracking and the conditions under which each is preferable. It gives you a fair baseline to compare your own solver against when you evaluate performance on larger scheduling instances.

About this video

A short prototype-project walkthrough that formulates map coloring as a constraint satisfaction problem and implements it in Python. In a few minutes it should show the concrete translation from a problem description into variables, domains, and constraints, and then the code that searches for a valid coloring. The channel notes parallel versions in other languages, suggesting the emphasis is on implementation structure rather than theory.

Why this video

It is the most implementation-oriented of the three and gives you a small, readable reference point for the code organization of a solver before you scale up to Sudoku and scheduling. Map coloring is simple enough that you can verify the output by eye, which makes it a useful first target when debugging a constraint model.

How These Videos Support the Learning Outcomes

Taken together these videos carry you from model to working, measurable code. The map coloring walkthrough reinforces MO3 by demonstrating an explicit variables-domains-constraints formulation and MO4 by showing the search loop in actual Python, which you can adapt to Sudoku and scheduling. The arc consistency lecture supplies the inference component you will toggle on and off when gathering node counts for MO5, and it depends on reading the constraint graph correctly, reinforcing MO2. The local search lecture provides the contrast case: by seeing a method that manipulates complete assignments rather than extending partial ones, you sharpen the MO1 distinctions between partial, complete, and consistent assignments and gain a basis for judging when systematic backtracking is the right tool.
