Local Maxima, Plateaus, and Ridges

▶

Local search abandons the idea of building a solution step by step along a path. Instead it keeps a single complete state — an entire candidate solution, however bad — and repeatedly nudges it into a neighbouring state in the hope of improving some measure of quality. This design buys enormous savings in memory (one state, not a frontier of partial paths) and makes it possible to attack problems whose state spaces are astronomically large. The price is that the search becomes blind: it can only compare the current state with states reachable by one move, and therefore has no global map of the terrain it is crossing. The characteristic failure modes of hill climbing — local maxima, plateaus, shoulders, and ridges — are all direct consequences of this blindness, and the standard remedies all amount to buying back, in one way or another, a little of the information that was given up.

The local search landscape. It is useful to picture the search space as a physical surface. Every point on that surface is one complete state: a full assignment of a queen to every column of a chessboard, a complete timetable for every class in a school, a complete tour visiting every city. The height of the point is the number produced by the objective function (for maximisation) or the heuristic cost function (for minimisation). The horizontal axes are a schematic stand-in for the move structure: two points are "adjacent" on the landscape if one move of the neighbourhood operator converts one into the other. A landscape is therefore defined jointly by three things — the state representation, the move operator, and the evaluation function — and changing any of them changes the shape of the surface. The same problem can have a cratered, treacherous landscape under one operator and a smooth, almost convex landscape under another.

Within this picture, a global maximum is the highest peak anywhere on the surface; reaching it means the algorithm has found an optimal solution. For a satisfaction problem such as 8-queens with the usual heuristic h = number of pairs of queens attacking each other, the global optimum is the flat ceiling at h = 0; for an optimisation problem such as the travelling salesperson problem, the global optimum is the single shortest tour (or the set of tours tied for shortest). The distinction matters because satisfaction problems often have many global optima scattered across the landscape, which makes them easier to hit by chance, while a genuine optimisation problem may have exactly one.

Hill climbing perceives none of this. At each iteration it evaluates only the states one move away, picks a better one, and moves. The classical metaphor is a climber in dense fog with amnesia: the fog means only the immediate neighbourhood is visible, and the amnesia means no record is kept of where the climber has already been. Both halves matter. Fog alone would still allow a systematic sweep; amnesia alone would still allow long-range vision. Together they mean the algorithm's entire fate is decided by local gradient information — the direction in which the terrain happens to rise at the current point. If the terrain stops rising, the climber stops, whether standing on Everest or on an anthill.

function HILL-CLIMBING(problem) returns a state
    current <- problem.INITIAL-STATE          // a complete, usually random, state
    loop do
        neighbour <- highest-valued successor of current
        if VALUE(neighbour) <= VALUE(current) then
            return current                     // no uphill move: stop here
        current <- neighbour

Note what is absent from this pseudocode: there is no visited set, no queue, no backtracking and no record of the best state ever seen. The single line if VALUE(neighbour) <= VALUE(current) then return current is the source of every difficulty discussed below.

Local maxima. A local maximum is a state that is higher than every one of its neighbours but lower than the global maximum. When hill climbing arrives at such a state, the loop condition fires and the algorithm halts, returning a suboptimal answer. Crucially, it returns that answer with complete confidence and no indication whatsoever that something better exists: from inside the algorithm, a local maximum and the global maximum are indistinguishable, because both look like "a state no neighbour improves on". Unless the problem supplies an external test (for example, "a solution is only acceptable if h = 0"), the caller cannot tell whether the result is optimal.

Local maxima are, empirically, the single most common cause of hill-climbing failure. The standard illustration is 8-queens with the "move one queen within its column" operator. Each state has 8 × 7 = 56 successors. Starting from random states, steepest-ascent hill climbing solves only about 14% of instances; the remaining 86% of runs get stuck, the overwhelming majority of them on local maxima rather than on flat regions. A typical stuck state has h = 1 — a single attacking pair — yet every one of the 56 single-queen moves either leaves h at 1 or raises it. The fix requires moving two queens at once, which is outside the neighbourhood, so the algorithm is genuinely trapped. On the positive side, the runs are cheap: successful runs average about 4 steps and failures about 3, so each attempt costs almost nothing.

The depth of the valleys surrounding a peak determines how hard it is to escape. If the neighbours of a local maximum are only slightly worse, a method that occasionally tolerates a small loss (simulated annealing at a moderate temperature, or a sideways/worsening move) will slip out quickly. If the peak is an isolated needle surrounded by a deep moat — a situation sometimes called a "golf-hole" landscape — then any perturbation large enough to leave the peak lands far down the slope, and the search effectively restarts. This is why escaping a true local maximum always requires accepting a temporarily worse state, something pure greedy search is by definition forbidden to do. Every escape mechanism in the rest of this topic is a disciplined way of relaxing that prohibition: randomised acceptance (annealing), forced acceptance through prohibition of the best move (tabu), or discarding the state entirely (restart).

Plateaus and shoulders. A plateau is a flat region of the landscape: a connected set of states all having the same objective value. Two very different situations hide under this one name, and telling them apart is the whole point:

  • A flat local maximum is a plateau with no uphill exit anywhere along its boundary. Every state outside the plateau that is reachable in one move is strictly worse. Progress by local moves is impossible; the only way out is a restart or a large perturbation.
  • A shoulder is a plateau that does have an uphill exit somewhere along its edge. The terrain is flat for a while and then resumes climbing. Here persistence genuinely pays off: if the search is willing to wander across the flat region long enough, it will eventually reach the lip and continue upward.

Strict hill climbing, as written above, halts on both kinds of plateau, because VALUE(neighbour) <= VALUE(current) is true when the values are equal. It thus throws away all shoulders along with all flat maxima — a severe loss, since shoulders are extremely common in combinatorial problems where the objective is integer-valued and coarse-grained (counts of conflicts, counts of violated constraints, numbers of satisfied clauses). In such problems huge numbers of distinct states share the same score, so plateaus are the norm rather than the exception.

The obvious remedy, allowing moves to equal-valued neighbours, introduces its own hazard. Because the algorithm has no memory, a random walk across a plateau can revisit states indefinitely. On a plateau of n states, an unbiased random walk needs on the order of n² moves to cross a one-dimensional strip, and the search may consume an enormous amount of time with the objective function never changing by so much as a single unit. Worse, on a flat local maximum this wandering can never succeed, so the time is wholly wasted. The practical answer is to allow sideways movement but to bound it, which leads to the next subtopic.

Ridges and zig-zagging. A ridge is a long, narrow, rising structure whose crest is sharp relative to the moves available. The defining feature is a mismatch between the orientation of the ridge and the directions the operator can move in. Suppose a continuous problem allows only axis-parallel steps (change x, or change y, but not both) while the ridge runs diagonally. Standing exactly on the crest, a step in x alone takes you off the crest and downhill; a step in y alone does the same. Every individual move is a loss, so steepest-ascent sees no improving step and stops — even though the terrain plainly rises if you walk along the diagonal.

If the steps are small enough that an off-crest move still lands slightly higher than where you started, the behaviour is different but barely better: the search zig-zags, alternating x and y steps and crawling up the ridge in a staircase of tiny net gains. Each gain costs a full round of neighbour evaluations, so the number of objective-function calls explodes while progress is minimal. Consider the function f(x, y) = -(x - y)² - 0.01(x + y - 10)², whose ridge runs along the line x = y. From the point (3, 3) a unit step in either coordinate alone immediately incurs the large -(x - y)² penalty, while the diagonal move to (4, 4) improves the objective. An axis-parallel operator simply cannot see the improvement.

Ridges are especially common in continuous optimisation when the variables are strongly correlated — that is, when the Hessian of the objective is ill-conditioned and its contours are long thin ellipses tilted with respect to the coordinate axes. Rosenbrock's banana function is the textbook example. Three families of remedy exist:

  • Compound or larger neighbourhoods. If the operator can change two variables simultaneously, or swap two assignments rather than reassign one, it may cut across the ridge in a single move. In 8-queens, a "swap the rows of two queens" operator reaches states that the single-queen operator cannot, flattening some of the landscape's worst features. The trade-off is cost: a k-variable compound neighbourhood grows combinatorially, so each step becomes much more expensive to evaluate.
  • Re-orienting the moves. Pattern search, Rosenbrock's method and conjugate-direction methods adapt the step directions to align with the ridge; gradient-based methods with momentum or second-order curvature information do the same thing analytically.
  • Re-representing the problem. A change of variables that decorrelates the dimensions converts the tilted ellipse into a circle and dissolves the ridge altogether. This is the deepest fix but requires insight into the problem structure.

Sideways moves and bounded persistence. Allowing sideways moves means permitting a transition to a neighbour of equal value. The modified acceptance test becomes if VALUE(neighbour) < VALUE(current) then return current — strictly less, rather than less-or-equal. This single character change lets the search traverse shoulders and resume climbing on the far side.

Without a limit, however, the algorithm can loop forever on a flat local maximum, drifting among equal-valued states that never lead anywhere. The standard implementation therefore caps the number of consecutive non-improving moves; the counter resets to zero whenever a strictly better state is found and the run is declared a failure when the cap is reached. The cap is a tuning parameter trading computation against coverage.

Variant on random 8-queens instancesSuccess rateAverage steps (success)Average steps (failure)
Steepest-ascent, no sideways moves≈ 14%≈ 4≈ 3
Steepest-ascent, up to 100 consecutive sideways moves≈ 94%≈ 21≈ 64

The table captures the bargain precisely: success rises from roughly one run in seven to roughly nineteen in twenty, but the average successful run becomes about five times longer and failures become about twenty times longer. Sideways moves buy a substantially higher success rate with additional computation time, which is usually an excellent trade when evaluating a state is cheap.

What sideways moves do not do is escape a true local maximum. If every neighbour is strictly lower, there is no equal-valued state to move to, the counter never even starts, and the algorithm halts exactly as before. Sideways moves are a cure for flatness, not for peakedness — a distinction worth remembering when diagnosing why a particular search is underperforming. If a profiler shows runs terminating after very few steps with no sideways moves used, the landscape is peaked and restarts or annealing are needed; if runs terminate at the sideways-move cap, the landscape is flat and a larger cap or a plateau-aware operator may help.

Random restarts and stochastic variants. The simplest and often the most effective response to a trap is to leave the landscape entirely and start again somewhere else.

  • Random-restart hill climbing runs hill climbing from a randomly generated initial state, keeps the best result found, and repeats until a goal is found or a budget is exhausted. It is trivially complete in the limit: since initial states are drawn at random from the whole space, the generator will eventually produce a goal state (or a state in the goal's basin of attraction) with probability approaching one. If a single run succeeds with probability p, the expected number of runs needed is 1/p and the expected total cost is one successful run plus (1-p)/p failed ones. For 8-queens without sideways moves, p ≈ 0.14, so about 7 runs are needed — roughly 4 + 6 × 3 ≈ 22 steps in total, which is trivial. With sideways moves, p ≈ 0.94 and about 1.06 runs suffice.
  • Stochastic hill climbing does not automatically take the steepest ascent. It chooses at random among the uphill neighbours, with probability weighted by the steepness of the improvement. Because it sometimes takes a gentler slope, it converges more slowly than steepest ascent, but it explores a wider variety of trajectories and in many landscapes converges to better optima — the steepest local gradient is frequently the one that leads into the nearest mediocre peak.
  • First-choice hill climbing implements stochastic hill climbing for states with enormous branching factors. Instead of enumerating all successors, it generates them one at a time in random order and moves to the first one that improves on the current state. When a state has thousands or millions of neighbours, evaluating them all for one step is prohibitive, and first-choice gets a usable move after only a handful of evaluations.

Restarts are also embarrassingly parallel: independent runs share no state, so k processors deliver very nearly a k-fold speed-up with trivial coordination (each worker reports its best state; the controller keeps the maximum). They compose freely with every other variant — one can run random-restart first-choice hill climbing with bounded sideways moves, or restart simulated annealing with different seeds — which is why restarts are usually the first enhancement added to any local search implementation. The main caveat is that restarts discard all accumulated information; on problems where good solutions share common structure, a biased or perturbation-based restart (as in iterated local search, which restarts from a kicked version of the incumbent rather than from scratch) typically outperforms uniform random restarting.

Tabu search and memory-based escape. Tabu search attacks the amnesia directly. The algorithm always moves to the best neighbour even when that neighbour is worse than the current state, and prevents the resulting cycling by maintaining a tabu list: a short, fixed-length memory of recently performed moves, or of attributes of recently visited states (for example, "queen 5 was moved out of row 3", or "edge (c, d) was removed from the tour"). Moves that would reverse a tabu attribute are forbidden for as long as it stays on the list.

function TABU-SEARCH(problem, tenure, max-iterations) returns a state
    current <- problem.INITIAL-STATE
    best    <- current
    tabu    <- empty list
    for i = 1 to max-iterations do
        candidates <- { s in NEIGHBOURS(current) :
                        move(current, s) not tabu
                        or VALUE(s) > VALUE(best) }      // aspiration criterion
        current <- argmax VALUE over candidates           // may be worse than current
        push move(current) onto tabu; if length(tabu) > tenure then pop oldest
        if VALUE(current) > VALUE(best) then best <- current
    return best

The mechanism is elegant. On reaching a local maximum, every neighbour is worse; the algorithm nevertheless steps down to the least-bad one. Pure greedy search would immediately step back up to the peak, oscillating forever — but the upward move is now tabu, so the search is compelled to keep walking, descending one side of the peak until it finds a route up a different slope. Prohibiting backtracking is what converts a tolerance for worsening moves into actual escape.

The tabu tenure — how many iterations an attribute stays forbidden — is the key tuning parameter, and the trade-off is sharp:

Tenure settingEffect on searchTypical symptom
Too shortRecently reversed moves become legal again before the search has left the basinCycling: the same small set of states is revisited indefinitely
Well chosenEnough prohibition to leave a basin, enough freedom to exploit a promising regionSteady improvement of the incumbent best, with visible descents and recoveries
Too longLarge parts of the neighbourhood are forbidden at every stepOver-constrained search: the candidate set empties, moves become arbitrary, quality stalls

A tenure on the order of the square root of the neighbourhood size is a common starting heuristic, and reactive tabu search adjusts the tenure automatically, lengthening it when repetition is detected and shortening it when the search appears over-constrained. The aspiration criterion shown in the pseudocode is a standard safeguard: a tabu move is permitted anyway if it would yield a state better than any seen so far, since the prohibition exists to prevent cycling, not to prevent progress. Richer schemes add long-term memory: frequency counts that penalise moves used often (diversification, pushing the search into unexplored regions) and elite-solution pools that restart from previously good states (intensification).

Finally, memory-based and randomised escape mechanisms are complements rather than rivals. Simulated annealing escapes by probabilistically accepting downhill moves according to a temperature that falls over time; tabu search escapes by deterministically forbidding recently used moves. Annealing needs no memory but requires a well-tuned cooling schedule and may accept pointless downhill moves; tabu search needs no temperature but requires memory structures and tenure tuning. Hybrids are routine — for example, annealing with a short tabu list to suppress immediate reversals, or tabu search with randomised candidate-list sampling in the style of first-choice hill climbing. Choosing among them is an engineering decision driven by the shape of the landscape, the cost of evaluating a state, and the computational budget available.
