Admissibility and Consistency

Introduction

A heuristic function h(n) is a guess about how much it will cost to get from node n to a goal. Two properties decide whether that guess is safe to use. A heuristic is admissible if it never overestimates: 0 <= h(n) <= h*(n), where h*(n) is the true optimal remaining cost. A heuristic is consistent (or monotonic) if it satisfies a triangle inequality on every edge: h(n) <= c(n, a, n') + h(n') for every successor n' of n, with h(goal) = 0.

These definitions matter because they are exactly what A* needs. Admissibility is what guarantees that tree-search A* returns an optimal solution; consistency is the stronger condition that also makes graph-search A* safe, because f-values never decrease along a path and a node is never re-expanded with a cheaper g. Every consistent heuristic is admissible, but the converse is false, so you should be able to produce or recognize a heuristic that is admissible yet inconsistent.

As you watch, keep two questions in front of you. First, how does each video justify that a heuristic never overestimates, usually by appealing to a relaxed version of the problem whose solution cost is a lower bound? Second, where does the triangle inequality show up, whether stated directly or implicitly through edge costs, potentials, and non-decreasing f-values along a path? Then practice the verification routine: check h(goal) = 0, argue the lower-bound property, and test the edge inequality on a few representative transitions.

About this video

An animated explainer that reframes A* as Dijkstra's algorithm run on a graph whose edge lengths have been modified by a potential function. The chapter list moves from changing the lengths, to what makes a good potential, to implementation, which is the natural setting in which the condition that reweighted edges stay non-negative appears.

Why this video

That non-negativity condition on reweighted edges is precisely the consistency inequality h(n) <= c(n, a, n') + h(n'), so the video gives a visual, intuitive route to understanding monotonicity and why f-values behave well along a path.
