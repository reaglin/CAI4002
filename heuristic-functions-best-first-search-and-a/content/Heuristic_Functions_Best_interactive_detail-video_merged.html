Heuristic Evaluation Functions

▶

Search algorithms that know nothing about the problem beyond its state space — breadth-first, depth-first, uniform-cost — must explore blindly. They cannot tell the difference between a node that sits one step from the goal and a node that sits fifty steps away, except by eventually expanding both. An heuristic evaluation function is the mechanism by which we inject problem-specific knowledge into an otherwise generic search procedure, so that the algorithm can prefer nodes that look closer to a solution. The remainder of this topic develops what such a function is, where its numbers come from, what the classic examples look like in pathfinding and sliding-tile domains, and how to compare and combine several heuristics for a single problem.

What Is a Heuristic Function?

A heuristic function, written h(n), is a mapping from a search node n to a non-negative real number that estimates the cost of the cheapest path from the state at n to a goal state. Formally:

h : Nodes -> R, with h(n) >= 0 for all n
h(n) = 0 whenever n is a goal node (by convention and good practice)

The non-negativity requirement is not arbitrary: costs in a search problem are non-negative, so a "remaining cost" of less than zero is meaningless and would corrupt the node-ordering arithmetic used by algorithms such as A*. The convention h(goal) = 0 matters too — a heuristic that reported some positive value at the goal would discourage the algorithm from recognising the solution it has already found.

It is essential to keep h(n) distinct from the other cost quantity carried by a search node, g(n):

QuantityDirectionNature of the valueHow it is obtained
g(n)Backward-lookingExact, knownAccumulated by summing the step costs along the path actually followed from the start node to n
h(n)Forward-lookingEstimated, uncertainComputed from the state description by a domain-specific formula
h*(n)Forward-lookingExact, usually unknownThe true cost of the optimal path from n to the nearest goal; computing it is generally as hard as solving the problem
f(n)Whole pathEstimate of total solution cost through ng(n) + h(n)

Two subtleties follow from this table. First, g(n) is a property of a node — of a particular path to a state — whereas h(n) is a property of the state itself. Two different nodes holding the same state necessarily have the same h value but may have quite different g values. Second, h*(n) is a well-defined mathematical object even though we cannot compute it cheaply; it is the yardstick against which heuristic quality is measured. If a state has no path to any goal at all, h*(n) is infinite.

Because h(n) is an estimate, it is permitted to be wrong. A heuristic may underestimate (h(n) < h*(n)), be exact (h(n) = h*(n)), or overestimate (h(n) > h*(n)). These three cases have very different consequences. Underestimating heuristics are safe for optimal search, because a search algorithm that trusts them will never prematurely discard a path whose true cost turns out to be low. Overestimating heuristics can cause an algorithm to abandon the genuinely best route and return a suboptimal answer; in exchange they often reduce the number of expansions. The term admissible is reserved for heuristics that never overestimate — that is, those satisfying 0 <= h(n) <= h*(n) for every node.

The operational role of a heuristic is to rank the frontier. A best-first search keeps a priority queue of unexpanded nodes and repeatedly removes the one with the smallest evaluation value. Greedy best-first search orders by h(n) alone; A* orders by f(n) = g(n) + h(n). In both cases the heuristic is what makes the ordering informative. Consider a toy illustration: the frontier contains three nodes with g values 4, 6 and 9. Uniform-cost search expands the one with g = 4. But if their heuristic values are 20, 3 and 1 respectively, A* computes f values of 24, 9 and 10, and expands the second node instead — it has used forward-looking knowledge to recognise that the cheap-so-far path is heading in a hopeless direction.

The payoff from a heuristic is measured in how much of the state space the search can avoid touching. A useful way to quantify this is the effective branching factor b*: if a search expands N nodes to find a solution at depth d, then b* is the branching factor a uniform tree of depth d would need to contain N + 1 nodes:

N + 1 = 1 + b* + (b*)^2 + ... + (b*)^d

A well-designed heuristic drives b* close to 1, meaning the search advances almost in a straight line towards the goal. For the 8-puzzle, blind iterative-deepening search has an effective branching factor near 2.45; the misplaced-tile heuristic brings it to roughly 1.4 and Manhattan distance to roughly 1.25. Those small-looking differences compound exponentially with depth: at depth 24, iterative deepening may expand on the order of tens of millions of nodes, misplaced tiles tens of thousands, and Manhattan distance a couple of thousand. The quality of h is therefore not a marginal tuning concern — it is the dominant factor in whether a search is feasible at all.

Encoding Domain Knowledge as an Estimate

Where do the numbers in a heuristic come from? The single most reliable and principled technique is problem relaxation. The recipe is:

  • Write down the problem's actions together with their preconditions.
  • Delete one or more preconditions, producing a relaxed problem whose action set is a superset of the original's.
  • Solve the relaxed problem exactly — ideally by a closed-form formula rather than by search.
  • Use that exact relaxed cost as h(n) for the original problem.

This construction automatically produces an admissible heuristic, and the argument is worth internalising. Every legal solution to the original problem is still a legal solution to the relaxed problem, because removing preconditions can only add options, never remove them. Hence the relaxed problem's optimal solution is at least as cheap as the original's optimal solution, so the relaxed cost can never exceed h*(n). Relaxation-derived heuristics are also, as it happens, always consistent, because the relaxed cost itself obeys a triangle inequality over the relaxed state space.

Apply the recipe to the 8-puzzle. The legal action can be stated as: "a tile may move from square A to square B if A is horizontally or vertically adjacent to B and B is blank." There are two preconditions to play with.

  • Delete both preconditions — a tile may move from any square to any square in one step. The cheapest solution is then simply to teleport each misplaced tile directly home, one move per misplaced tile. The exact relaxed cost is the count of misplaced tiles, which is the heuristic h1.
  • Delete only "B is blank" — a tile may slide to any adjacent square, passing straight through occupied squares. Each tile now travels independently along a grid path to its goal square, and the shortest such path has length equal to the tile's horizontal plus vertical offset. Summing over all tiles gives Manhattan distance, the heuristic h2.
  • Delete only "A is adjacent to B" — a tile may jump to the blank square from anywhere. This yields a third, less commonly used heuristic sometimes called Gaschnig's heuristic, computable by simulating the simplified puzzle; it lies between h1 and h2 in strength on many states.

Apply the same recipe to road navigation. The real problem says: "you may move from town A to town B at cost equal to the road length, provided a road connects A and B." Delete the precondition that a road must exist and let the cost be the Euclidean separation — you may now fly in a straight line across fields, rivers and mountains. The exact solution to this relaxed problem is the straight-line distance from the current location to the destination, giving h_SLD.

Relaxation is not the only source of domain knowledge, however. Two further families are important in practice:

  • Pattern databases. Select a subset of the problem's elements — for example tiles 1, 2, 3 and 4 of the 15-puzzle, treating the other tiles as indistinguishable "don't care" markers. Exhaustively search this reduced space backwards from the goal and store, in a lookup table keyed by pattern configuration, the exact minimum number of moves needed to place those tiles correctly. At search time, h(n) is a single array lookup. Because every real solution must also solve the subproblem, the stored value never overestimates. Disjoint (additive) pattern databases go further: if each database counts only moves of its own tiles, and the tile sets are disjoint, the separate lookups may be added rather than merely maximised, producing dramatically stronger estimates. Additive databases are what made optimal solution of the 24-puzzle practical.
  • Subproblem decomposition and learned heuristics. Costs of independently solvable components can be summed when the components do not share resources. Alternatively, a function approximator can be trained on features of the state (for instance, "number of adjacent tile pairs that are out of order") using solved instances as training data. Learned heuristics are usually inadmissible, since statistical fitting offers no guarantee of never overestimating, but they can be fast and accurate in the average case.

Straight-Line Distance for Pathfinding

In a map or grid domain where every location carries coordinates, the canonical heuristic is straight-line (Euclidean) distance to the goal:

h_SLD(n) = sqrt( (x_n - x_goal)^2 + (y_n - y_goal)^2 )

Its appeal begins with cost: the computation is two subtractions, two multiplications, one addition and one square root — a few nanoseconds, independent of the size of the map. Nothing about the road network need be consulted, only a coordinate pair per node, which is a trivial amount of data to store.

Its admissibility is equally straightforward. In the Euclidean plane, the line segment between two points is the unique shortest curve joining them. Any actual route, being a sequence of road segments, is a path in the plane from n to the goal and therefore has length at least the length of that segment. Hence h_SLD(n) <= h*(n) always, provided edge costs really are road lengths. The qualification matters: if edge costs represent travel time in minutes rather than distance in kilometres, then raw kilometres may exceed the minute-count and destroy admissibility. The standard fix is to divide by the maximum achievable speed, h(n) = h_SLD(n) / v_max, which restores the guarantee because no vehicle can cover the straight-line gap faster than that.

Consider a concrete miniature example. Suppose the goal lies at coordinates (0, 0) and four frontier nodes have coordinates and known path costs as follows:

NodeCoordinates (x, y)g(n)h_SLD(n)f(n) = g + h
A(30, 40)2050.070.0
B(60, 0)7560.0135.0
C(0, 25)9525.0120.0
D(9, 12)14015.0155.0

A greedy best-first search, ordering by h alone, would seize on node D as the closest to the goal — ignoring the 140 units already spent getting there. An A* search, ordering by f, expands A, whose total estimated journey is cheapest. Notice also how the heuristic separates genuinely different situations that g alone conflates: C and D are geometrically near the goal but expensively reached, while B is both far and expensive and is correctly deprioritised.

The weakness of straight-line distance appears when geometry and topology diverge. If the destination lies directly across a bay, a mountain range, a motorway with no crossing, or a one-way system, the physical detour may be several times the straight-line gap. The heuristic then reports a small number while h* is large, so the heuristic error h* - h is large and the search degenerates towards uniform-cost behaviour — it expands a broad disc of nodes around the start before committing. A particularly vivid failure is the dead-end peninsula: nodes deep inside the peninsula have low h_SLD because they are geometrically close to a goal on the far shore, so the search is lured in and must exhaust the entire peninsula before backing out. The heuristic remains admissible throughout — it never lies upwards — it is simply uninformative. Remedies include using a different metric that matches the movement model (Manhattan or octile distance on grids where diagonal moves are forbidden or cost sqrt(2)), or precomputing landmark-based lower bounds (the ALT technique) that capture real connectivity rather than raw geometry.

Puzzle Heuristics: Misplaced Tiles and Manhattan Distance

The 8-puzzle — eight numbered tiles and one blank in a 3×3 frame — is the standard laboratory for heuristic design. Its state space contains 9!/2 = 181,440 reachable states, and the average optimal solution length is about 22 moves, so blind search is painful while informed search is easy. Two heuristics dominate the discussion.

h1, the misplaced-tile heuristic, counts the tiles that are not currently on their goal square. The blank is deliberately excluded: counting it would allow overestimation, since a single move that puts the last tile in place also, necessarily, relocates the blank, and counting both would charge two moves for one.

h2, the Manhattan distance (or city-block) heuristic, sums over all tiles the horizontal plus vertical grid separation between the tile's current square and its goal square:

h2(n) = sum over tiles t != blank of ( |row(t) - goalRow(t)| + |col(t) - goalCol(t)| )

The practical consequence is that a search guided by h2 prunes much more aggressively: nodes whose f value already exceeds the eventual solution cost are recognised as hopeless much earlier.

Why is each heuristic admissible? For h1: every move repositions exactly one tile, and every misplaced tile must be repositioned at least once before the puzzle is solved, so any solution contains at least as many moves as there are misplaced tiles. For h2: every move changes one tile's position by exactly one grid step, which alters that tile's Manhattan distance by at most 1. A tile currently d steps from home therefore needs at least d moves of its own, and since moves of different tiles are distinct moves, the total is at least the sum of the individual distances. Both arguments can also be read off directly from the relaxation construction described earlier, which is their real justification.

Both heuristics are also underestimates in a structural way: they ignore the interference between tiles. Only one tile can occupy a square, and tiles must be shuffled around the single blank, so real solutions almost always need more moves than Manhattan distance predicts. This observation leads to the well-known linear conflict enhancement: if two tiles are in their goal row, and their goal columns are in the opposite order to their current columns, one must move out of the row and back again, adding at least 2 moves beyond Manhattan distance. Adding 2 per such conflicting pair preserves admissibility and typically improves the estimate by a useful margin.

Crucially, h2(n) >= h1(n) for every state. The reason is immediate: a misplaced tile contributes exactly 1 to h1 and contributes its Manhattan distance — which is at least 1 — to h2; a correctly placed tile contributes 0 to both. Summing term by term gives the inequality. Equality holds only in the special case where every misplaced tile is exactly one step from home.

Comparing and Combining Heuristics

The comparison above generalises into the central concept of heuristic quality. We say h2 dominates h1 when both are admissible and h2(n) >= h1(n) for every node n. Dominance is a pointwise, universally-quantified condition: a heuristic that is larger on most states but smaller on a few does not dominate, and comparing two such heuristics requires empirical measurement rather than proof.

The practical importance of dominance is captured by the following result: if h2 dominates h1 and both are admissible, then A* using h2 expands no more nodes than A* using h1 (ignoring tie-breaking among nodes whose f value exactly equals the optimal cost). The reasoning rests on a fact about A* with an admissible heuristic: every node with f(n) < C*, where C* is the optimal solution cost, is certain to be expanded, and no node with f(n) > C* is ever expanded. Since h2 >= h1 implies f2(n) >= f1(n), any node that h2 forces into the "must expand" category is already in that category under h1, but not conversely. The stronger heuristic therefore prunes a superset of what the weaker one prunes. In short: bigger admissible values are always better, because they push more nodes above the C* cut-off while never pushing the true optimal path above it.

When several admissible heuristics are available and none dominates the others, they can be combined for free by taking the pointwise maximum:

h(n) = max( h_1(n), h_2(n), ..., h_k(n) )

This composite is itself admissible. The argument is one line: each h_i(n) <= h*(n), so the largest of them is also at most h*(n). If every component is consistent, the maximum is consistent too. And by construction the maximum dominates every component, so it expands no more nodes than any of them individually. Suppose, for instance, that a 15-puzzle solver has a Manhattan-plus-linear-conflict estimate and three separate pattern databases covering overlapping tile groups; evaluating all four and keeping the largest gives a heuristic strictly stronger than any single one. Note the contrast with the additive case: summing is only permitted when the components provably account for disjoint portions of the solution cost (as with disjoint pattern databases), whereas taking the maximum is always safe.

Maximisation is not free in time, however, and this brings us to the central engineering trade-off. The real objective is not "fewest nodes expanded" but "least total wall-clock time", which is roughly

total time  ~=  (nodes expanded) x (time to generate and evaluate one node)

A more accurate heuristic shrinks the first factor and inflates the second. Taking the maximum of four heuristics may halve the node count while quadrupling the per-node cost — a net loss. Manhattan distance costs a handful of additions per node and buys an order-of-magnitude reduction in expansions, which is why it is universally used; a heuristic that solved a near-complete relaxation by its own internal search might be nearly perfect yet so slow that plain Manhattan distance finishes first. Pattern databases sit at a favourable point on this curve precisely because their accuracy is purchased in an offline precomputation phase, leaving only an array lookup at run time; their cost shows up as memory rather than time. Useful practical tactics include computing cheap heuristics first and evaluating expensive ones only when the cheap value fails to prune, and updating Manhattan distance incrementally — when a tile moves one square, its contribution changes by exactly ±1, so a child's h can be derived from its parent's in constant time rather than recomputed from scratch.

Finally, it is illuminating to consider the two extremes of the heuristic spectrum.

  • h(n) = 0 for all n. This is trivially admissible and consistent — it never overestimates anything — but it carries no information. With f(n) = g(n) + 0 = g(n), A* degenerates exactly into uniform-cost search (Dijkstra's algorithm), expanding nodes in order of path cost and radiating uniformly outward from the start. It still finds optimal solutions; it simply pays the full exponential price.
  • h(n) = h*(n) for all n. The perfect oracle. At every step along an optimal path, f(n) = g(n) + h*(n) = C*, the optimal cost, while every node off an optimal path has f(n) > C*. With favourable tie-breaking, A* walks straight down an optimal path to the goal, expanding only the solution nodes themselves. The catch is that computing h* means solving the remaining subproblem optimally, which is as hard as the original problem — so the perfect heuristic is a theoretical reference point, not an implementation strategy.

Every real heuristic lives between these poles, and heuristic design is the craft of climbing from the h = 0 end towards the h = h* end while keeping evaluation cheap and admissibility intact. Relaxation tells you how to climb safely; dominance tells you whether you have actually climbed; maximisation lets you merge partial climbs; and the time-versus-accuracy trade-off tells you when to stop.

Admissibility and Consistency

1

Admissibility and Consistency

▶

A heuristic function h(n) is a piece of domain knowledge injected into a search algorithm: a guess at how much more it will cost to get from node n to a goal. Because it is only a guess, we need a precise way of saying when a guess is safe — that is, when the guarantees we care about (finding a least-cost solution, never having to redo work) still hold. Two properties do almost all of the work here. Admissibility is a global condition comparing the estimate to the true remaining cost. Consistency (also called monotonicity) is a local condition comparing the estimate at one node to the estimate at each of its successors. The two are closely related but not identical, and understanding exactly how they differ explains a great deal about why A* is implemented the way it is — why it keeps a closed list, why it sometimes has to reopen nodes, and why heuristics derived from relaxed problems are so prized.

Throughout, let g(n) be the cost of the path from the start node to n that the search currently holds, let h*(n) denote the true optimal cost of the cheapest path from n to any goal (with h*(n) = ∞ if no goal is reachable from n), let c(n, a, n′) be the cost of applying action a in node n to reach successor n′, and let C* be the cost of an optimal solution from the start. A* orders its frontier by f(n) = g(n) + h(n).

Admissibility: never overestimate

A heuristic h is admissible if for every node n in the state space

0 ≤ h(n) ≤ h*(n)

In words: the estimate is non-negative and never exceeds the actual cheapest remaining cost. Admissible heuristics are therefore optimistic — they may be too cheerful about how close the goal is, but never too gloomy. The condition must hold at every node, not merely at the start or on the nodes a particular run happens to visit; a single node where h(n) > h*(n) is enough to destroy admissibility.

One immediate corollary is that h(goal) = 0 for every goal node, because h*(goal) = 0 and h is non-negative and bounded above by it. This is easy to forget when designing a heuristic by formula: if your formula happens to return a small positive number at a goal state, the heuristic is inadmissible no matter how sensible it looks elsewhere.

The simplest admissible heuristic is the zero heuristic, h(n) = 0 for all n. Since h*(n) ≥ 0 always, the inequality holds trivially. But the zero heuristic carries no domain knowledge: it cannot distinguish a node adjacent to the goal from one on the far side of the map. With h = 0 we have f(n) = g(n), and A* degenerates exactly into uniform-cost search (Dijkstra's algorithm), expanding nodes in order of path cost outward from the start in all directions. This is the useful baseline: admissibility alone guarantees correctness, never efficiency. The practical design goal is to be as large as possible — as close to h* as possible — while remaining under the bound.

Why admissibility yields optimality (tree search). The argument is short and worth internalising. Suppose A* with an admissible h is about to select a suboptimal goal node G₂ from the frontier, with g(G₂) > C*. Since h(G₂) = 0, we have f(G₂) = g(G₂) > C*. Because the start node has been expanded and the optimal path has not yet been completed, some node n on an optimal path to the optimal goal must still be on the frontier. For that node, g(n) is the optimal cost to reach it (in tree search every path is kept separately, so the optimal-path node appears with its optimal g), and admissibility gives

f(n) = g(n) + h(n) ≤ g(n) + h*(n) = C* < f(G₂)

So n has a strictly smaller f-value and would have been chosen before G₂. Contradiction — therefore A* cannot return a suboptimal goal. Note that the goal test must be applied when a node is selected for expansion, not when it is generated; testing at generation time can return a goal found on the frontier before a cheaper path to it has surfaced.

What overestimation does. Consider this tiny graph, where h is admissible at every node except A:

S --1--> A --1--> G        h(S)=0, h(A)=5, h(G)=0
S --3--------------> G      h*(S)=2, h*(A)=1

A* expands S and generates two nodes: A with f = 1 + 5 = 6, and G via the direct edge with f = 3 + 0 = 3. The frontier's cheapest node is G, so A* expands it, finds a goal, and returns the path of cost 3 — even though the optimal solution S → A → G costs 2. The inflated estimate at A made the good route look expensive, and the algorithm never examined it. This is the generic failure mode: an overestimating heuristic can prune away the optimal path and let a more expensive goal be expanded first. (Note also that the returned solution is not arbitrarily bad: if h overestimates by at most ε, the solution returned is at most ε worse than optimal — the idea behind deliberately "weighted" or ε-admissible heuristics when speed matters more than exactness.)

Admissibility of the 8-puzzle heuristics. The two standard 8-puzzle heuristics are both admissible, and in both cases the reason is a counting argument about what a single move can accomplish. A legal move slides exactly one tile into the blank square, one position horizontally or vertically.

  • h₁ = number of misplaced tiles (not counting the blank). Each move changes the position of exactly one tile, so it can reduce the misplaced count by at most 1. Any solution must reduce the count to 0, so it needs at least h₁(n) moves: h₁(n) ≤ h*(n).
  • h₂ = Manhattan (city-block) distance, the sum over all tiles of the vertical plus horizontal distance from the tile's current square to its goal square. Each move changes one tile's Manhattan distance by exactly ±1, so one move reduces the total sum by at most 1. Since the sum must reach 0, at least h₂(n) moves are needed: h₂(n) ≤ h*(n).

Both are also instances of the general relaxation principle discussed below: h₁ is the exact solution cost when a tile may teleport to its goal square in one move; h₂ is the exact cost when a tile may move to any adjacent square regardless of whether it is blank. Because h₂(n) ≥ h₁(n) everywhere (a misplaced tile contributes at least 1 to the Manhattan sum), h₂ dominates h₁ and is the better heuristic: A* with h₂ never expands a node that A* with h₁ skips.

Consistency (monotonicity) and the triangle inequality

A heuristic h is consistent (or monotone) if for every node n, every action a, and the resulting successor n′,

h(n) ≤ c(n, a, n′) + h(n′)

and h(goal) = 0 for every goal node. Rearranged as h(n) − h(n′) ≤ c(n, a, n′), the condition reads: the heuristic may drop by at most the cost of the edge you traverse. You are not allowed to "earn" more estimated progress than you actually pay for. Equally, the estimate may rise by any amount when you move to a successor (that just means the move was a bad idea), so the condition is one-sided.

This is a form of the triangle inequality. Think of h(n) as a measured distance from n to the goal. The triangle with vertices n, n′ and the goal says that going from n to the goal directly must not cost more than going via n′. Consistency requires the heuristic's own estimates to obey that geometric common sense relative to the real edge costs of the graph.

The crucial practical difference from admissibility is how you check it. Admissibility is a global condition: it compares h(n) to h*(n), a quantity that is generally as hard to compute as solving the problem itself. Consistency is a local condition: it is verified edge by edge, looking only at a node, one successor, and one edge cost. That usually reduces to a short case analysis over the available action types, which is why consistency is often easier to prove than admissibility even though it is the stronger property.

Consistency of straight-line distance. In route-finding on a map, let h_SLD(n) be the Euclidean straight-line distance from n's location to the goal's location, and let road segments have cost equal to their true (road) length, which is at least the straight-line separation of their endpoints. For any road from n to n′:

h_SLD(n) = |n − goal|
         ≤ |n − n′| + |n′ − goal|       (Euclidean triangle inequality)
         ≤ c(n, a, n′) + h_SLD(n′)      (road length ≥ straight-line length)

In plain terms: the direct distance between two points is never longer than any detour through a third point, so straight-line distance can never shrink faster than you travel. Hence h_SLD is consistent, and also admissible since h_SLD(goal) = 0 and straight-line distance lower-bounds any actual route.

Consistency of the 8-puzzle heuristics. Again, a one-line case analysis. Every action has cost 1. Manhattan distance changes by exactly +1 or −1 per move (one tile moves one square), so h₂(n) − h₂(n′) ≤ 1 = c(n, a, n′). Misplaced tiles changes by −1, 0 or +1, so h₁(n) − h₁(n′) ≤ 1. Both are consistent. Notice how much easier these proofs were than the corresponding admissibility arguments — but they also deliver more.

The relationship between the two properties

Consistency implies admissibility. Suppose h is consistent and let n be any node from which a goal is reachable. Take an optimal path n = n₀ → n₁ → … → n_k = goal of total cost h*(n). Applying consistency along each edge and chaining:

h(n₀) ≤ c(n₀,n₁) + h(n₁)
      ≤ c(n₀,n₁) + c(n₁,n₂) + h(n₂)
      ≤ …
      ≤ c(n₀,n₁) + … + c(n_{k−1},n_k) + h(n_k)
      = h*(n) + h(goal) = h*(n)

(Formally this is an induction on the number of edges to the goal.) If no goal is reachable, h*(n) = ∞ and the bound is trivial. So every consistent heuristic is admissible — consistency is the strictly stronger property.

The converse fails. Admissible-but-inconsistent heuristics do exist. They are rare in practice and almost always arise from hand-tuning individual values, from lookups in a table built by an ad-hoc procedure, or from mixing several estimators without care. Here is a minimal example:

Edges:  S→A cost 1,  S→B cost 3,  A→B cost 1,  B→G cost 4
h:      h(S)=0, h(A)=4, h(B)=1, h(G)=0
True:   h*(S)=6, h*(A)=5, h*(B)=4, h*(G)=0   →  admissible everywhere
Check edge A→B:  h(A)=4  ≤  c(A,B) + h(B) = 1 + 1 = 2 ?   NO  →  inconsistent

The estimate plunges from 4 to 1 across an edge that costs only 1 — a drop of 3 that was not paid for.

Why inconsistency forces re-expansion. Trace A* graph search on that example, with a closed list that refuses to reopen nodes:

The inconsistent estimate at A made A look worse than B, so B was closed with a suboptimal g of 3; when the better route to B (g = 2) was discovered one step later, the closed list blocked the correction. The repairs are: (i) allow reopening — whenever a closed node is reached by a cheaper path, remove it from the closed list and push it back on the frontier with the new g; or (ii) apply pathmax, propagating h(n′) ← max(h(n′), h(n) − c(n, a, n′)) as nodes are generated, which repairs local inconsistencies on the fly. Reopening restores optimality but can cost extra expansions — in pathological cases exponentially many. This is precisely the overhead that consistency buys you out of.

The good news for practitioners: nearly every naturally occurring heuristic is consistent. Heuristics derived by relaxing the problem, by pattern-database lookup, by max-ing other consistent heuristics, or by metric distance (straight-line, Manhattan, Chebyshev, octile) are all consistent as a by-product of how they are constructed. You normally have to work at it to produce an inconsistent heuristic.

Monotonic f-values along a path

The name monotonicity comes from what consistency does to f. Let n′ be a successor of n on the path the search is following, so g(n′) = g(n) + c(n, a, n′). Then

f(n′) = g(n′) + h(n′)
      = g(n) + c(n, a, n′) + h(n′)
      ≥ g(n) + h(n)                  (by consistency)
      = f(n)

So f never decreases as you move deeper along any path. The f-value is a running estimate of the total cost of the complete solution through the current node, and consistency says that estimate can only improve (rise) as you learn more by going deeper — it never collapses on you.

Three consequences follow, and together they justify the standard implementation of A* graph search.

  • A* expands nodes in order of non-decreasing f-value. Since any successor's f is at least its parent's, no node can ever be generated with an f smaller than that of the node currently being expanded. The sequence of f-values of expanded nodes is therefore non-decreasing over the whole run.
  • When a node is selected for expansion, its optimal path has already been found — that is, g(n) = g*(n), the true cheapest cost from the start to n. Sketch: if a cheaper route to n existed, some node m on that route would still be on the frontier, and by the non-decreasing-f property that route's f-values are all bounded by g*(n) + h(n) < g(n) + h(n), so m would have been chosen first. Hence no cheaper route can still be hiding.
  • The closed list is safe without reopening. Because the first expansion of a node already carries its optimal g, any later path to that node is at best equally good and can be discarded outright. The familiar "if the successor is in the closed set, skip it" line is correct exactly when h is consistent; with a merely admissible h it is a bug.

It is worth being precise about what "no re-expansion" costs you if you lose it. With a consistent heuristic every node is expanded at most once, so the number of expansions is bounded by the number of distinct states with f(n) < C* (plus some tie-breaking at f = C*). With reopening under an inconsistent heuristic, a node may be expanded many times, and contrived graphs exist in which the number of re-expansions grows exponentially in the number of nodes.

Contours. A geometric way to see all of this is to draw the contours of equal f-value in the state space. Because f is non-decreasing along paths, the set of nodes with f(n) ≤ k forms a connected region containing the start, and these regions are nested: the region for k = 380 sits entirely inside the region for k = 400. A* sweeps outward through these bands in order, finishing one contour before starting the next, and it stops as soon as it expands a goal, having fully expanded every node strictly inside the contour f = C*.

The shape of the bands is what distinguishes one heuristic from another:

  • With h = 0, f = g and the contours are circles (in cost terms) centred on the start — A* expands blindly in every direction, which is uniform-cost search.
  • With an informative h, the contours are stretched and pulled toward the goal: nodes pointing away from the goal get a large h and fall outside the band, while nodes along a promising corridor stay inside. The search explores a narrow elongated ellipse rather than a disc.
  • In the limit h = h*, the contour for f = C* contains only the nodes of an optimal path, and A* walks straight to the goal with no wasted expansions.
  • If h₂ dominates h₁ (both admissible, h₂(n) ≥ h₁(n) everywhere), then every node with g + h₂ < C* also has g + h₁ < C*, so A* with h₂ expands a subset of the nodes A* with h₁ expands. Bigger (still-admissible) heuristics mean narrower bands and strictly less work.

This is why "as large as possible without exceeding h*" is the correct design objective, and why the effective branching factor of A* on the 8-puzzle falls sharply from h₁ (misplaced tiles) to h₂ (Manhattan) to pattern databases.

Verifying a candidate heuristic

Given a proposed h, you have four basic moves: prove admissibility via relaxation, prove consistency via edge-wise case analysis, refute either with a counterexample, or build the heuristic in a way that makes both properties automatic.

1. Proving admissibility by relaxation. A relaxed problem is the original problem with some restrictions on the actions removed. Every solution to the original problem is still a solution to the relaxed problem (the relaxed problem permits everything the original permits, and more), so the optimal relaxed cost can only be smaller:

h(n) = optimal cost of the relaxed problem from n  ≤  h*(n)

That single sentence is the whole proof of admissibility, which is why relaxation is such a productive design method. Worked examples:

  • 8-puzzle, misplaced tiles. Original rule: a tile may move to an adjacent square if that square is blank. Drop both conditions — a tile may move anywhere in one step. The optimal relaxed solution moves each misplaced tile once, costing h₁(n). Admissible.
  • 8-puzzle, Manhattan distance. Drop only the "must be blank" condition; a tile may move to any adjacent square, through other tiles. Tiles are now independent, and each needs exactly its Manhattan distance, so the relaxed optimum is h₂(n). Admissible.
  • Grid pathfinding, Manhattan distance with 4-way movement and unit costs. Relax by deleting all obstacles. The optimum on an empty grid is |Δx| + |Δy|. Admissible. (Careful: if diagonal moves of cost 1 are permitted, this relaxation argument breaks and the correct admissible heuristic is the Chebyshev distance max(|Δx|, |Δy|); for diagonals of cost √2 it is the octile distance. A heuristic is admissible only with respect to a specific action set and cost model.)
  • Route finding, straight-line distance. Relax by allowing travel off-road in a straight line between any two points. The optimum is |n − goal|. Admissible.

2. Proving consistency by edge-wise case analysis. Fix an arbitrary node n and an arbitrary legal action a with successor n′, and show

h(n) − h(n′) ≤ c(n, a, n′)

for every action type the domain offers. The work is usually small because there are few action types and each changes h in a bounded way. For grid pathfinding with 4-way unit-cost moves and Manhattan distance: any single move changes |Δx| + |Δy| by exactly ±1, and the edge costs 1, so the inequality holds with equality in the worst case. For the 8-puzzle with Manhattan distance: the moved tile's distance changes by ±1 and no other tile's distance changes, so the drop is at most 1 = the edge cost. For a weighted graph with a table-defined h, the "case analysis" is simply checking every edge in the table — tedious but finite.

3. Refuting with a counterexample. Both properties are universally quantified, so a single violating instance kills them.

  • To refute admissibility, exhibit one node n with h(n) > h*(n). Example: on a grid with 8-way movement at unit cost, Manhattan distance from (0,0) to (3,3) is 6, but the true cost is 3 diagonal moves — h = 6 > 3 = h*. Inadmissible. Another classic: a sliding-tile heuristic that adds a bonus term for "linear conflicts" counted twice can exceed h* on some configurations.
  • To refute consistency, exhibit one edge (n, a, n′) with h(n) > c(n, a, n′) + h(n′), as in the A→B edge of the earlier four-node graph. Note the asymmetry: a heuristic can be admissible everywhere and still fail this test on a single edge, so refuting consistency does not refute admissibility. Conversely, refuting admissibility at some node automatically refutes consistency (since consistency implies admissibility).

4. Let the construction do the work. Relaxation-derived heuristics are not merely admissible — they are also consistent, and for a structural reason. If h is the exact optimal cost of a relaxed problem whose action set includes the original actions at no greater cost, then h itself satisfies the triangle inequality in the relaxed space: moving from n to n′ in the real problem is one of the options available in the relaxed problem, so the relaxed optimum from n cannot exceed c(n, a, n′) plus the relaxed optimum from n′. That is exactly consistency. The same argument covers pattern databases, which store exact optimal costs for an abstracted (projected) version of the puzzle: because each real move maps to a move of cost ≤ 1 in the abstraction, the stored values obey the triangle inequality and the heuristic is consistent as well as admissible. Hence the practical advice: design heuristics by relaxation or abstraction, and you get both properties for free rather than having to argue for them.

Combining heuristics. Suppose you have several admissible heuristics h₁, h₂, …, h_m, none dominating the others. The safe combiner is the maximum:

h_max(n) = max( h₁(n), h₂(n), …, h_m(n) )
  • Admissibility is preserved. Each h_i(n) ≤ h*(n), so the largest of them is also ≤ h*(n).
  • Consistency is preserved. If every h_i is consistent, pick the index j achieving the max at n; then h_max(n) = h_j(n) ≤ c(n,a,n′) + h_j(n′) ≤ c(n,a,n′) + h_max(n′).
  • And it dominates. h_max ≥ h_i for every i, so the combination is at least as informative as any component — at the cost of evaluating all of them at each node.

Summation generally does not work. h₁ + h₂ can easily exceed h* because the two heuristics may be "charging" for the same moves. On the 8-puzzle, misplaced tiles plus Manhattan distance at a state one move from the goal gives 1 + 1 = 2 > 1 = h* — inadmissible. Summing is legitimate only when the components account for disjoint portions of the cost: this is the idea behind disjoint (additive) pattern databases, where each database counts only the moves of the tiles in its own pattern and no move is counted twice, so the sum remains a lower bound. Verifying that disjointness condition is the price of being allowed to add.

A checklist for a candidate h. (1) Is h(n) ≥ 0 everywhere and h(goal) = 0 at every goal state? (2) Can you describe a relaxed problem whose exact optimal cost is h? If yes, admissibility and consistency are both settled. (3) If not, enumerate the action types and check h(n) − h(n′) ≤ c(n, a, n′) for each. (4) If any check fails, hunt for an explicit counterexample rather than patching the formula blindly. (5) If h is admissible but you cannot establish consistency, either enable node reopening in your A* implementation or apply pathmax — and expect extra expansions.

A heuristic function h(n) is a guess about how much it will cost to get from node n to a goal. Two properties decide whether that guess is safe to use. A heuristic is admissible if it never overestimates: 0 <= h(n) <= h*(n), where h*(n) is the true optimal remaining cost. A heuristic is consistent (or monotonic) if it satisfies a triangle inequality on every edge: h(n) <= c(n, a, n') + h(n') for every successor n' of n, with h(goal) = 0.

These definitions matter because they are exactly what A* needs. Admissibility is what guarantees that tree-search A* returns an optimal solution; consistency is the stronger condition that also makes graph-search A* safe, because f-values never decrease along a path and a node is never re-expanded with a cheaper g. Every consistent heuristic is admissible, but the converse is false, so you should be able to produce or recognize a heuristic that is admissible yet inconsistent.

Greedy Best-First Search

▶

Greedy best-first search is the simplest informed search strategy that makes direct use of a heuristic function. It is best understood not as an isolated algorithm but as one setting of a dial inside a much more general machine: the best-first search framework. Once that framework is in place, uniform-cost search, greedy best-first search and A* all become the same control loop running with three different evaluation functions. Studying greedy search carefully is therefore valuable for two reasons. First, it shows what pure heuristic guidance can buy you — often a dramatic reduction in the number of nodes expanded. Second, and more importantly, it shows precisely what pure heuristic guidance cannot buy you: any guarantee at all about the quality of the solution returned. That failure is the motivation for the evaluation function used by A*.

Best-first search as a general framework. Best-first search maintains the frontier (the set of generated-but-not-yet-expanded nodes) as a priority queue ordered by increasing value of an evaluation function f(n). At each iteration the algorithm removes the node with the lowest f-value, tests it, and expands it, inserting each successor into the queue. Because the queue is ordered by f, the algorithm always works next on the node that currently looks most promising according to whatever notion of "promising" f encodes. The word best is therefore aspirational rather than factual: the node with the smallest f-value is the node that appears best given the information available, not the node that is genuinely best.

function BEST-FIRST-SEARCH(problem, f) returns a solution node or failure
    node   <- NODE(STATE = problem.INITIAL)
    frontier <- a priority queue ordered by f, containing node
    reached  <- a table mapping problem.INITIAL to node      // the explored/closed structure

    while frontier is not empty do
        node <- POP(frontier)                                // lowest f(n)
        if problem.IS-GOAL(node.STATE) then return node
        for each child in EXPAND(problem, node) do
            s <- child.STATE
            if s is not in reached then
                reached[s] <- child
                INSERT(frontier, child)
    return failure

Three features of this loop deserve attention. The priority queue supplies the ordering discipline; a binary heap gives O(log |frontier|) insertion and extraction. The explored (closed) set — here the reached table — converts tree search into graph search by refusing to regenerate states that have already been seen, which is what prevents the algorithm from wandering round cycles forever. And the evaluation function f is passed in as a parameter: it is the only problem-specific knowledge in the loop. This separation is the central design idea. The mechanism (queue, expansion, goal test, repeated-state handling) is fixed and reusable; the intelligence lives entirely in f.

Nothing in the pseudocode changes as you move down that table. You swap one line — the definition of f — and obtain a strategy with completely different completeness, optimality and complexity properties. This is why best-first search is taught as a framework: understanding the loop once means you understand all of its specialisations.

The greedy strategy: f(n) = h(n). Greedy best-first search sets f(n) = h(n), where h(n) is a heuristic estimate of the cheapest cost from the state at n to a goal. The accumulated cost g(n) of reaching n plays no role whatsoever in the ordering. The algorithm always expands the node that it believes is closest to a goal, in the hope that such a node lies on a short path to one. It is called greedy in exactly the sense used in greedy algorithms generally: it takes the locally most attractive option at every decision point and never revisits the question of whether the money already spent getting there was well spent.

Termination is normally by the late goal test: the search stops when a goal node is selected for expansion, i.e. popped from the frontier. Some presentations use an early goal test and stop as soon as a goal is generated as a successor. For greedy search this distinction matters very little, because a goal node has h = 0 and therefore sits at the very front of the queue the moment it is inserted; it will be popped on the next iteration anyway (barring other zero-h nodes). For A*, by contrast, the distinction is critical, because popping is what certifies optimality. The early test simply makes greedy search stop one iteration sooner.

The consequence of ignoring g is easy to state and easy to underestimate: a node that looks close to the goal is preferred even if it was reached by an absurdly expensive route. Suppose state X is reached by a 900 km detour but has h(X) = 10, while state Y is reached by a 5 km hop and has h(Y) = 60. Greedy search expands X first and will happily return a solution of cost around 910 in preference to one of total estimated cost 65. Because the ordering is driven purely by the forward estimate, greedy search behaves much like depth-first search with a compass: it plunges deeper and deeper along whichever branch keeps producing smaller h-values, backing up only when the current region stops looking good relative to everything else on the frontier.

Completeness and termination behaviour. In its tree-search form, with no record of visited states, greedy best-first search is not complete even in finite state spaces. The classic counterexample is travelling from Iasi to Fagaras in Romania. From Iasi, the heuristic favours Neamt, which is geographically nearer to Fagaras but is a dead end: its only successor is Iasi itself. Tree search has no memory of having been at Iasi, so it regenerates Iasi, whose best-looking successor is again Neamt, and the algorithm oscillates between two neighbouring cities forever, never considering the detour south through Vaslui that actually leads to the goal.

In its graph-search form, with an explored set (or a reached table as above), this cannot happen: Neamt's successor Iasi is already in reached and is discarded, Neamt's subtree is exhausted, and the search is forced to fall back on Vaslui. Since every expansion permanently removes a state from the pool of expandable states, and the pool is finite, the algorithm must eventually either find a goal or empty the frontier. Greedy best-first graph search is therefore complete in finite state spaces.

Infinite or unbounded state spaces restore the problem in a different guise. There, a repeated-state check does not help, because the algorithm need never repeat a state in order to fail: it can follow an infinite path of ever-new states whose heuristic values keep decreasing (or simply remain small) without ever reaching a goal. Consider searching an infinite grid for a goal to the west while the heuristic is miscalibrated so that easterly cells always look slightly better; the search marches east forever. The practical lessons are blunt: always use graph search with an explored set or a reached table; add a depth or expansion-count cut-off in unbounded spaces; and treat loop detection as a correctness requirement, not an optimisation.

Optimality: why greedy search fails. Greedy best-first search is not optimal, and no property of the heuristic can repair this. In particular, admissibility buys nothing. Admissibility (0 ≤ h(n) ≤ h*(n)) constrains the heuristic's relationship to the remaining cost, and consistency constrains how h changes along an edge, but neither constrains the relationship between h and the cost already incurred. Since g is precisely the quantity the greedy ordering discards, a property of h alone cannot control the total cost g + h of the path returned. The Romania trace above is a complete proof by counterexample: SLD is both admissible and consistent, and the answer is still 32 km worse than optimal.

The mechanism of failure is worth naming explicitly. A node whose heuristic value is low is attractive regardless of how it got there, so a low-h node sitting at the end of an expensive approach route acts as a lure. Conversely, the first few steps of the genuinely cheapest path may lead through nodes whose heuristic values are temporarily worse — Rimnicu Vilcea (193) looks worse than Fagaras (176) even though it is on the optimal route — and greedy search has no reason to look at them. Any strategy that wants optimality must be able to say "this branch looked good, but it has now cost so much that an alternative with a worse-looking estimate is more promising overall." That requires adding the accumulated cost back into the evaluation function, giving f(n) = g(n) + h(n): an estimate of the total cost of the whole solution through n, rather than of one half of it. That is exactly A*.

Time and space complexity. Let b be the branching factor and m the maximum depth of the search space. In the worst case — an uninformative, misleading or constant heuristic — greedy best-first search degenerates into something close to an unguided exploration of the whole space and runs in O(b^m) time. Space is also O(b^m), because every generated node is retained: unexpanded nodes sit in the priority queue, and expanded nodes sit in the explored set so that repeated states can be detected. Exponential memory growth is usually the binding constraint in practice. A machine can often keep computing for hours, but a frontier that doubles every few seconds exhausts RAM in minutes, so greedy search typically dies of memory exhaustion rather than impatience.

The worst case, however, is rarely the typical case. The whole point of the heuristic is to prune, and a good heuristic prunes hard. In the extreme, a perfect heuristic (h = h*) with no ties makes greedy search expand only the nodes on an optimal path, giving O(bd) generated nodes for a solution at depth d — essentially linear in the solution depth. Realistic heuristics sit between these poles, and performance degrades gracefully but genuinely as the heuristic's error grows. A useful mental model is that the search explores a "beam" around the heuristic's preferred direction whose width grows with the heuristic's inaccuracy.

One more cost is easy to forget: the priority queue itself. Each insertion and each extract-min on a binary heap costs O(log N) where N is the current frontier size, so the per-node overhead carries a logarithmic factor on top of the cost of generating successors and evaluating h. When h is cheap (a subtraction and an absolute value, as in Manhattan distance) this overhead is visible in profiling; when h is expensive (a pattern-database lookup or a sub-search), it is negligible. Duplicate detection via a hash table adds expected O(1) per generated node plus the memory for the table.

Failure modes caused by misleading heuristics. Greedy search's behaviour is entirely dictated by the shape of the heuristic landscape, so it inherits all of that landscape's pathologies.

  • Local minima in h. A local minimum is a state whose successors all have higher h-values than itself. Greedy search entering such a region must expand every node in the basin whose h-value is below the value of the "escape" nodes before it will consider leaving. In a large basin this means exhaustive, essentially blind exploration of a region that contains no solution.
  • Plateaux. A plateau is a connected region in which many states share the same h-value. Since the priority queue cannot distinguish them, tie-breaking (often insertion order) decides the expansion sequence, and the search degenerates to an uninformed sweep across the plateau. Integer-valued heuristics on grid maps produce plateaux constantly, which is why practical implementations break ties deliberately — for example, preferring the most recently generated node, or preferring lower g — rather than leaving the order to chance.
  • Obstacles invisible to h. Straight-line distance on a grid or road map knows nothing about walls, rivers, one-way streets or impassable terrain. A heuristic that measures "as the crow flies" will happily lead the search into the mouth of a U-shaped wall, because every step into the concavity reduces h. The search must then fill the entire pocket before it is willing to back out and go around. This is the single most commonly observed failure of greedy search in game and robotics pathfinding.
  • Attraction to unreachable or distant regions. Nodes can have small h-values and yet be very far from any goal along feasible paths; h measures geometry while the real cost measures connectivity. A state on the wrong side of a wall, a room with one long corridor to it, or a puzzle configuration two tiles from solved but requiring a long cyclic manoeuvre, all look cheap and all consume expansions.
  • No cheap recovery. Because g is invisible, greedy search has no notion of "this branch is becoming expensive." It abandons a region only when every node in it is numerically worse than something else on the frontier, and even then it keeps all of the sunk work in memory. There is no backtracking policy, no cost-based cut-off, and no mechanism analogous to A*'s automatic re-focusing when g grows.

A concrete grid example makes the pattern vivid. Consider a 20×20 grid with the start at the left, the goal at the right, and a long vertical wall between them containing a single gap at the extreme top. With Manhattan or Euclidean distance to the goal as h, every eastward step reduces h, so greedy search drives straight at the wall, then fans out along it expanding cells in order of their distance to the goal — which means it explores the cells nearest the wall first, including the whole dead region in front of it, before drifting to the gap. The pathology is not that it fails (it will find the gap eventually) but that it expands a large, wholly useless region, and that the path it finally returns may hug the wall in an awkward, far-from-optimal way.

When greedy best-first search is appropriate. None of the above makes greedy search useless; it makes it a tool with a specific profile. It is the right choice when finding something quickly matters more than finding the best thing.

  • Very large spaces where any feasible solution is acceptable. In planning, configuration, or constraint-style problems with huge branching factors, an optimal solution may be computationally out of reach while a workable one is not. Greedy search — and its descendants, such as the enforced-hill-climbing and greedy best-first modes of modern planners like FF and Fast Downward — routinely solve instances on which A* exhausts memory.
  • As a fast first pass. A greedy solution can serve as an initial incumbent whose cost bounds later search (branch-and-bound, anytime weighted A*, or ARA*), or it can be locally repaired by smoothing and shortcutting. "Get a path now, improve it while the agent is already moving" is standard practice in robotics and games.
  • When the heuristic is known to be accurate. If h correlates strongly with true remaining cost and the domain is free of large local minima and obstacle-induced traps — open terrain, well-behaved metric spaces, smooth cost landscapes — greedy search expands dramatically fewer nodes than uniform-cost search and returns solutions only slightly worse than optimal.
  • As a tunable extreme. Weighted A* with f = g + w·h interpolates between A* (w = 1) and greedy search (w → ∞). Knowing how the greedy endpoint behaves is what lets you reason about intermediate weights, which typically give bounded-suboptimal solutions (cost at most w times optimal) with large speed-ups.
  • When not to use it. Avoid greedy search whenever the cost of the returned solution has real consequences — fuel, money, distance travelled by a physical vehicle, machine time, safety margins — or whenever a guarantee must be given to a user or a regulator. In those settings the extra expansions bought by f = g + h are the price of correctness, and they are usually worth paying.

Best-first search is a general framework rather than a single algorithm: it keeps a priority queue (the open list) of frontier nodes and always expands the node that looks most promising according to an evaluation function f(n). Different choices of f give different algorithms — uniform-cost search uses f(n) = g(n), A* uses f(n) = g(n) + h(n), and greedy best-first search uses f(n) = h(n), the heuristic estimate of the remaining cost to a goal, ignoring the cost already paid to reach n.

That single design choice explains everything about greedy search's behaviour. Because it only looks forward, it often dives quickly toward the goal and expands far fewer nodes than uninformed search, which is why it is attractive in practice. But it is not optimal: a shallow-looking but expensive route can win over a cheaper one, and with repeated-state checking it is complete only on finite graphs, while in the worst case it degenerates to the exponential time and space of breadth-first style search because the whole frontier must be stored.

Optimality and Completeness Proofs for A*

▶

Two guarantees separate A* from the merely plausible best-first searches: it is complete (it will find a solution whenever one exists) and it is optimal (the solution it returns is a cheapest one). Neither guarantee is automatic — each depends on precise conditions on the heuristic function and on the bookkeeping of the search algorithm. The key quantities are g(n), the cost of the path by which the search reached node n; h(n), the heuristic estimate of the remaining cost from n to the nearest goal; f(n) = g(n) + h(n), the estimated cost of a complete solution through n; h*(n), the true optimal cost from n to a goal; and C*, the cost of an optimal solution from the start state. A heuristic is admissible when 0 ≤ h(n) ≤ h*(n) for every node, so f(n) never overestimates the cost of the best solution through n. The proofs below show exactly how this one inequality propagates into global guarantees about what A* returns, and why a stronger property — consistency — is needed as soon as we add a closed list.

Tree-search A* is optimal with an admissible heuristic. Tree-search A* keeps no record of visited states; it simply expands the frontier node of lowest f, and it applies the goal test when a node is selected for expansion, not when it is generated. The claim is that under admissibility, the first goal node selected for expansion is an optimal one. The proof is by contradiction. Suppose A* is about to expand a goal node G2 whose path cost is g(G2) = C2 > C*, that is, a suboptimal goal. Because G2 is a goal, h(G2) = 0, so

f(G2) = g(G2) + h(G2) = g(G2) = C2 > C*

Now consider an optimal path from the start state to an optimal goal G, with total cost C*. At any moment before the search terminates, at least one node on that path has been generated but not yet expanded — call it n; it sits on the frontier. (This is true because the start node itself lies on the optimal path: before anything is expanded, the start node is an unexpanded node of the path, and whenever a path node is expanded its successor on the path is generated and joins the frontier.) Since tree search keeps the whole path, g(n) equals the true cost of reaching n along the optimal path, so g(n) + h*(n) = C*. Admissibility gives h(n) ≤ h*(n), hence

f(n) = g(n) + h(n) ≤ g(n) + h*(n) = C* < C2 = f(G2)

So f(n) < f(G2), and a best-first queue ordered on f must select n before G2. This contradicts the assumption that G2 was about to be expanded. Since the argument applies at every step, no suboptimal goal is ever expanded, and the first goal expanded has cost C*. (With ties at f = C*, A* may expand an optimal goal while other f = C* nodes remain; that is harmless, since all of them represent solutions of cost C* or worse.)

The clause about when the goal test is applied is not a technicality — it is where the proof lives. If a goal node were returned the moment it was generated, A* could return G2 while the cheaper node n was still waiting on the frontier with a smaller f. Consider this small graph, where S is the start and both G and G2 are goals:

Consistency and the monotonicity of f. A heuristic is consistent (or monotone) if, for every node n, every action a, and the successor n' it produces,

h(n) ≤ c(n, a, n') + h(n')

This is a triangle inequality: the estimate at n may not exceed the cost of one real step plus the estimate from where that step lands. Consistency immediately yields monotonic f-values along any path. If n' is a successor of n, then g(n') = g(n) + c(n, a, n'), so

f(n') = g(n') + h(n')
      = g(n) + c(n, a, n') + h(n')
      ≥ g(n) + h(n)                   (by consistency)
      = f(n)

Hence f is non-decreasing along every path in the search tree, which is why consistent heuristics are also called monotone. Intuitively, the estimate of total solution cost can only become more pessimistic (or stay the same) as real cost is paid and uncertainty is removed.

Every consistent heuristic is admissible. Prove it by induction on the number of steps k in an optimal path from n to a goal. For k = 0, n is a goal, and consistency with h(goal) = 0 plus non-negativity gives h(n) = 0 = h*(n). For the inductive step, let n' be the first node on an optimal k-step path from n; then h*(n) = c(n, a, n') + h*(n'), and by consistency and the induction hypothesis h(n) ≤ c(n, a, n') + h(n') ≤ c(n, a, n') + h*(n') = h*(n). So consistency is strictly stronger than admissibility.

The converse fails. Take the graph used later for the graph-search counterexample, with h(X) = 6 and h(M) = 0 on an edge X → M of cost 1. Both values are admissible (they equal or underestimate the true distances), yet h(X) = 6 > 1 + 0 = c(X, a, M) + h(M), so h is inconsistent. In practice, inconsistent admissible heuristics are rare: they usually arise only when heuristics are combined carelessly, learned from data, or deliberately constructed. Most heuristics in common use are consistent:

  • Straight-line distance on a map: for any road from n to n' of length c, the Euclidean triangle inequality gives SLD(n, goal) ≤ c + SLD(n', goal) whenever road length is at least Euclidean length.
  • Manhattan distance on the 8-puzzle: a single move changes the Manhattan sum by exactly +1 or −1, and the step cost is 1, so h(n) ≤ 1 + h(n') always holds.
  • Misplaced tiles: one move changes the count by at most 1, again satisfying the inequality.
  • Maximum of consistent heuristics: if h1 and h2 are consistent, so is max(h1, h2).

The practical payoff of consistency is a structural fact: whenever A* selects a node for expansion, it has already found an optimal path to that node's state. Suppose not — suppose n is expanded with g(n) greater than the optimal cost g*(n). Then some node m on a cheapest path to that state is still on the frontier with g(m) = g*(m), and by consistency f(m) ≤ g*(n) + h(n) < g(n) + h(n) = f(n), so m would have been chosen first. Therefore closing a node is safe: nothing better will come along later.

Graph-search A* is optimal with a consistent heuristic. Graph search adds a closed list (explored set) and discards any newly generated node whose state is already closed, which is essential for finite-memory search of graphs with many repeated states (grids, sliding-tile puzzles, route networks). The proof of optimality now rests on monotonicity. Because f never decreases along a path, and because A* always pops the smallest f on the frontier, the sequence of f-values of expanded nodes is non-decreasing: A* expands nodes in non-decreasing order of f. Two consequences follow:

  • Every node with f(n) < C* is expanded before any node with f = C*, and a goal node G has f(G) = g(G). A suboptimal goal has f > C* and therefore cannot be the first goal expanded, since a node on the optimal path with f ≤ C* is always available. The first goal expanded has f = C*.
  • By the "optimal path on first expansion" property above, a state is closed only once an optimal path to it has been found. Discarding later duplicates therefore loses no optimal solution, and the closed list is pure savings.

Without consistency, the second bullet collapses, and graph-search A* can return a suboptimal answer. Consider start S, intermediate states X and M, and goal G, with edges S→X = 1, X→M = 1, S→M = 3, M→G = 5. True costs are h*(S) = 7, h*(X) = 6, h*(M) = 5, and C* = 7 via S→X→M→G. Take the admissible but inconsistent heuristic h(S) = 0, h(X) = 6, h(M) = 0, h(G) = 0.

There are two standard repairs when a heuristic cannot be made consistent: (i) manage the closed list specially by reopening a closed node whenever a strictly cheaper path to it is discovered (A* with node re-expansion), which restores optimality at the price of possible extra expansions; or (ii) locally repair the heuristic with the pathmax rule h(n') ← max(h(n'), h(n) − c(n, a, n')), which enforces monotonicity of f along the generated paths. The first remedy is the one normally implemented; the general lesson is that admissibility buys optimality for tree search, consistency buys optimality for graph search.

Completeness of A*. Optimality says that if A* returns something, it is a cheapest solution; completeness says it will return something whenever a solution exists. The argument is a counting argument built on the f-ordering. Since A* never expands a goal before exhausting cheaper options, it expands all nodes with f(n) < C* before expanding any goal node. So the question becomes: can that set be infinite, or can A* get stuck inside it forever? Two conditions rule this out:

  • Positive step costs bounded away from zero: every action costs at least some ε > 0. Then a node at depth d has g ≥ dε, and since h ≥ 0, f ≥ dε. Any node with f < C* therefore lies at depth less than C*/ε — a finite bound.
  • Finite branching factor b: there are at most b^d nodes at depth d, so at most O(b^{C*/ε}) nodes can have f < C*. Finitely many, however astronomically many.

A* expands a new node at each iteration and never revisits an expanded node in graph search (and, in tree search, cannot cycle indefinitely below f = C* because of the depth bound). Having exhausted the finite set {n : f(n) < C*}, it must next select a node with f = C*, and an optimal goal is always among the candidates, so a goal is reached in finite time. Both conditions are necessary. If step costs can shrink geometrically — say costs 1/2, 1/4, 1/8, … along an infinite branch — infinitely many nodes can have f < C* and A* will never escape that branch; this is the same pathology that makes uniform-cost search incomplete without a positive cost bound. If the branching factor is infinite (a continuous action space, say), a single expansion never terminates. When no solution exists, behaviour depends on the space: in a finite graph with a closed list, A* exhausts the frontier and reports failure in finite time; in an infinite space it may run forever, exactly like breadth-first or uniform-cost search, since no finite amount of expansion can prove the absence of a goal.

Contours of equal f-cost. Monotonic f gives a vivid geometric picture of A*'s behaviour. Draw, in the state space, the set of states with f(n) ≤ Ci for increasing values C1 < C2 < …. These nested regions are called contours, by analogy with contour lines on a map. Because expansion proceeds in non-decreasing order of f, A* fans out contour by contour: every node inside the contour f = Ci is expanded before any node outside it. The shape of these contours is controlled entirely by the heuristic:

  • With h = 0, A* degenerates into uniform-cost search. The contours are the sets g(n) ≤ Ci: circular bands expanding equally in all directions from the start, utterly indifferent to where the goal lies.
  • With a weak but non-trivial h, the contours are still broad but are pulled slightly toward the goal; the search is an ellipse-like blob with the start and goal roughly at the foci.
  • With an accurate h, the contours elongate dramatically along the start–goal axis and become narrow; few nodes lie between successive contours, so few nodes are expanded.
  • With a perfect heuristic, h = h*, every node on an optimal path satisfies f(n) = g(n) + h*(n) = C*, while every node off an optimal path has f > C*. The contour f = C* hugs the optimal path itself and A* walks essentially straight to the goal, expanding only optimal-path nodes (plus whatever ties the tie-breaking rule admits).

On an obstacle-free grid with unit moves, this is easy to visualise. Dijkstra's algorithm (h = 0) expands a diamond centred on the start whose radius grows until it swallows the goal; A* with Manhattan distance expands, in the ideal case, only the rectangle spanned by start and goal, because all shortest monotone paths have f = C* while any step away from the goal immediately raises f by 2. The contour picture also explains two practical facts: adding a tie-breaking rule that prefers larger g (equivalently smaller h) among equal f drives the search to the far edge of the f = C* contour and finds the goal sooner; and all the nodes strictly inside f < C* are unavoidable, so the only room for improvement lies in how much of the f = C* band gets expanded.

Optimal efficiency of A*. A* is not merely optimal in the cost of the solution it returns; with a consistent heuristic it is optimally efficient among all optimal algorithms that use the same heuristic information and expand nodes from the same start state. The argument runs as follows. Suppose some algorithm A fails to expand a node n with f(n) = g(n) + h(n) < C*, yet claims an optimal solution. The information available to A about the region below n consists only of h(n). There exists another problem instance, identical in everything A has actually examined and still consistent with the heuristic values it has seen, in which the subtree under n contains a goal at true remaining cost exactly h(n) — giving a solution of cost f(n) < C*. On that instance, A would miss the optimal solution. Hence any algorithm guaranteed to be optimal must expand every node with f(n) < C*. A* expands precisely that set, plus some subset of the f = C* band (which subset depends on tie-breaking and on where the goal happens to be found). Therefore no competing algorithm with the same heuristic can be guaranteed to expand strictly fewer nodes.

Three caveats keep this result honest. First, it is a statement about node expansions, not about running time per expansion: priority-queue operations, duplicate detection and heuristic evaluation all cost something, and an algorithm expanding slightly more nodes far more cheaply may well be faster in wall-clock terms. Second, it says nothing about memory. A* must keep the frontier and (in graph search) the closed list, so its space requirement is proportional to the number of nodes it stores, which is typically exponential. In practice A* exhausts RAM long before it exhausts patience: on a machine generating a million nodes per second, gigabytes vanish in minutes. Memory, not time, is A*'s binding constraint. Third, the guarantee is "no algorithm is guaranteed to do better", not "no algorithm ever does better": a lucky heuristic-blind algorithm may stumble onto the goal early on a particular instance.

Heuristic error and the number of nodes expanded. How much work A* does is governed by how close h is to h*. Two ways of measuring the gap give very different answers:

  • Relative error, ε = (h* − h)/h*. If the relative error is a positive constant — the heuristic is, say, always within 90% of the truth — the number of nodes expanded still grows exponentially in the solution depth d, roughly as O(b^{εd}) in a tree-shaped space with unit costs. A constant fraction of error accumulated over d levels is an absolute error proportional to d, and each unit of absolute error multiplies the contour's width.
  • Absolute error, |h*(n) − h(n)|. Sub-exponential node growth requires the absolute error to grow no faster than the logarithm of the true path cost: |h*(n) − h(n)| = O(log h*(n)). Virtually no heuristic for a real combinatorial problem satisfies this. The honest conclusion is that A* with a realistic heuristic still faces exponential growth; a good heuristic shrinks the base of the exponent, which is enormously valuable but is not a change of complexity class.

Comparing two heuristics is therefore a matter of how far each pushes the exponent down, and here dominance gives a clean theorem. If h1 and h2 are both admissible and h2(n) ≥ h1(n) for every node n, we say h2 dominates h1, and A* using h2 never expands more nodes than A* using h1 (up to tie-breaking at f = C*). The proof is one line of contour reasoning: every node A* expands has f < C* or f = C*; if g(n) + h2(n) < C* then g(n) + h1(n) ≤ g(n) + h2(n) < C*, so every node necessarily expanded under h2 is also necessarily expanded under h1, but not conversely. The moral is to use the largest admissible estimate available — for instance max(h1, h2) of two admissible heuristics, which dominates both and remains admissible (and consistent if both are consistent). On the 8-puzzle, Manhattan distance h2 dominates misplaced tiles h1, since each misplaced tile needs at least one move and usually more.

The standard practical yardstick is the effective branching factor b*: if A* expands N nodes and the solution found is at depth d, then b* is the branching factor a uniform tree of depth d would need in order to contain N + 1 nodes:

N + 1 = 1 + b* + (b*)² + … + (b*)^d

b* is remarkably stable across problem instances for a given heuristic, which makes it a reliable basis for comparison; a well-designed heuristic drives b* close to 1, meaning the search barely branches at all. This topic asks a sharper question than "how does A* work?" It asks "why can we trust it?" The answer comes in two proofs. First, with an admissible heuristic (one that never overestimates the true remaining cost), tree-search A* returns an optimal solution: a suboptimal goal sitting on the frontier has f equal to its full, inflated path cost, while some node on an optimal path always has f no greater than the optimal cost, so the suboptimal goal can never be selected first. Second, with a consistent heuristic (h(n) <= c(n,a,n') + h(n')), f never decreases along a path — the monotonicity property — which guarantees that the first time A* expands a node it has already found the cheapest path to it. That is exactly the condition graph-search A* needs, because graph search discards later rediscoveries of a state.

The proofs also give you a geometric picture. Because f is nondecreasing, A* expands nodes in bands, or contours, of increasing f-cost, much like ripples spreading from the start state; a perfect heuristic collapses the contours onto the optimal path, while h = 0 makes them circular and A* degenerates into uniform-cost search. Completeness follows from the same machinery given a finite branching factor and positive step costs bounded away from zero, since only finitely many nodes can have f below the optimal cost. Optimal efficiency says no other algorithm using the same heuristic information can expand fewer nodes (up to tie-breaking), and heuristic error analysis explains why the node count still grows quickly when h is merely good rather than perfect.

Designing and Comparing Heuristics

1

Designing and Comparing Heuristics

▶

Once you know how to run A* and how to check admissibility and consistency, the interesting engineering question becomes: where do good heuristics come from, and how do you tell which of two candidates is actually better? Two admissible heuristics can both be "correct" in the sense that neither overestimates, yet one may let A* solve a 15-puzzle in a fraction of a second while the other grinds for hours. This topic develops the theory and the practical methodology for that comparison: the partial order of dominance, the summary statistic of the effective branching factor, three systematic generators of heuristics (relaxed problems, pattern databases, subproblem decomposition), the rules for combining several heuristics into one, and a disciplined experimental protocol for comparing them on sliding-tile and grid-pathfinding benchmarks.

Heuristic dominance and why it matters

Let h1 and h2 both be admissible heuristics for the same problem. We say that h2 dominates h1 when

h2(n) >= h1(n)   for every node n in the state space

Dominance is a pointwise condition: it is not enough for h2 to be larger on average or on the instances you happened to test. A single node where h2(n) < h1(n) breaks the relation, and the two heuristics become incomparable (each may win on different instances). Because both heuristics are bounded above by the true remaining cost h*(n), dominance says that h2 sits closer to h* everywhere: it is uniformly better informed.

The classic example is the 8-puzzle. Let h1 = number of misplaced tiles (blank excluded) and h2 = sum over tiles of the Manhattan distance from each tile's current square to its goal square. Every misplaced tile contributes at least 1 to the Manhattan sum, and tiles that are correctly placed contribute 0 to both, so h2(n) >= h1(n) for all states n. Concretely, for the state

7 2 4            1 2 3
5 _ 6    goal:   4 5 6
8 3 1            7 8 _

h1 = 8 (every tile is out of place) while h2 = 3+1+2+2+2+3+3+2 = 18. The true optimal cost is 26, so Manhattan distance recovers far more of the remaining work.

Why does a larger admissible value translate into less search? Recall the central fact about A* with an admissible heuristic: let C* be the optimal solution cost. A* must expand every node whose f(n) = g(n) + h(n) < C* (such a node might lie on a cheaper solution and cannot be ruled out), it may expand some nodes with f(n) = C* depending on tie-breaking, and it never expands a node with f(n) > C*. Now consider a node n that h1 forces A* to expand, i.e. g(n) + h1(n) < C*. If h2 dominates h1, then either g(n) + h2(n) < C* as well (A* with h2 may also expand it) or g(n) + h2(n) >= C*, in which case h2 prunes it. The set of nodes surely expanded under h2 is therefore a subset of the set surely expanded under h1. Up to the nodes with f = C* that tie-breaking decides, A* with a dominating heuristic never expands more nodes than A* with the dominated one. Larger admissible values push more of the frontier above the C* cut-off, and everything above that cut-off is pruned for free.

Two cautions keep this result from being a licence to inflate heuristic values.

  • Dominance presupposes admissibility on both sides. If you simply multiply Manhattan distance by 3, you get bigger numbers and a much smaller search tree — and solutions that can be badly suboptimal, because the proof above relied on h <= h* to guarantee that pruned nodes really cannot lie on an optimal path. An inadmissible "dominating" heuristic trades correctness for speed; that may be an acceptable trade, but it is a different trade, and it must be declared explicitly (for example as weighted A* with a bounded-suboptimality guarantee).
  • Accuracy costs cycles. Misplaced tiles costs a handful of comparisons per node; Manhattan distance costs a table lookup and addition per tile; a pattern-database heuristic costs an index computation plus a memory probe that may miss cache; a heuristic computed by solving a relaxed problem with its own search can cost milliseconds. The quantity you care about is (nodes expanded) × (cost per node), not nodes alone. A heuristic that halves node expansions but triples per-node cost is a net loss. Always report wall-clock time next to node counts.

There is also a diminishing-returns effect worth noting: incremental heuristics applied at the top of the tree save little, because near the root g is small and almost everything has f < C* anyway. The savings come from pruning the exponentially wide layers deep in the tree.

Measuring heuristic quality: the effective branching factor

"Nodes expanded" is instance-specific and scales wildly with depth, which makes raw counts awkward to compare across problems. The effective branching factor b* normalises them. Suppose A* expands N nodes while finding a solution at depth d. Define b* as the branching factor that a uniform tree of depth d would need in order to contain N + 1 nodes (the +1 counts the root):

N + 1 = 1 + b* + (b*)^2 + ... + (b*)^d

The equation has a unique positive root greater than 1 (for N > d), found numerically by bisection or Newton's method. Worked example: if A* expands N = 24 nodes to reach a goal at depth d = 4, we need 1 + b + b² + b³ + b⁴ = 25. Trying b = 1.85 gives 24.3; b = 1.90 gives 26.4; b = 1.86 gives ≈24.6. So b* ≈ 1.87. Interpreting it: a b* close to 1 means the search was nearly a straight walk down to the goal — a highly informed heuristic; a b* close to the problem's real branching factor (about 2.8 for the 8-puzzle counting repeated states, 4 for a 4-connected grid) means the heuristic is providing almost no guidance and A* is degenerating towards uniform-cost search.

A pleasant empirical property is that b* is reasonably stable across instances and across depths for a given heuristic and problem family, which is exactly what you want from a summary statistic: you can estimate it from a modest sample of randomly generated problems and use it to predict costs at depths you cannot afford to run.   • Relative error: ε = (h*(n) − h(n)) / h*(n), a scale-free version in [0, 1]. Theoretical analyses relate the number of nodes A* expands to roughly b^(ε·d), which explains why small reductions in relative error buy exponential reductions in search.

The practical rule: always report nodes expanded, nodes generated, b*, and wall-clock time together. Nodes and b* measure informedness; time captures the per-node price you paid for it. A pattern database may show b* = 1.05 and still lose on time if the database does not fit in memory and every probe is a page fault.

Generating heuristics from relaxed problems

The most reliable way to invent an admissible heuristic is not to invent it at all, but to derive it. A relaxed problem is the original problem with some restrictions on the actions removed. Because every action of the original problem is still legal in the relaxation (and more besides), every solution to the original is also a solution to the relaxation. In graph terms, relaxation adds edges to the state space: the original graph is a subgraph of the relaxed graph. Adding edges can only shorten shortest paths, so

h_relaxed(n) = optimal cost from n to goal in the relaxed problem
            <= optimal cost from n to goal in the original problem = h*(n)

which is exactly admissibility, and it holds by construction — no case analysis required. Better still, such a heuristic is automatically consistent. Let n' be a successor of n via an action of cost c(n, a, n'). That action also exists in the relaxed problem, so an optimal relaxed solution from n can be obtained by (at worst) taking that action and then solving optimally from n'. Hence h_relaxed(n) <= c(n, a, n') + h_relaxed(n'), the triangle inequality, which is the definition of consistency. So A* with a relaxed-problem heuristic keeps its graph-search optimality guarantee without needing to re-open closed nodes.

The 8-puzzle makes the technique vivid. Write the legal-move rule formally:

A tile may move from square A to square B
    if  (1) A is horizontally or vertically adjacent to B
    and (2) B is blank.

Now delete conditions and read off the heuristics:

  • Delete (2) only — "a tile may move to any adjacent square, blank or not". Each tile can now walk independently to its goal square, so the optimal relaxed cost is the sum of the individual walking distances: Manhattan distance. Computable in O(number of tiles) with no search.
  • Delete (1) and (2) — "a tile may move anywhere, any time". Each misplaced tile needs exactly one move, so the relaxed optimum is the misplaced-tiles count. Even cheaper to compute, but much weaker.
  • Delete (1) only — "a tile may move into the blank square from anywhere" (adjacency dropped, but the destination must still be blank). The relaxed problem is a swap puzzle: repeatedly swap the blank with some tile. Its optimal solution cost — computable by a simple greedy loop (if the blank is on a square whose goal tile is not there, swap in that tile; otherwise swap in any misplaced tile) — is Gaschnig's heuristic. It is bounded below by misplaced tiles and is incomparable with Manhattan distance, so the two can usefully be combined with max.

These three illustrate the essential constraint on the method: the relaxed problem must be solvable cheaply, ideally in closed form or by a trivial greedy procedure, with no search. If evaluating h requires running a search of its own, the heuristic may cost more than it saves — you have merely moved the exponential blow-up from the outer search to the inner one. (The classic exception is when the inner search results are precomputed once and cached, which is exactly the pattern-database idea below.) Automatic systems such as ABSOLVER have generated heuristics by mechanically relaxing problem descriptions written in a formal action language, discovering, among others, a then-novel heuristic for Rubik's Cube.

Grid pathfinding is relaxed the same way: delete the constraint "the destination cell must not be a wall". Shortest paths in the obstacle-free grid are then available in closed form, and which formula you use depends on the movement model:

Pattern databases and subproblem decomposition

Relaxation weakens the rules; subproblem decomposition weakens the goal. Instead of asking "how many moves to solve the whole puzzle?", ask "how many moves to get tiles 1, 2, 3 and 4 into place, ignoring where every other tile ends up?" Any solution to the full puzzle also solves that subproblem, so the subproblem's optimal cost is a lower bound on the full cost — admissible, for exactly the same structural reason as before.

A pattern is the abstracted state that results: the positions of the pattern tiles (say 1–4) plus the blank are recorded exactly, and every other tile is replaced by a "don't-care" marker, so all states that agree on the pattern tiles collapse into a single abstract state. For the 15-puzzle with pattern tiles {1,2,3,4}, the number of distinct patterns is 16·15·14·13·12 ≈ 524,160 — small enough to enumerate exhaustively, whereas the full state space has 16!/2 ≈ 1013 states.

The pattern database (PDB) is built once, offline, by a backward breadth-first search from the abstract goal:

queue <- [abstract goal pattern], dist[goal] = 0
while queue not empty:
    p <- pop(queue)
    for each abstract predecessor p' of p:      # moves in the abstract space
        if p' not yet visited:
            dist[p'] = dist[p] + 1
            push(p', queue)
store dist[] in a flat array indexed by a perfect hash of the pattern

Because BFS from the goal in the abstract space labels every reachable pattern with its exact optimal abstract distance, the lookup at search time is a single array probe: compute the index of the current state's pattern, read the stored number, done. At runtime the PDB is just a very large, very accurate lookup table — the search it would have required was paid for once, in advance. Typical 15-puzzle PDBs reduce node expansions by two to three orders of magnitude compared with Manhattan distance.

Three properties matter for correctness and strength:

  • Admissibility. The abstract problem is a relaxation (goal weakened, so additional states count as goals), hence h_PDB(n) <= h*(n). PDB heuristics built this way are also consistent, because abstract distance obeys the triangle inequality over the abstract moves induced by real moves.
  • Max over several databases. Build one PDB for tiles {1,2,3,4} and another for {5,6,7,8}. Each is admissible, so h(n) = max(h_A(n), h_B(n)) is admissible and dominates both. This is free strength, at the price of one extra probe per node.
  • Disjoint (additive) databases. Max is wasteful: it throws away the information in the smaller value. You would like to add h_A + h_B, but naively that double-counts, because a single real move can advance a tile in A while shoving a tile from B out of the way, and both databases would charge for it. The fix is to count, during the backward BFS, only the moves of the tiles belonging to that pattern; moves of non-pattern tiles cost 0. Then the move budgets of disjoint patterns are genuinely disjoint, each real move is charged to at most one database, and the sum stays admissible. Korf and Felner's disjoint 7–8 partition of the 15-puzzle (one PDB over seven tiles, one over the remaining eight) yields a heuristic strong enough to solve random 15-puzzle instances optimally in milliseconds, and the same technique scaled to the 24-puzzle.

The trade-off is resource consumption. A PDB over k tiles in an m-square puzzle has about m!/(m−k−1)! entries; each extra tile multiplies both the memory and the build time by roughly the number of remaining squares. Larger patterns give larger (better) values, but the build may take hours and the table may exceed RAM, at which point random probes thrash the cache and the per-node cost explodes. Practical guidance: choose the largest pattern whose table fits comfortably in physical memory, store one byte (or even a nibble) per entry, and measure whether the extra accuracy actually reduces time and not merely node counts.

Combining multiple heuristics

Often you have several admissible heuristics and none dominates the others — Manhattan distance and Gaschnig's heuristic on the 8-puzzle, or two pattern databases over different tile sets. The safe combinator is the pointwise maximum:

h(n) = max( h1(n), h2(n), ..., hk(n) )
  • Admissible. Each hi(n) <= h*(n), so their maximum is also <= h*(n). And since h(n) >= hi(n) for every i by definition of max, h dominates every component — you get the best of all of them at every node, not merely the best on average.
  • Consistent. If every component is consistent, so is the max. Proof sketch: fix a node n and suppose the max is attained by hj. Then h(n) = hj(n) <= c(n,a,n') + hj(n') <= c(n,a,n') + h(n'), because hj(n') <= h(n'). So A* with the max retains optimality under graph search with a closed list.
  • Sums are dangerous. h1(n) + h2(n) is generally inadmissible: if two heuristics both account for the same underlying moves, their sum can exceed h*. Adding misplaced tiles to Manhattan distance on the 8-puzzle state shown earlier gives 8 + 18 = 26, which happens to equal h* there but will overshoot on other states. Addition is legitimate only when the components account for disjoint costs — the disjoint-PDB construction above, or "Manhattan distance of the red tiles + Manhattan distance of the blue tiles", where every move is charged exactly once.
  • Weighted combinations. f(n) = g(n) + w·h(n) with w > 1 (weighted A*), or a convex blend α·h1 + (1−α)·h2 scaled upward, deliberately inflates the heuristic to bias the search towards the goal. Node expansions can fall dramatically, but optimality is lost; what remains, if h is admissible, is the bounded guarantee that the returned solution costs at most w · C*. Use it when a good-enough-fast answer beats a perfect-slow one, and say so in your results.
  • Pay attention to the arithmetic cost. Computing k heuristics and taking their max costs roughly k times the per-node heuristic work. If h2 rarely exceeds h1, that extra work buys almost nothing. A useful engineering trick is lazy evaluation: compute the cheap component first, and only compute the expensive one if the cheap value is not already enough to prune the node (for instance, if g(n) + h1(n) already exceeds the current bound in IDA*, skip h2 entirely).

A further refinement specific to the sliding-tile puzzle shows how to strengthen a heuristic without violating admissibility: the linear-conflict heuristic adds 2 to Manhattan distance for each pair of tiles that are both in their goal row (or column), in reversed order, with no third tile able to pass between them without leaving the line. Those two tiles must each leave and re-enter the line, which costs two moves that Manhattan distance does not count — and those moves are not counted anywhere else, so the addition remains admissible and dominates plain Manhattan distance.

Empirical comparison methodology

Theory tells you that a dominating admissible heuristic expands no more nodes; it does not tell you how much faster your program will be, which heuristic wins at which depth, or whether your PDB has a bug. For that you need a controlled experiment, and the discipline here matters as much as the algorithms.

  • Fix the benchmark set in advance. Generate a random but fixed collection of solvable instances — for the 8-puzzle, scramble the goal by a random walk of known length, or generate random permutations and discard those with the wrong parity (only half of the 9! permutations are reachable). Stratify by solution depth (e.g. 20 instances each at depths 4, 8, 12, 16, 20, 24) so you can plot trends, and store the instances in a file with a fixed random seed so every heuristic sees exactly the same problems.
  • Record a full vector of metrics per run, not just one number: nodes generated, nodes expanded, peak frontier (open-list) size, maximum closed-list size, solution cost, number of heuristic evaluations, and wall-clock time. Peak frontier size is the memory story; nodes expanded is the informedness story; wall-clock is the story your users care about.
  • Verify optimality as a sanity check. All admissible heuristics must return the same solution cost on the same instance (the paths may differ, the costs may not). A heuristic that returns a cheaper cost means another one is broken; a heuristic that returns a more expensive cost is inadmissible — almost always a bug in a PDB index, an additive decomposition that double-counts, or a mismatch between the heuristic and the movement model.
  • Hold tie-breaking constant. Many nodes share the same f, and the order in which they are popped can change node counts by an order of magnitude. Fix a single rule for all runs — the standard choice is "lowest f, break ties in favour of larger g (i.e. smaller h), break remaining ties by insertion order (FIFO)" — so that observed differences are attributable to the heuristic and not to queue accidents. Preferring larger g drives the search towards deeper, nearly-complete paths and typically reduces the number of f = C* nodes expanded.
  • Plot nodes expanded on a logarithmic vertical axis against solution depth. Exponential processes look like straight lines on a log scale, and two heuristics with different b* values appear as lines with different slopes. On a linear axis the weaker heuristic's curve simply swamps everything and you learn nothing. Report the median as well as the mean, because node counts are heavy-tailed and a single pathological instance can dominate an average.
  • Match the heuristic to the movement model. This is the single most common correctness bug in grid pathfinding. Manhattan distance is admissible for 4-connected movement, but if diagonal moves are allowed at cost 1 (or √2 ≈ 1.414), a diagonal step reduces the true distance by one diagonal while Manhattan distance drops by 2, so Manhattan overestimates — it is inadmissible, A* silently returns suboptimal paths, and the bug is invisible unless you compare costs against a reference uniform-cost search. Use octile distance for √2 diagonals, Chebyshev for unit-cost diagonals, and Euclidean only when motion is genuinely unconstrained. Likewise, if terrain cells have varying costs with a minimum cost c_min per step, every distance heuristic must be multiplied by c_min to stay admissible.
  • Control the environment. Same machine, same language and compiler flags, same data structures (a binary-heap open list and a hash-set closed list for every variant), warm-up runs before timing, and a stated node or time limit after which an instance is recorded as "unsolved" rather than quietly dropped — dropping failures biases averages in favour of the weakest heuristic.

Once you know what admissibility and consistency mean, the practical question becomes: where do good heuristics come from, and how do you tell one apart from another? This topic answers both. A heuristic is only useful if it is both cheap to compute and close to the true remaining cost h*(n); the art lies in finding estimates that are as informed as possible while never overestimating. The standard recipe is relaxation — drop a constraint from the original problem, solve the easier version exactly, and use that exact cost as an estimate for the hard problem. Misplaced tiles and Manhattan distance both arise this way from the 8-puzzle, and the same idea generalizes to pattern databases, which precompute exact solution costs for a subproblem (say, the positions of tiles 1 through 4) and look them up during search.

Comparison matters just as much as construction. If h2(n) is greater than or equal to h1(n) at every node and both are admissible, we say h2 dominates h1, and A* using h2 never expands more nodes than A* using h1 — a strong theoretical reason to prefer more informed heuristics. When dominance does not hold, or when you want a quantitative measure, the effective branching factor b* summarizes how bushy the search tree effectively was, and careful empirical comparison over many random instances tells you what actually happens in practice. You will also see how to combine several admissible heuristics safely by taking their maximum, and when subproblem costs can be added rather than maxed.

As you watch, focus on the mechanics of relaxation: what constraint is being dropped, why the relaxed problem is easy to solve, and why its optimal cost can never exceed the original's. Try to restate each example in the formal language of admissibility you learned earlier, and keep asking whether a proposed heuristic is dominated by, or dominates, one you already know.
