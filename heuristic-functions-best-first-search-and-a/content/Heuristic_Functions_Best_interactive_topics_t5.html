Optimality and Completeness Proofs for A*

▶

Two guarantees separate A* from the merely plausible best-first searches: it is complete (it will find a solution whenever one exists) and it is optimal (the solution it returns is a cheapest one). Neither guarantee is automatic — each depends on precise conditions on the heuristic function and on the bookkeeping of the search algorithm. The key quantities are g(n), the cost of the path by which the search reached node n; h(n), the heuristic estimate of the remaining cost from n to the nearest goal; f(n) = g(n) + h(n), the estimated cost of a complete solution through n; h*(n), the true optimal cost from n to a goal; and C*, the cost of an optimal solution from the start state. A heuristic is admissible when 0 ≤ h(n) ≤ h*(n) for every node, so f(n) never overestimates the cost of the best solution through n. The proofs below show exactly how this one inequality propagates into global guarantees about what A* returns, and why a stronger property — consistency — is needed as soon as we add a closed list.

Tree-search A* is optimal with an admissible heuristic. Tree-search A* keeps no record of visited states; it simply expands the frontier node of lowest f, and it applies the goal test when a node is selected for expansion, not when it is generated. The claim is that under admissibility, the first goal node selected for expansion is an optimal one. The proof is by contradiction. Suppose A* is about to expand a goal node G2 whose path cost is g(G2) = C2 > C*, that is, a suboptimal goal. Because G2 is a goal, h(G2) = 0, so

f(G2) = g(G2) + h(G2) = g(G2) = C2 > C*

Now consider an optimal path from the start state to an optimal goal G, with total cost C*. At any moment before the search terminates, at least one node on that path has been generated but not yet expanded — call it n; it sits on the frontier. (This is true because the start node itself lies on the optimal path: before anything is expanded, the start node is an unexpanded node of the path, and whenever a path node is expanded its successor on the path is generated and joins the frontier.) Since tree search keeps the whole path, g(n) equals the true cost of reaching n along the optimal path, so g(n) + h*(n) = C*. Admissibility gives h(n) ≤ h*(n), hence

f(n) = g(n) + h(n) ≤ g(n) + h*(n) = C* < C2 = f(G2)

So f(n) < f(G2), and a best-first queue ordered on f must select n before G2. This contradicts the assumption that G2 was about to be expanded. Since the argument applies at every step, no suboptimal goal is ever expanded, and the first goal expanded has cost C*. (With ties at f = C*, A* may expand an optimal goal while other f = C* nodes remain; that is harmless, since all of them represent solutions of cost C* or worse.)

The clause about when the goal test is applied is not a technicality — it is where the proof lives. If a goal node were returned the moment it was generated, A* could return G2 while the cheaper node n was still waiting on the frontier with a smaller f. Consider this small graph, where S is the start and both G and G2 are goals:

S --2--> A --3--> G        h(S)=4, h(A)=3, h(G)=0
S --7--> G2                h(G2)=0        C* = 5

Consistency and the monotonicity of f. A heuristic is consistent (or monotone) if, for every node n, every action a, and the successor n' it produces,

h(n) ≤ c(n, a, n') + h(n')

This is a triangle inequality: the estimate at n may not exceed the cost of one real step plus the estimate from where that step lands. Consistency immediately yields monotonic f-values along any path. If n' is a successor of n, then g(n') = g(n) + c(n, a, n'), so

f(n') = g(n') + h(n')
      = g(n) + c(n, a, n') + h(n')
      ≥ g(n) + h(n)                   (by consistency)
      = f(n)

Hence f is non-decreasing along every path in the search tree, which is why consistent heuristics are also called monotone. Intuitively, the estimate of total solution cost can only become more pessimistic (or stay the same) as real cost is paid and uncertainty is removed.

Every consistent heuristic is admissible. Prove it by induction on the number of steps k in an optimal path from n to a goal. For k = 0, n is a goal, and consistency with h(goal) = 0 plus non-negativity gives h(n) = 0 = h*(n). For the inductive step, let n' be the first node on an optimal k-step path from n; then h*(n) = c(n, a, n') + h*(n'), and by consistency and the induction hypothesis h(n) ≤ c(n, a, n') + h(n') ≤ c(n, a, n') + h*(n') = h*(n). So consistency is strictly stronger than admissibility.

The converse fails. Take the graph used later for the graph-search counterexample, with h(X) = 6 and h(M) = 0 on an edge X → M of cost 1. Both values are admissible (they equal or underestimate the true distances), yet h(X) = 6 > 1 + 0 = c(X, a, M) + h(M), so h is inconsistent. In practice, inconsistent admissible heuristics are rare: they usually arise only when heuristics are combined carelessly, learned from data, or deliberately constructed. Most heuristics in common use are consistent:

  • Straight-line distance on a map: for any road from n to n' of length c, the Euclidean triangle inequality gives SLD(n, goal) ≤ c + SLD(n', goal) whenever road length is at least Euclidean length.
  • Manhattan distance on the 8-puzzle: a single move changes the Manhattan sum by exactly +1 or −1, and the step cost is 1, so h(n) ≤ 1 + h(n') always holds.
  • Misplaced tiles: one move changes the count by at most 1, again satisfying the inequality.
  • Maximum of consistent heuristics: if h1 and h2 are consistent, so is max(h1, h2).

The practical payoff of consistency is a structural fact: whenever A* selects a node for expansion, it has already found an optimal path to that node's state. Suppose not — suppose n is expanded with g(n) greater than the optimal cost g*(n). Then some node m on a cheapest path to that state is still on the frontier with g(m) = g*(m), and by consistency f(m) ≤ g*(n) + h(n) < g(n) + h(n) = f(n), so m would have been chosen first. Therefore closing a node is safe: nothing better will come along later.

Graph-search A* is optimal with a consistent heuristic. Graph search adds a closed list (explored set) and discards any newly generated node whose state is already closed, which is essential for finite-memory search of graphs with many repeated states (grids, sliding-tile puzzles, route networks). The proof of optimality now rests on monotonicity. Because f never decreases along a path, and because A* always pops the smallest f on the frontier, the sequence of f-values of expanded nodes is non-decreasing: A* expands nodes in non-decreasing order of f. Two consequences follow:

  • Every node with f(n) < C* is expanded before any node with f = C*, and a goal node G has f(G) = g(G). A suboptimal goal has f > C* and therefore cannot be the first goal expanded, since a node on the optimal path with f ≤ C* is always available. The first goal expanded has f = C*.
  • By the "optimal path on first expansion" property above, a state is closed only once an optimal path to it has been found. Discarding later duplicates therefore loses no optimal solution, and the closed list is pure savings.

Without consistency, the second bullet collapses, and graph-search A* can return a suboptimal answer. Consider start S, intermediate states X and M, and goal G, with edges S→X = 1, X→M = 1, S→M = 3, M→G = 5. True costs are h*(S) = 7, h*(X) = 6, h*(M) = 5, and C* = 7 via S→X→M→G. Take the admissible but inconsistent heuristic h(S) = 0, h(X) = 6, h(M) = 0, h(G) = 0.

Graph-search A* returns a solution of cost 8 although C* = 7. The failure is exactly the one predicted: M was closed with g(M) = 3 when the optimal value is g*(M) = 2, and the inconsistency h(X) = 6 > c(X, a, M) + h(M) = 1 pushed X behind M in the queue. Notice also that the expanded f-values 0, 3, 7, 8 are not monotone along the path S → X → M (7 then 3), which is the signature of inconsistency. There are two standard repairs when a heuristic cannot be made consistent: (i) manage the closed list specially by reopening a closed node whenever a strictly cheaper path to it is discovered (A* with node re-expansion), which restores optimality at the price of possible extra expansions; or (ii) locally repair the heuristic with the pathmax rule h(n') ← max(h(n'), h(n) − c(n, a, n')), which enforces monotonicity of f along the generated paths. The first remedy is the one normally implemented; the general lesson is that admissibility buys optimality for tree search, consistency buys optimality for graph search.

Completeness of A*. Optimality says that if A* returns something, it is a cheapest solution; completeness says it will return something whenever a solution exists. The argument is a counting argument built on the f-ordering. Since A* never expands a goal before exhausting cheaper options, it expands all nodes with f(n) < C* before expanding any goal node. So the question becomes: can that set be infinite, or can A* get stuck inside it forever? Two conditions rule this out:

  • Positive step costs bounded away from zero: every action costs at least some ε > 0. Then a node at depth d has g ≥ dε, and since h ≥ 0, f ≥ dε. Any node with f < C* therefore lies at depth less than C*/ε — a finite bound.
  • Finite branching factor b: there are at most b^d nodes at depth d, so at most O(b^{C*/ε}) nodes can have f < C*. Finitely many, however astronomically many.

A* expands a new node at each iteration and never revisits an expanded node in graph search (and, in tree search, cannot cycle indefinitely below f = C* because of the depth bound). Having exhausted the finite set {n : f(n) < C*}, it must next select a node with f = C*, and an optimal goal is always among the candidates, so a goal is reached in finite time. Both conditions are necessary. If step costs can shrink geometrically — say costs 1/2, 1/4, 1/8, … along an infinite branch — infinitely many nodes can have f < C* and A* will never escape that branch; this is the same pathology that makes uniform-cost search incomplete without a positive cost bound. If the branching factor is infinite (a continuous action space, say), a single expansion never terminates. When no solution exists, behaviour depends on the space: in a finite graph with a closed list, A* exhausts the frontier and reports failure in finite time; in an infinite space it may run forever, exactly like breadth-first or uniform-cost search, since no finite amount of expansion can prove the absence of a goal.

Contours of equal f-cost. Monotonic f gives a vivid geometric picture of A*'s behaviour. Draw, in the state space, the set of states with f(n) ≤ Ci for increasing values C1 < C2 < …. These nested regions are called contours, by analogy with contour lines on a map. Because expansion proceeds in non-decreasing order of f, A* fans out contour by contour: every node inside the contour f = Ci is expanded before any node outside it. The shape of these contours is controlled entirely by the heuristic:

  • With h = 0, A* degenerates into uniform-cost search. The contours are the sets g(n) ≤ Ci: circular bands expanding equally in all directions from the start, utterly indifferent to where the goal lies.
  • With a weak but non-trivial h, the contours are still broad but are pulled slightly toward the goal; the search is an ellipse-like blob with the start and goal roughly at the foci.
  • With an accurate h, the contours elongate dramatically along the start–goal axis and become narrow; few nodes lie between successive contours, so few nodes are expanded.
  • With a perfect heuristic, h = h*, every node on an optimal path satisfies f(n) = g(n) + h*(n) = C*, while every node off an optimal path has f > C*. The contour f = C* hugs the optimal path itself and A* walks essentially straight to the goal, expanding only optimal-path nodes (plus whatever ties the tie-breaking rule admits).

On an obstacle-free grid with unit moves, this is easy to visualise. Dijkstra's algorithm (h = 0) expands a diamond centred on the start whose radius grows until it swallows the goal; A* with Manhattan distance expands, in the ideal case, only the rectangle spanned by start and goal, because all shortest monotone paths have f = C* while any step away from the goal immediately raises f by 2. The contour picture also explains two practical facts: adding a tie-breaking rule that prefers larger g (equivalently smaller h) among equal f drives the search to the far edge of the f = C* contour and finds the goal sooner; and all the nodes strictly inside f < C* are unavoidable, so the only room for improvement lies in how much of the f = C* band gets expanded.

Optimal efficiency of A*. A* is not merely optimal in the cost of the solution it returns; with a consistent heuristic it is optimally efficient among all optimal algorithms that use the same heuristic information and expand nodes from the same start state. The argument runs as follows. Suppose some algorithm A fails to expand a node n with f(n) = g(n) + h(n) < C*, yet claims an optimal solution. The information available to A about the region below n consists only of h(n). There exists another problem instance, identical in everything A has actually examined and still consistent with the heuristic values it has seen, in which the subtree under n contains a goal at true remaining cost exactly h(n) — giving a solution of cost f(n) < C*. On that instance, A would miss the optimal solution. Hence any algorithm guaranteed to be optimal must expand every node with f(n) < C*. A* expands precisely that set, plus some subset of the f = C* band (which subset depends on tie-breaking and on where the goal happens to be found). Therefore no competing algorithm with the same heuristic can be guaranteed to expand strictly fewer nodes.

Three caveats keep this result honest. First, it is a statement about node expansions, not about running time per expansion: priority-queue operations, duplicate detection and heuristic evaluation all cost something, and an algorithm expanding slightly more nodes far more cheaply may well be faster in wall-clock terms. Second, it says nothing about memory. A* must keep the frontier and (in graph search) the closed list, so its space requirement is proportional to the number of nodes it stores, which is typically exponential. In practice A* exhausts RAM long before it exhausts patience: on a machine generating a million nodes per second, gigabytes vanish in minutes. Memory, not time, is A*'s binding constraint. Third, the guarantee is "no algorithm is guaranteed to do better", not "no algorithm ever does better": a lucky heuristic-blind algorithm may stumble onto the goal early on a particular instance.

Heuristic error and the number of nodes expanded. How much work A* does is governed by how close h is to h*. Two ways of measuring the gap give very different answers:

  • Relative error, ε = (h* − h)/h*. If the relative error is a positive constant — the heuristic is, say, always within 90% of the truth — the number of nodes expanded still grows exponentially in the solution depth d, roughly as O(b^{εd}) in a tree-shaped space with unit costs. A constant fraction of error accumulated over d levels is an absolute error proportional to d, and each unit of absolute error multiplies the contour's width.
  • Absolute error, |h*(n) − h(n)|. Sub-exponential node growth requires the absolute error to grow no faster than the logarithm of the true path cost: |h*(n) − h(n)| = O(log h*(n)). Virtually no heuristic for a real combinatorial problem satisfies this. The honest conclusion is that A* with a realistic heuristic still faces exponential growth; a good heuristic shrinks the base of the exponent, which is enormously valuable but is not a change of complexity class.

Comparing two heuristics is therefore a matter of how far each pushes the exponent down, and here dominance gives a clean theorem. If h1 and h2 are both admissible and h2(n) ≥ h1(n) for every node n, we say h2 dominates h1, and A* using h2 never expands more nodes than A* using h1 (up to tie-breaking at f = C*). The proof is one line of contour reasoning: every node A* expands has f < C* or f = C*; if g(n) + h2(n) < C* then g(n) + h1(n) ≤ g(n) + h2(n) < C*, so every node necessarily expanded under h2 is also necessarily expanded under h1, but not conversely. The moral is to use the largest admissible estimate available — for instance max(h1, h2) of two admissible heuristics, which dominates both and remains admissible (and consistent if both are consistent). On the 8-puzzle, Manhattan distance h2 dominates misplaced tiles h1, since each misplaced tile needs at least one move and usually more.

The standard practical yardstick is the effective branching factor b*: if A* expands N nodes and the solution found is at depth d, then b* is the branching factor a uniform tree of depth d would need in order to contain N + 1 nodes:

N + 1 = 1 + b* + (b*)² + … + (b*)^d

b* is remarkably stable across problem instances for a given heuristic, which makes it a reliable basis for comparison; a well-designed heuristic drives b* close to 1, meaning the search barely branches at all. Extrapolate to the 15-puzzle or 24-puzzle and the stored node counts pass any plausible memory budget, which is why even excellent heuristics leave A* memory-bound. That bottleneck, and not the node-expansion count protected by the optimal-efficiency theorem, is what motivates the memory-conscious variants: IDA* (iterative-deepening A*, which performs depth-first searches bounded by successive f-contours and uses space linear in depth, at the cost of re-expanding earlier contours), RBFS (recursive best-first search, also linear-space, remembering the best alternative f-value at each recursion level), and SMA* (simplified memory-bounded A*, which fills the available memory and then drops the worst leaf, backing its f-value up to its parent so the information is not lost). All of them retain the optimality guarantees proved above when the heuristic is admissible — and, for the graph-search versions, consistent — trading repeated work for the memory A* cannot spare.
