Introduction

Almost every classical AI problem — route planning, puzzle solving, scheduling moves in a game — can be cast in the same shape: you have a current situation, a set of legal moves, a way to tell when you are done, and a cost for getting there. Formulating a search problem means writing that down precisely as five parts: the initial state, the available actions, the transition model that says what each action does, the goal test, and the path cost function. Once a problem is in that form, the same generic algorithm can solve it regardless of whether the states are cities, board configurations, or robot positions.

The generic framework keeps a frontier of nodes waiting to be expanded and (in graph search) an explored set of states already visited, which prevents infinite loops and repeated work. Different search strategies differ only in one decision: which node to pull off the frontier next. A strategy is called uninformed (or blind) when that decision uses nothing beyond the problem definition itself — no estimate of how far a state is from the goal. We judge these strategies on four criteria: completeness (will it find a solution if one exists), optimality (will it find the cheapest one), time complexity, and space complexity.

As you watch the videos below, keep two things in mind. First, watch the data structure driving the frontier — a queue versus a stack changes nothing else about the algorithm but changes its behavior, guarantees, and memory use completely. Second, try to map what you see back onto the five-part formulation: what is the state, what counts as an action, and where does the explored set appear in the code or trace?

Video 1: Breadth-first search in 4 minutes

Michael Sambol · 3:59 · 608,315 views · 4y ago · captions — Watch on YouTube

About this video

A compact walkthrough of breadth-first search: how the algorithm uses a FIFO queue as its frontier, marks nodes as visited, and expands a graph level by level outward from the start node. The video traces the order in which nodes are discovered and links to a Python implementation on GitHub so you can read the code alongside the explanation.

Why this video

Michael Sambol's algorithm shorts are widely used and known for being accurate and tightly edited, and this one shows exactly the frontier-plus-visited-set structure that the generic graph search framework describes — with BFS as the concrete instance where the frontier is a queue.

Video 2: Depth-first search in 4 minutes

Michael Sambol · 4:01 · 554,087 views · 4y ago · captions — Watch on YouTube

About this video

The companion video for depth-first search, showing how DFS dives as deep as possible along one branch before backtracking, using a stack (or recursion) in place of BFS's queue. It traces the visit order on an example graph and points to accompanying Python code.

Why this video

Watching this immediately after the BFS video makes the key insight of uninformed search vivid: the algorithms are identical except for the frontier discipline, which is precisely what drives their differing completeness, optimality, and memory profiles.

About this video

An introduction to the classic N-Queens puzzle, scaled down to a 4x4 board, used as a worked example of how a puzzle gets turned into a problem a computer can search. Based on its description, it frames the puzzle in terms of states (partial board placements), constraints, and the systematic exploration — including backtracking — needed to find a valid configuration.

Why this video

It gives you a concrete problem to practice the formulation step on, illustrating how a real puzzle becomes states, actions, and a goal test; note that it approaches the puzzle from the constraint-satisfaction angle, so treat it as a formulation example rather than a description of BFS or uniform-cost search.

How These Videos Support the Learning Outcomes

The 4-Queens video gives you practice at the formulation step behind MO1 — recognizing what counts as a state, what an action does, and when a configuration passes the goal test. The BFS and DFS videos directly support MO2 and MO3 by tracing expansion order on a state-space graph and showing the queue-based and stack-based frontiers, together with the visited/explored set, in working code. Comparing the two traces side by side also sets up MO4 and MO5: you will see why BFS finds the shallowest solution but stores an entire level of the frontier, and why DFS is memory-cheap but can wander deep down an unpromising branch — the trade-off at the heart of choosing an uninformed strategy. Uniform-cost search is not covered by these videos and will come from the course readings and lecture material.
