Introduction

Depth-first search (DFS) explores a state space by always expanding the deepest unexpanded node first. In practice this means the frontier behaves as a stack (last-in, first-out): the most recently generated successors are the next ones tried. DFS can also be written recursively, where the call stack itself holds the path being explored and returning from a call is exactly the act of backtracking to the most recent branch point.

This topic matters because DFS is the counterweight to BFS. Where BFS guarantees shallowest-first solutions at the cost of storing an exponential frontier, DFS needs only space proportional to the depth of the current path, which makes it usable on problems BFS cannot fit in memory. The price is that DFS is not optimal and, on infinite or cyclic state spaces, not even complete — it can run forever down one branch. Depth-limited search fixes the infinite-branch problem by cutting off at a chosen depth, and iterative deepening search repeats depth-limited search with growing limits to recover BFS-like completeness and shallowest-solution guarantees while keeping DFS-like memory use.

As you watch, keep three questions in mind. First, can you state the exact expansion order and the stack contents at each step for the example graphs used in lecture? Second, can you name the b, m, and d quantities in the complexity expressions and explain why DFS space is O(bm) while BFS is O(b^d)? Third, can you say precisely which property (completeness, optimality, time, space) each variant gains or loses relative to plain DFS? Note that the first two videos are presented from a data-structures/graph-traversal angle, so you will need to map their notion of "visited set" onto this course's explored set and goal test.
