Introduction

Breadth-first search (BFS) is the first systematic search strategy we study in detail. The idea is simple: keep a frontier of nodes waiting to be expanded, and always expand the shallowest one first. A FIFO queue gives you exactly that behavior, so BFS sweeps the state space level by level — all nodes at depth 0, then depth 1, then depth 2, and so on. Paired with an explored set (sometimes called a closed list) and parent pointers, BFS turns into a practical solver that can reconstruct the path it found.

This topic matters because BFS sets the baseline for everything that follows. It is complete whenever the branching factor is finite, and it is optimal when every edge has the same cost — but it pays for those guarantees with O(b^d) time and, more painfully, O(b^d) memory, since the whole frontier must be stored. Those properties are what we later compare against DFS, depth-limited search, iterative deepening, and uniform-cost search. We also look at two details that are easy to get wrong: testing the goal when a node is generated rather than when it is expanded (which saves a whole level of work), and detecting duplicate states so repeated states do not blow up the search.

While watching the videos below, focus on three things. First, watch the queue: what is added, what comes off the front, and in what order nodes are visited. Second, notice how each presenter marks nodes as visited or discovered — that is the duplicate detection mechanism, and the exact moment it happens changes how much work BFS does. Third, keep the 8-puzzle in mind: the graph examples are small, but the same loop runs over puzzle states, where the branching factor and depth decide whether BFS is feasible at all. Note that these videos present BFS from an algorithms and data-structures perspective; the AI-specific framing (five-part problem specification, goal-test timing, and the completeness/optimality analysis) comes from the course material and lectures.
