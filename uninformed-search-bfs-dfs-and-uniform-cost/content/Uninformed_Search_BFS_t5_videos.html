Introduction

Search algorithms are often described on paper as abstract procedures, but turning BFS, DFS, and uniform-cost search into working code forces you to make concrete decisions about data structures. The central idea is that the frontier is not just a bag of states: it is a specific container whose behavior defines the strategy. A FIFO queue gives you breadth-first search, a LIFO stack gives you depth-first search, and a priority queue ordered by path cost gives you uniform-cost search. Swap the container and you swap the algorithm.

Just as important is the search node, which wraps a state together with a pointer to its parent, the action that produced it, and the accumulated path cost. Those extra fields are what let you reconstruct the solution path by walking parent pointers backward from the goal. Alongside the frontier you also need an explored set and a membership test for the frontier itself, usually backed by a hash set keyed on a canonical representation of the state, so that repeated states do not cause redundant expansion or infinite loops. Uniform-cost search adds one more wrinkle: when a cheaper path to an already-queued state is discovered, you must either decrease its key or push a duplicate entry and discard stale ones when they are popped.

The videos below cover the building blocks you will use in the 8-puzzle and weighted-route-finding coding exercises. While watching, pay attention to three things: which container is used for the frontier, where and how visited states are recorded, and what information is stored per node. If a video shows only traversal (visiting every node) rather than returning a path, ask yourself what you would add to recover the solution.
