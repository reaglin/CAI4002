Introduction

So far you have seen breadth-first, depth-first, and uniform-cost search as individual procedures. This topic steps back and asks the engineering question: given a particular problem, which one should you actually run? The standard way to answer that is to evaluate each strategy on four criteria — completeness (does it find a solution if one exists?), optimality (is the solution it finds the cheapest?), time complexity (how many nodes does it expand?), and space complexity (how many nodes must it hold in memory at once?). Expressed in terms of branching factor b, solution depth d, maximum depth m, and in the uniform-cost case the cheapest edge cost and optimal path cost, these criteria produce the familiar side-by-side comparison table.

The headline result from that table is that memory, not time, is usually the binding constraint. BFS and uniform-cost search store an exponentially growing frontier, so they exhaust RAM long before they exhaust patience; DFS needs only linear space but gives up both completeness on infinite or cyclic spaces and optimality in general. Empirical node counts on benchmark problems make this concrete: a modest increase in depth multiplies BFS memory by a factor of b. Choosing a strategy therefore means matching problem structure to these trade-offs — uniform edge costs or varying ones, shallow or deep solutions, finite or unbounded depth, and how much memory you actually have.

While watching, keep a comparison table in front of you and fill in cells as each video supplies them. Listen specifically for the assumptions behind each claim: BFS is optimal only when all edge costs are equal, DFS is complete only on finite state spaces with cycle checking, and uniform-cost search's complexity is driven by path cost rather than depth. Also notice what none of these methods do — they expand nodes without any estimate of how close a state is to the goal, which is the shared limitation that motivates informed search later in the course.
